# 重点主题圈三榜单算法

## 1. 输出与参数

| 榜单 | 数据范围 | 排名指标 | 数量 |
|---|---|---|---:|
| 圈内累计曝光榜 | 单个主题圈最近24小时候选帖 | 当前累计浏览量 | Top 10/圈 |
| 全部主题总榜 | 五个圈内Top 10的并集 | 当前累计浏览量 | Top 20 |
| 单位时间增量榜 | 具有相邻成功快照的24小时候选帖 | 单位时间新增浏览量 | Top 20 |

固定参数：扫描周期2小时；有效窗口为发布后滚动24小时；新帖读取从上次成功时间前10分钟开始。扫描任务保存真实执行时间，不假定相邻快照严格间隔2小时。

圈内榜和总榜回答“当前累计曝光最高的是谁”；增量榜回答“最近获得新曝光最快的是谁”。

## 2. 数据要求

### 帖子

- `post_id`
- `account_id`
- `account_handle`
- `circle_id`
- `post_type`
- `published_at`
- `original_url`
- `first_observed_at`

### 浏览量快照

- `snapshot_id`
- `post_id`
- `snapshot_at`
- `view_count`
- `collection_status`
- `data_anomaly`

所有候选帖在发布后24小时内保存每次成功扫描的完整快照。帖子出窗后停止新增快照，既有快照继续保留。

## 3. 每2小时执行流程

### 步骤1：确定窗口

设本轮真实执行时间为 `run_at`：

- 排行窗口：`run_at - 24小时` 至 `run_at`；
- 新帖读取窗口：`last_success_at - 10分钟` 至 `run_at`；
- 首次运行没有 `last_success_at` 时，读取完整排行窗口。

完成条件：本轮具有明确的排行窗口和新帖读取窗口。

### 步骤2：读取新帖并去重

读取所有启用账号在新帖窗口内发布的内容，以 `post_id` 去重。重复读取只更新已有帖子，不创建新记录。

完成条件：一个Post ID最多对应一条帖子记录。

### 步骤3：筛选候选帖

候选帖必须同时满足：

1. 来自启用账号；
2. 发布时间位于本轮24小时窗口；
3. 能读取当前浏览量；
4. 原始链接有效；
5. 不是纯转发；
6. 不是正文与目标完全相同的重复内容。

包含新增表达的引用帖可以进入。系统不判断帖子是否与账号所属主题圈相关；帖子直接继承账号配置的 `circle_id`。

完成条件：每条候选帖均可验证上述六项条件。

### 步骤4：更新候选快照

读取所有仍在24小时窗口内的候选帖当前浏览量并保存成功快照，不区分当前是否上榜。

采集失败时：不生成成功快照；不计算增量；该帖本轮沿用上一张成功快照；失败不能触发出榜。

浏览量回退时：标记 `data_anomaly=true`；本周期增量按0处理；累计浏览量沿用上一成功值；不产生负增长。

完成条件：每条候选具有本轮成功快照或明确失败状态。

### 步骤5：生成圈内累计曝光榜

对每个主题圈：

1. 取本轮24小时候选帖；
2. 按本轮有效累计浏览量降序排列；
3. 浏览量相同时，发布时间较晚者优先；
4. 仍相同时，按 `post_id` 稳定排序；
5. 取前10。

第一次抓到的新帖子有当前浏览量，可立即参与。排名 `<=10` 进榜；排名 `>10` 或发布超过24小时出榜。候选不足10条时展示实际条数。

完成条件：每个圈最多10条且可由快照复算。

### 步骤6：生成全部主题总榜

1. 合并五个圈内Top 10，最多50条；
2. 对相同 `post_id` 去重；
3. 按累计浏览量降序排列；
4. 同值时沿用圈内榜排序规则；
5. 取前20。

总榜不重新抓取账号或帖子。总排名 `<=20` 进榜；总排名 `>20`、不再属于任何圈内Top 10或发布超过24小时出榜。

完成条件：总榜最多20条且每条均来自某个圈内Top 10。

### 步骤7：计算单位时间新增浏览量

候选帖至少有两张成功快照时计算：

```text
新增浏览量 = 当前有效浏览量 - 上一成功快照浏览量
间隔小时数 = 当前快照时间 - 上一成功快照时间
单位时间新增浏览量 = max(新增浏览量, 0) / 间隔小时数
```

间隔必须大于0，使用真实快照间隔。第一张快照没有增量；异常或失败区间不产生有效增量。

完成条件：每个有效增量均可追溯到两张成功快照。

### 步骤8：生成单位时间增量榜

1. 汇总所有圈内仍在24小时窗口的候选帖；
2. 只保留具有有效正增长的帖子；
3. 按单位时间新增浏览量降序排列；
4. 同值时，累计浏览量较高者优先；
5. 仍相同时，发布时间较晚者优先；
6. 取前20。

排名 `<=20` 进榜；排名 `>20`、增长为0、无法形成有效增量或发布超过24小时出榜。首次快照不进入增量榜。

完成条件：增量榜最多20条且不含首次快照、零增长和负增长记录。

### 步骤9：保存榜单历史

每次榜单计算保存：

- `leaderboard_type`
- `circle_id`
- `rule_version`
- `calculated_at`
- `post_id`
- `rank`
- `rank_value`
- `previous_rank`
- `first_entered_at`
- `highest_rank`
- `exited_at`

首次进入标记“新上榜”；排名变化展示上升或下降位次；出榜后在24小时内再次命中时复用原记录并标记“重新上榜”。

完成条件：任何条目都能说明进榜依据、当前排名和出榜时间。

## 4. 跨榜与多来源规则

- 同一帖子可以同时进入圈内榜、总榜和增量榜，底层帖子及快照唯一。
- 退出一个榜单不影响它在其他榜单的状态。
- 发布超过24小时后退出全部榜单并停止扫描。
- 榜单状态不控制快照范围：全部24小时候选均保存成功快照。
- 多条帖子高置信度匹配同一Event时，页面以该榜排名最高的帖子作为代表，其他帖子作为相关来源。
- 多帖浏览量不相加；无法确认同一Event时保持独立条目。

## 5. Hot Event准入

Hot Event采用两层门槛。上榜只证明传播表现，不能跳过第一层。

### 第一层：Event成立

内容必须同时满足：

1. 内容可独立描述一次具体变化；
2. 能提取主体、动作、对象，以及适用的时间或事件状态；
3. 至少存在一个可追溯原始来源；
4. 事实状态由Evidence单独判断。

以下内容即使进入榜单，也不能自动进入Hot Event：

- 单纯观点或情绪表达；
- 没有具体动作的预测；
- 长期议题讨论；
- 广告或推广；
- 无法说明具体发生了什么的内容。

完成条件：系统能够输出Event核心结构和至少一个原始来源；否则结果为“仅榜单展示”。

### 第二层：命中准入路径

第一层成立后，命中以下任一路径即可准入：

- 圈内累计曝光榜Top 3；
- 全部主题总榜Top 10；
- 单位时间增量榜Top 10；
- 24小时内至少两个不同监控账号描述同一Event，且至少一条来源进入任一榜单；
- 事件主体官方账号或直接相关核心人物发布正式动作、新结果、取消、更正、否认或反转；
- 用户人工提升并记录原因。

每次准入必须保存：

- 命中的准入路径；
- 对应榜单名称、排名和计算时间，或官方/人工依据；
- 代表帖及相关来源；
- Event结构提取结果；
- 规则版本。

完成条件：至少一条准入路径具有可追溯依据；否则不创建或更新Hot Event。

### 第三步：创建或更新

- 描述已有Event的同一次现实变化：更新已有Event，追加Signal；能支持事实时追加Evidence。
- 描述新动作、新结果、取消、更正、否认或反转：创建新的Event。
- 只是新的观点、重复传播或没有新增事实：保留为Signal，不新建Event。

完成条件：同一次现实变化只有一个Event，新现实变化形成新Event，所有处理结果均保留原始来源。

## 6. 验收用例

1. 新帖首次采集有12万浏览，可立即参与圈内榜和总榜，但不进入增量榜。
2. 相邻成功快照为10万和16万、间隔2小时，单位时间新增为3万/小时。
3. 两次快照实际间隔3小时，增量除以3而不是2。
4. 当前浏览量小于上一成功值时，累计值沿用上一成功值，增量为0并标记异常。
5. 采集失败时不生成增量，也不因失败将帖子移出榜单。
6. 每圈第11名不能进入圈内榜，也不能作为总榜候选。
7. 总榜每条记录必须来自某个圈内Top 10。
8. 首次快照、零增长和负增长均不能进入增量榜。
9. 帖子超过24小时后退出全部榜单并停止新增快照，历史仍可读取。
10. 粉丝量变化不会改变任一榜单排序。
11. 高曝光观点可以上榜，但不具备Event结构时不能进入Hot Event。
12. 同一帖子跨榜出现时只存在一套帖子与快照数据。
