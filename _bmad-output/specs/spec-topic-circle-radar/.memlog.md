topic: 主题圈雷达规则
updated: 2026-08-31T11:52

- (decision) 主题圈触发后调用配置的三条基础生产线，而不是硬编码三个具体账号；每条生产线可绑定一个或多个账号。
- (decision) 每个被触发的账号分别建立任务并固定生成3条账号专属候选；同 Event 同账号任务不得因多触发路径重复创建。
- (capability) CAP-1：维护五个主题圈及可启停的平权账号清单。
- (capability) CAP-2：每3小时幂等采集有效内容并从失败后的上次成功点恢复。
- (capability) CAP-3：按主体、动作、对象、时间、地点和状态识别同一具体Event。
- (capability) CAP-4：以B3h、B24h和Tmax计算圈内讨论广度与流量强度。
- (capability) CAP-5：四条关注度规则任一命中即可独立于热搜触发统一Event链路。
- (capability) CAP-6：同一Event多路径触发复用任务并向每个绑定账号交付3条候选。
- (capability) CAP-7：通过历史回放或影子监测校准阈值、账号组合和误报率。
- (event) Coherence validation passed for v1.1: 主题圈触发复用三条生产线与Event×Account×Skill Version任务边界，不再硬编码三个具体账号。
- (event) Preservation validation passed for v1.1: 原有采集、聚类、B3h/B24h/Tmax和四触发规则保留，新增多账号三候选映射。
- (decision) AI与科技主题圈第一批监控池由原10个调整为19个：@OpenAI、@OpenAIDevs、@AnthropicAI、@claudeai、@GoogleDeepMind、@GoogleAI、@AIatMeta、@spacexai、@deepseek_ai、@Alibaba_Qwen、@cursor_ai、@nvidia、@sama、@thsottiaux、@DarioAmodei、@demishassabis、@ylecun、@elonmusk、@TechCrunch。
- (decision) 相对旧版AI与科技10账号，保留@OpenAI、@AnthropicAI、@GoogleDeepMind、@AIatMeta、@TechCrunch；删除@huggingface、@AndrewYNg、@karpathy、@verge、@WIRED；新增其余14个账号。
- (decision) 最终不监控@JensenHuang和@ChatGPTapp，原因分别为更新频率过低及用户明确取消。
- (question) Signal形成热点Event的判断维度需要在下一轮重定义；现有B3h、B24h、Tmax、持续性、事件聚类和事实状态分离作为已有讨论基础，但账号平权、3小时采集及阈值是否继续适用尚未确认。
- (event) Coherence validation passed for v1.2 account-pool update: AI与科技圈为19个、全局59个的数量与清单一致，Signal判断维度仍明确标为待讨论而未被擅自定稿。
- (event) Preservation validation passed for v1.2 account-pool update: 用户确认的19账号、相对旧版保留/删除/新增关系及不监控@JensenHuang与@ChatGPTapp均已进入memlog，最终启用清单已渲染至SPEC。
- (direction) 用户要求将重点主题圈追踪算法简化并定稿为三榜单：圈内累计曝光榜、全部主题总榜、单位时间增量榜。
- (decision) CAP-2采集周期由每3小时改为每2小时；每轮扫描全部启用账号在滚动24小时内发布的帖子，并保存每次浏览量快照。
- (decision) 候选帖仅按客观条件准入：启用账号、发布未超过24小时、可读取浏览量、有效原始链接、非纯转发、非完全重复；不再由Agent判断内容与圈层主题是否相关。
- (decision) CAP-4原B3h、B24h、Tmax及四条组合触发规则退役，由三榜单规则取代。
- (capability) CAP-4：每个主题圈按当前累计浏览量生成Top 10圈内榜。
- (capability) CAP-5：只汇总五个圈内Top 10，并按当前累计浏览量生成Top 20总榜，不另行抓取账号。
- (capability) CAP-6：对拥有至少两张成功快照的24小时候选帖计算单位时间新增浏览量，并生成Top 20增量榜。
- (decision) 单位时间新增浏览量等于当前浏览量减上一成功快照浏览量后除以真实间隔小时数；首次快照可进入圈内榜和总榜，但不进入增量榜。
- (decision) 所有24小时候选帖均保存每次成功扫描的完整浏览量快照；发布超过24小时后停止扫描，历史快照继续保留。
- (constraint) 粉丝量、点赞、回复、转发、账号权重和综合分数均不参与三个榜单排序。
- (constraint) 浏览量回退时本周期增量记为0并标记数据异常；采集失败不生成快照、不触发出榜并保留上一轮状态。
- (decision) 圈内榜按圈内Top 10独立进出；总榜按圈内Top 10并集中的Top 20独立进出；增量榜按正增长候选中的Top 20独立进出。
- (decision) 同一帖子可同时进入多个榜单但底层记录唯一；同一Event的多帖子在榜单层以最高排名代表帖展示，其他帖子作为相关来源。
- (decision) Hot Event准入要求先满足明确Event结构与可追溯来源，再命中圈内Top 3、总榜Top 10、增量榜Top 10、至少两账号讨论同一Event、官方重大信息或人工提升任一路径。
- (constraint) 榜单热度只表示公开传播表现，不确认事实；Hot Event事实仍由Evidence与表达边界治理。
- (event) 旧版3小时采集、B3h、B24h、Tmax和直接启动内容生产线的口径已由本轮三榜单算法取代。
- (decision) 为保持能力ID稳定，CAP-3继续表示同一Event识别，CAP-4表示关注度计算并升级为三榜单，CAP-5表示独立Hot Event触发，CAP-6表示统一下游衔接，CAP-7表示校准验证；新增CAP-8客观候选准入。
- (event) Coherence validation passed for v2.0: 八项能力均具备intent与可测试success，旧算法被明确退役，三榜单、异常、出榜和Hot Event边界一致。
- (event) Preservation validation passed for v2.0: 本轮确认的2小时扫描、24小时窗口、完整快照、圈内Top 10、总榜Top 20、增量Top 20、客观准入和排序排除项均已进入SPEC或companions。
- (direction) 用户确认Hot Event准入采用两层门槛：先满足Event结构与可追溯来源，再命中六条热度或重要性路径中的任意一条。
- (decision) 不具备Event结构的高曝光观点、情绪、长期议题、无具体动作预测、广告推广和无法说明具体变化的内容只保留在榜单，不进入Hot Event。
- (decision) Hot Event六条准入路径固定为圈内榜Top 3、总榜Top 10、增量榜Top 10、多账号同Event、官方重大信息和人工提升。
- (decision) 准入后同一次现实变化更新已有Event并追加Signal或Evidence；新动作、新结果、取消、更正、否认或反转创建新Event。
- (event) Coherence validation passed for Hot Event update: CAP-5与算法均采用两层门槛，六条路径、排除项、依据字段和创建/更新结果无冲突。
- (event) Preservation validation passed for Hot Event update: 用户确认的Event结构、六条准入路径、高曝光非Event排除以及更新/新建分流均已保留。
