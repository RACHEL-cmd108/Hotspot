# 运营决策中心 MVP 规则

状态：第一期业务基线
更新：2026-08-31

## 1. 这个子系统做什么

运营决策中心接收一份完整的事件上下文，判断它是否值得成为 PredX 的选题推荐、应何时处理，以及有哪些可承接角度。

它只输出“选题推荐与候选角度”，不生成内容、不发布内容，也不把事件自动交给下游内容生产。

## 2. 输入

- 一份事件上下文：可来自热点情报中心、人工提交或其他外部来源；
- PredX 的产品介绍与承接边界；
- PredX 实时市场数据。

人工输入不必完全结构化。信息不足时，系统可以继续检查市场和产品价值；只有缺失信息会改变判断时，才提示补充。

## 3. 什么进入选题推荐

以下三条路径任意一条成立，即进入选题推荐：

| 路径 | 成立条件 | 推荐标签 |
|---|---|---|
| 公共热度 | 事件代表帖进入 X 短时增速排行榜前 3。 | 公共热度 |
| 实时市场承接 | 事件与一个仍开放、语义和结算条件相关的 PredX 市场匹配。 | 实时市场 |
| 产品价值承接 | 事件与 PredX 的产品定位、价值主张、用户问题、使用场景或产品能力存在自然关联，并能说明面向谁、提供什么具体价值。 | 产品价值 |

三条路径可以同时成立。只有公共热度、但尚无市场或产品连接时，也可以推荐，但标记为“待人工探索”，不硬造产品角度。

## 4. 什么时候处理

已进入选题推荐的事件只分为两种处理节奏：

| 节奏 | 条件 | 运营要求 |
|---|---|---|
| 立即响应 | 满足以下任意一项：X 短时增速榜前 3；未来 12 小时内有直接相关的发布、投票、结算、截止或正式决定；过去 2 小时内有官方确认、正式结果或关键决定，且直接关联开放市场或 PredX 产品。 | 建议 2 小时内完成人工判断。 |
| 今日处理 | 已进入推荐、但不满足立即响应条件。 | 当天完成人工判断。 |

系统不设置“持续观察”。若出现新信息，将更新后的事件上下文重新提交判断。

## 5. 系统必须给出的结果

每张选题推荐卡至少包含：

- 事件摘要；
- 为什么进入推荐：命中的路径与证据；
- 处理节奏：立即响应或今日处理，以及依据；
- 匹配的实时市场，或明确的产品价值连接；
- 若干候选承接角度；
- 证据与来源链接；
- 风险和不确定性说明。

候选承接角度是“可以从什么问题或价值切入”，不是最终标题、文案或内容大纲。

## 6. 人工如何处理候选角度

| 动作 | 含义 |
|---|---|
| 直接采用 | 原样采用一个 Agent 候选角度。 |
| 修改后采用 | 以一个 Agent 候选为起点，人工修改后保存最终角度。说明 Agent 给出了可用起点。 |
| 人工新建角度 | 认可该选题，但最终方向不基于任何 Agent 候选。说明选题被采用，但 Agent 角度未被采用。 |
| 重新推荐 | 要求系统避开已否定的方向，探索新的候选角度；这是中间动作。 |
| 不采用 | 本次不做该选题，或没有可用角度。 |

每次处理记录原因和最终结果，用于计算选题采用率、Agent 角度采用率与重新推荐后的改善情况。

## 7. 权限边界

- **Agent**：读取上下文、匹配市场和产品价值、给出推荐理由与候选角度、根据反馈重新推荐。
- **程序**：提供实时市场、排行榜和时间数据，保存状态、证据、反馈和审计记录。
- **运营人员**：最终决定是否采用、修改或新建角度，并对高风险或低置信度判断复核。

运营人员的判断永远优先；系统不自动将热点对象送入内容生产。
