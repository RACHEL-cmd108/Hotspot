# 运营决策中心 MVP 规则

状态：第一期业务基线
更新：2026-08-31

## 1. 这个子系统做什么

运营决策中心接收一份完整的事件上下文，判断它是否值得成为 PredX 的选题推荐、应何时处理，以及有哪些可承接角度。

它只输出“选题推荐与候选角度”，不生成内容、不发布内容，也不把事件自动交给下游内容生产。

## 2. 输入

- 一份事件上下文：可来自热点情报中心、人工提交或其他外部来源；
- [PredX 热点—产品承接基础配置](../predx-event-product-association-reference.md)；
- PredX 实时市场数据。

人工输入不必完全结构化。信息不足时，系统可以继续检查市场和产品价值；只有缺失信息会改变判断时，才提示补充。

## 3. 统一研判结果与输出

运营人员或外部来源只提交一份事件上下文，不选择“本次目的”。Agent 对同一事件同时判断：是否应进入选题推荐，以及是否存在自然的 PredX 承接角度。

| 结果 | 成立条件 | 系统交付与去向 |
|---|---|---|
| `recommended`（已进入选题推荐） | 满足公共热度、实时市场承接或 PredX 承接中的任一准入路径。 | 创建选题推荐卡；卡内包含候选承接角度。 |
| `angle_ready`（不进入推荐 · 已生成承接角度） | 不满足选题推荐准入，但存在可探索的自然 PredX 连接；尚不足以形成当前的产品价值承接。 | 留在上下文收件箱；可查看角度、重新推荐，或由运营人员手动加入选题推荐。 |
| `needs_info`（需要补充） | 无法可靠识别事件，或缺失信息会实质改变推荐或承接结论。 | 留在收件箱；明确说明缺什么、为什么影响判断，并提供补充后重新研判入口。 |
| `no_angle`（暂不推荐 · 暂无自然承接） | 事件已被理解，且不满足推荐准入，也不存在自然 PredX 承接。 | 留档结束；说明不推荐理由和表达边界，不生成牵强角度。 |

`recommended` 不等于自动进入内容生产。所有结果均停留在运营决策中心，最终由运营人员决定是否采用。

### 3.1 什么时候需要补充

只有下列缺口才返回 `needs_info`：

- 无法识别事件主体或发生了什么；
- 只有链接、没有可读取的事件内容；
- 无法区分事实、传闻或观点，而该区别会改变判断；
- 缺少时间、来源或关键背景，且该缺口会改变热点时效、市场匹配或承接判断。

其他信息不完整时，Agent 标记为“未知”并继续研判；不因缺少非关键细节而要求用户补表单。

### 3.2 输入与内部标准化

人工输入不设强制格式。用户可粘贴事件描述、原文、链接、已有判断、社交讨论或外部 API 内容。

Agent 必须先形成以下内部事件上下文；未知字段填写 `unknown`，不得补写为事实：事件摘要、主体／对象、事件时间与进展、来源与可追溯证据、热度线索、PredX 实时市场候选与连接证据，以及 PredX 连接层级（L1、L2、L3、L4 或 `none`）。

### 3.3 Agent 固定输出字段

```text
result                 四种研判结果之一
event_summary          标准化事件摘要
entry_reasons[]        命中的推荐准入路径及证据；未命中则为空
recommendation_reason  推荐、不推荐或需要补充的原因
handling               immediate / today / none
market_matches[]       匹配市场、链接、匹配依据；没有则为空
association_level      L1 / L2 / L3 / L4 / none
association_reason     PredX 承接或不承接的依据
angles[]               候选承接角度；仅在有自然承接时给出
evidence[]             来源、链接与关键事实
risk_and_unknowns[]   风险、表达边界与未知项
material_gaps[]        需要补充的内容及其影响；仅 result=needs_info 时给出
```

- `recommended` 必须含 `entry_reasons`、`handling`、`evidence` 和候选 `angles`；
- `angle_ready` 的 `handling` 为 `none`，但必须含 `association_level`、`association_reason` 和 `angles`；
- `needs_info` 必须含至少一项 `material_gaps`，每项写明“缺什么／为什么影响判断”；
- `no_angle` 的 `association_level` 必须为 `none`，`angles` 必须为空，并说明不生成角度的理由。

### 3.4 Agent 执行顺序

1. 读取输入并形成标准化事件上下文。
2. 判断是否存在关键缺口；只有满足 3.1 才返回 `needs_info`。
3. 检查公共热度、实时市场和 PredX L1–L4 承接。
4. 有自然承接时生成彼此实质不同的候选角度，并附证据与风险边界。
5. 根据推荐准入输出 `recommended`、`angle_ready` 或 `no_angle`。
6. 记录本次输入、证据、规则版本和结果，供运营人员查看与反馈。

## 4. 什么进入选题推荐

以下三条路径任意一条成立，即进入选题推荐：

| 路径 | 成立条件 | 推荐标签 |
|---|---|---|
| 公共热度 | 事件代表帖进入 X 短时增速排行榜前 3。 | 公共热度 |
| 实时市场承接 | 事件与一个仍开放、语义和结算条件相关的 PredX 市场匹配。 | 实时市场 |
| PredX 承接 | 命中产品配置的 L1 直接、L2 类似、L3 主题或 L4 概念连接之一，且能说明面向谁、提供什么具体产品价值；不要求事件直接影响 PredX 功能或存在精确市场。 | 产品价值 |

三条路径可以同时成立。PredX 承接必须输出最高连接层级与证据；`none` 不生成产品承接角度或伪造链接理由。只有“自然连接”、但尚不能说明具体产品价值时，不命中该准入路径，可作为 `angle_ready` 留在收件箱供运营人员探索。公共热度成立但 PredX 承接为 `none` 时，仍可作为仅公共热度的选题推荐，由运营人员判断是否采用。

## 5. 什么时候处理

已进入选题推荐的事件只分为两种处理节奏：

| 节奏 | 条件 | 运营要求 |
|---|---|---|
| 立即响应 | 满足以下任意一项：X 短时增速榜前 3；未来 12 小时内有直接相关的发布、投票、结算、截止或正式决定；过去 2 小时内有官方确认、正式结果或关键决定，且直接关联开放市场或 PredX 产品。 | 建议 2 小时内完成人工判断。 |
| 今日处理 | 已进入推荐、但不满足立即响应条件。 | 当天完成人工判断。 |

系统不设置“持续观察”。若出现新信息，将更新后的事件上下文重新提交判断。

## 6. 系统必须给出的结果

每张选题推荐卡至少包含：

- 事件摘要；
- 为什么进入推荐：命中的路径与证据；
- 处理节奏：立即响应或今日处理，以及依据；
- PredX 连接层级、匹配市场或官方链接，以及对应依据；
- 若干候选承接角度；
- 证据与来源链接；
- 风险和不确定性说明。

候选承接角度是“可以从什么问题或价值切入”，不是最终标题、文案或内容大纲。

## 7. 承接角度生成规则

Agent 生成角度时，先选择当前事件自然成立的承接面，再形成候选；不要求穷举，也不为凑数生成。

| 承接类型 | 可探索的承接面 |
|---|---|
| L1 直接连接 | 当前热点与活跃市场直接对应；可从当前预期、价格变化、新证据、结算条件、时间节点、关联市场或结果复盘切入。 |
| L2 类似连接 | 没有直接市场，但市场接口提供相似人物、事件或主题的市场；必须明确“类似”，不得写成当前热点的直接市场。 |
| L3 主题连接 | 热点适合从结果、概率、事件路径、截止节点或市场反应的主题切入。 |
| L4 概念连接 | 以预测、不确定性、意外、未知结果或事后市场反应做轻量连接；严肃事件必须尊重、克制，不做机会或交易导向。 |

每个 PredX 承接候选必须说明：最高连接层级、切入主张、目标用户、用户价值、事件／市场／产品证据、推荐官方链接及风险或未知。L1 或 L2 必须记录市场匹配来源；L4 可以没有具体市场。`none` 不生成产品承接角度。

候选之间必须在连接层级、承接面、核心问题或用户价值上有实质区别；只改写问法、标题风格或内容形式不算不同角度。产品能力、官方链接和表达边界一律以 PredX 基础配置为准。

用户要求重新推荐时，Agent 保留被明确保留的候选，避开已否定的核心方向，优先探索尚未覆盖的承接面。

## 8. 人工如何处理候选角度

| 动作 | 含义 |
|---|---|
| 直接采用 | 原样采用一个 Agent 候选角度。 |
| 修改后采用 | 以一个 Agent 候选为起点，人工修改后保存最终角度。说明 Agent 给出了可用起点。 |
| 人工新建角度 | 认可该选题，但最终方向不基于任何 Agent 候选。说明选题被采用，但 Agent 角度未被采用。 |
| 重新推荐 | 要求系统避开已否定的方向，探索新的候选角度；这是中间动作。 |
| 不采用 | 本次不做该选题，或没有可用角度。 |

每次处理记录原因和最终结果，用于计算选题采用率、Agent 角度采用率与重新推荐后的改善情况。

## 9. 权限边界

- **Agent**：读取上下文、按 PredX 基础配置判定连接层级、匹配市场并给出推荐理由与候选角度、根据反馈重新推荐。
- **程序**：提供实时市场、排行榜和时间数据，保存状态、证据、反馈和审计记录。
- **运营人员**：最终决定是否采用、修改或新建角度，并对高风险或低置信度判断复核。

运营人员的判断永远优先；系统不自动将热点对象送入内容生产。
