# Event 重复响应

## Why

热点 Event 首次响应后可能在短时间内出现新事实、状态变化、互动爆发或传播扩张，但持续上榜本身不应造成每小时重复生产。系统需要在响应及时性与专项追踪成本之间建立明确边界：合格 Signal 先经过普通触发过滤，首次响应后只在固定 24 小时窗口内执行增量判断，值得再次响应时直接创建新 Event 并启动独立内容链路。

## Capabilities

- **CAP-1 Signal 前置过滤**
  - **intent:** 系统先以生效的普通触发条件过滤小时 Signal，只让合格 Signal 进入 Event 识别。
  - **success:** 未命中 Top 5、相邻成功快照上升至少 10 位、重点主题、至少两个目标地区或人工触发的自动 Signal，只保存观察数据且不执行 Event 识别与专项增量判断。

- **CAP-2 响应窗口路由**
  - **intent:** 系统识别合格 Signal 是否属于当前处于有效固定 24 小时窗口的同一事件发展线，并选择普通响应或重复响应路径。
  - **success:** 无同一事件或旧窗口已结束时直接执行普通响应；同一事件且窗口有效时只进入五项再次响应条件判断。

- **CAP-3 增量重复响应**
  - **intent:** 系统在有效窗口内依据事实、状态、互动量、传播范围或人工指令判断是否再次响应。
  - **success:** R1—R5 任意一项成立即允许再次响应；五项均不成立时不创建 Event，其中 R3 固定为相邻成功快照互动总量增长至少 2 倍。

- **CAP-4 独立响应 Event**
  - **intent:** 每次被接受的普通触发或重复触发都创建新的 Event，并启动独立完整的内容响应链路。
  - **success:** 新 Event 记录事件发展线、上一响应 Event、触发 Signal、触发原因和窗口信息；上一轮内容是否完成不阻塞本轮创建与执行。

- **CAP-5 可追溯比较基线**
  - **intent:** 系统保存每次被接受触发的事实、状态、传播范围和快照基线，使后续增量判断可解释、可复现。
  - **success:** 排名和互动量使用相邻成功小时快照，事实、状态和传播范围使用上一次创建响应 Event 时的基线；普通观察快照不覆盖响应基线。

## Constraints

- 24 小时窗口属于事件发展线，从该轮第一次普通响应固定起算；窗口内新增 Event 不重置、不顺延窗口。
- 窗口结束后的下一张合格 Signal 按普通响应处理，不继承上一窗口的实质增量门槛；持续处于 Top 5 仍满足普通触发条件。
- 自动 Signal 未满足普通触发条件时不得进入 Event 识别或专项增量判断；人工触发可以绕过自动门槛，但必须记录操作者、时间和原因。
- 窗口内 R1 实质新事实、R2 状态实质变化、R3 互动量至少 2 倍、R4 传播范围扩张、R5 人工触发为“或”关系，任意一项成立即可再次响应。
- 实质新事实按 100 分指标判断：`≥15` 自动成立，`5–14` 人工判断，`<5` 不成立；来源冲突先核验，不自动响应。
- 互动总量固定为点赞、回复/评论、转发和引用转发之和，只比较相邻成功小时快照；失败、不完整、不同口径或上一快照为 0 的数据不得以倍数自动触发。
- 只有系统接受触发并创建新 Event 时，才更新事实、状态和传播范围响应基线。
- 详细流程、指标、硬规则、字段合同、决策表与验收场景以伴随文档 [response-rules.md](./response-rules.md) 为准。

## Non-goals

- 不定义跨来源 Event 的合并评分、拆分或人工合并流程。
- 不定义内容候选的写作、审核、发布和效果追踪细节。
- 不用冷却时间代替增量判断，也不让窗口内新 Event 自动延长 24 小时窗口。
- 不因普通观察快照、重复报道、措辞变化或低增量波动重复创建 Event。

## Success signal

- 给定连续小时快照，系统能稳定区分窗口外普通响应、窗口内有效重复响应和应过滤的无增量 Signal；每次决策均能回溯触发规则、窗口、比较基线及 R1—R5 的判断结果。
- 验收样例中，窗口内互动量增长 2 倍、新事实达到 15 分、标准状态迁移或传播范围扩张均能独立创建新 Event；无增量的持续高位 Signal 不会在窗口内重复创建 Event。
