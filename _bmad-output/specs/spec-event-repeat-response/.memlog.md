topic: Event重复响应规则
updated: 2026-08-21T15:42
---

- (direction) 用户确认将 Event 重复响应规则定为终版，并迁入 _bmad-output/specs/spec-event-repeat-response。
- (capability) CAP-1：系统先用普通触发条件过滤小时 Signal，只有合格 Signal 才进入 Event 识别。
- (capability) CAP-2：系统识别合格 Signal 是否属于处于有效固定 24 小时窗口的同一事件发展线，并据此选择普通响应或重复响应。
- (capability) CAP-3：窗口内 R1 实质新事实、R2 状态实质变化、R3 相邻成功快照互动量至少 2 倍、R4 传播范围扩张、R5 人工触发任一成立即可再次响应。
- (capability) CAP-4：每次普通或重复响应均创建新的 Event，记录事件发展线关系并启动独立完整内容响应链路。
- (capability) CAP-5：系统保存并更新事实、状态、传播范围与成功小时快照基线，使每次增量判断可解释、可追溯。
- (constraint) 24 小时窗口属于事件发展线，从该轮首次普通响应固定起算；窗口内新增 Event 不重置、不顺延窗口。
- (constraint) 窗口结束后的下一张合格 Signal 按普通响应处理，不受上一窗口实质增量门槛限制；持续 Top 5 仍可满足普通触发。
- (constraint) 实质新事实采用 100 分指标，达到 15 分自动成立、5 至 14 分人工判断、低于 5 分不成立；冲突事实先核验。
- (constraint) 互动总量为点赞、回复或评论、转发、引用转发之和，只在相邻成功小时快照之间按相同口径比较；上一快照为 0 时不以倍数自动触发。
- (constraint) 自动 Signal 未满足普通触发条件时不进入 Event 识别，也不执行专项增量判断；人工触发可绕过自动门槛但必须审计。
- (decision) 普通触发条件为当前 Top 5、相邻成功快照上升至少 10 位、命中重点主题、至少两个目标地区或人工触发。
- (decision) 状态实质变化采用明确状态迁移；传播范围扩张采用新增目标地区、多地区扩散、进入 Worldwide 或新增独立渠道。
- (decision) 只有接受触发并创建新 Event 时才更新事实、状态和传播范围响应基线；普通小时快照不覆盖这些基线。
- (note) 详细指标、流程图、决策表和验收场景保存在伴随文档 response-rules.md。
- (event) Coherence validation passed：SPEC 满足五字段内核、CAP-1 至 CAP-5 均含 intent 与 success、约束和非目标明确，详细规则由 companion 承载。
- (event) Preservation validation passed：源规则中的流程顺序、24 小时窗口、R1 至 R5 或关系、2 倍互动门槛、新事实评分、状态迁移、传播扩张、基线、决策表和验收场景均保存在 SPEC 或 response-rules.md。
- (event) Spec finalized：Event 重复响应规则确认为终版并纳入 specs 权威索引。
