# PredX 热点—产品承接基础配置

状态：v3，平台级共享配置

更新日期：2026-08-31

适用范围：热点匹配、运营机会排序、PredX 承接角度生成、X 内部选题、后续内容生成与审核

## 1. 使用目标

本配置是 PredX 热点运营链路的产品事实源。所有上游匹配器和下游 Agent 必须用它回答四个问题：

1. 当前热点能否由 PredX 承接；
2. 属于哪一种连接层级；
3. 最自然的产品价值和官方链接是什么；
4. 哪些能力与表述可以使用。

当前只生成供运营人员评估的 X 平台内部选题，不自动发布。

增长目标：

- **主目标**：扩大 PredX 曝光，让潜在用户知道产品存在，建立品牌知名度；
- **次目标**：推动留存和回访，让用户在热点发生时想到用 PredX 查看新闻、相关市场和市场反应。

产品价值不设固定优先级。每个热点选择当下最自然、最容易理解的一项价值，不为展示完整功能而堆叠卖点。

## 2. 产品事实

### 2.1 PredX 是什么

PredX 是面向 Polymarket 交易者的新闻情报与研究产品。它将新闻整理为事件，把事件连接到相关 Polymarket 市场，帮助用户理解发生了什么、哪些市场可能受影响、Polymarket 如何定价这件事，以及还有哪些市场值得观察。

对大众受众的默认短句：

> PredX 帮助用户从一条热点新闻找到相关预测市场，并观察市场如何反应。

PredX 是独立产品，与 Polymarket 不存在隶属、官方合作或背书关系。

### 2.2 主要用户

- Polymarket 交易者和预测市场用户；
- 关注新闻如何影响市场的人；
- 对新闻、概率、不确定性和市场反应感兴趣的人；
- 希望从新闻快速找到相关预测市场的潜在用户。

曝光阶段不要求选题只服务专业交易者。娱乐、名人、科技、政治、金融、体育等大众热点均可作为新用户理解 PredX 的入口。

### 2.3 已确认上线的核心能力

官网明确将 Mapping Layer 标为已上线：

| 能力 | 允许的产品主张 |
|---|---|
| 实体识别 | 识别新闻中的人物、国家、机构、球队、政策、资产代码等实体。 |
| 事件聚合 | 将多条相关报道整理为同一个事件或故事线。 |
| 活跃市场匹配 | 为事件寻找最相关的 Polymarket 活跃市场。 |
| 相关市场扩展 | 找到同一事件可能影响的其他市场，而非只看单一合约。 |
| 关系分层 | 用直接、间接、延伸等层级表达事件与市场的不同关联程度。 |

允许概括为：

> PredX 能把新闻整理成事件，匹配相关 Polymarket 市场，并扩展出同一事件可能影响的其他市场。

### 2.4 部分上线能力

以下页面或能力处于部分上线状态。Agent 只有在本次任务拿到可验证页面数据或产品返回结果时，才可描述具体内容：

- Signal Feed；
- Event Page；
- Market Page；
- Telegram 信号；
- Watchlist；
- Price Alert；
- 从卡片跳转并通过用户自己的钱包在 Polymarket 操作；
- 订单簿深度和滑点展示。

没有本次可验证结果时，只能链接相应产品页面或使用 2.3 的核心能力，不得补写具体信号、价格、深度、提醒状态或交易入口。

### 2.5 尚未上线的能力

官网标为 `Coming soon` 的能力不能写成当前功能：

- Resolution Verdict 自动结算条件判断；
- 多维置信度与多来源验证评分；
- UMA 争议风险提示；
- Mispricing Detection；
- Overreaction、Underreaction、Wrong Direction 信号；
- BUY YES、BUY NO、WATCH、AVOID 等结构化决策卡；
- Alpha Window；
- 信号发布后 1h / 6h / 24h 表现记录及公开 Track Record。

## 3. 官方链接注册表

内容需要产品承接时，必须从本表选择至少一个官方链接；不得猜测路径或使用第三方页面替代产品入口。

| 链接 ID | 官方页面 | URL | 使用场景 |
|---|---|---|---|
| `predx_home` | PredX 首页 | https://predx.pro/home | 默认链接；品牌介绍、轻连接、概念连接或无法确定更具体入口时使用。 |
| `predx_news` | PredX News | https://predx.pro/news | 新闻、热点、事件时间线、同类事件承接。 |
| `predx_market` | PredX Markets | https://predx.pro/market | 直接市场、类似市场、相关市场和市场反应承接。 |
| `predx_signal` | PredX Signal | https://predx.pro/signal | 已有可验证 Signal 数据，或选题明确引导查看 Signal 页面时使用。 |

链接规则：

1. 默认使用 `https://predx.pro/home`；
2. 有明确新闻或市场承接角度时，优先使用对应深层链接；
3. 一条 X 内容通常放一个最相关的 PredX 链接，避免链接堆叠；
4. 内部选题必须输出 `recommended_product_url` 和选择原因；
5. 最终内容必须保留可点击的完整 URL；
6. 链接存在不代表页面内一定有本次热点的数据，具体内容仍需运行时验证。

## 4. 运营系统补充的市场匹配

产品覆盖 Polymarket 活跃市场。运营系统取得市场接口后，可以自行完成：

- 当前热点的直接市场匹配；
- 相似人物、相似事件或同类主题的市场匹配。

这些匹配属于运营系统的运行时结果，不自动等于 PredX 页面已经展示了该关系。

表达必须标明来源层级：

- 产品页面可验证：可以写“在 PredX 查看相关市场”；
- 运营系统通过市场接口匹配：写“可以从这个热点延伸观察这些类似市场”；
- 只有概念连接：只表达预测、不确定性或市场反应，不声称存在具体市场。

## 5. 热点承接判断

具体市场不是准入条件。系统按以下顺序寻找最强且真实的连接，命中后仍可保留更弱连接作为备选角度。

### L1：直接市场连接

热点中的人物、机构、动作、结果、时间或条件与一个活跃市场直接对应。

示例：候选人正式宣布退选，连接“是否退选”或“是否在大会前退选”的市场。

### L2：类似市场连接

当前热点没有直接市场，但市场接口能找到相似人物、相似事件或同类主题的市场。

示例：明星 A 出现恋爱八卦，没有明星 A 的市场，但存在其他名人的恋爱、结婚、分手、获奖或公开活动市场。

必须明确它是类似市场，不得把它描述成当前热点的直接市场。

### L3：主题连接

没有合适的直接或类似市场，但热点属于可讨论结果、概率、事件路径、截止节点或市场反应的主题。

示例：明星突然退出一部电影，从“公众事件可能沿多个结果发展”切入预测市场研究。

### L4：概念或情绪连接

热点与具体市场关系较弱，但可以用预测、不确定性、意外、结果未知或事后市场反应做轻量承接。

示例：名人去世时可以克制表达“世事无常，并不是所有事情都能够被预测”，再引出 PredX 关注新闻发生后与预测市场之间的关系。

L4 可以很短，不要求展开完整产品介绍。它仍须尊重事实和事件，不暗示 PredX 预测了意外。

### `none`：跳过产品承接

满足任一条件时输出 `none`：

- 无法形成一句自然、可理解的 PredX 连接；
- 承接必须虚构市场、产品数据或产品能力；
- 热点事实不足，连轻量概念表达都可能误导；
- 严肃事件的唯一角度是玩梗、交易机会或消费受害者。

完成标准：每个候选必须输出一个最高连接层级及证据；没有可靠连接则明确为 `none`。

## 6. 动态选择产品价值

| 热点特征 | 首选产品价值 |
|---|---|
| 有直接对应市场 | 从新闻找到相关市场。 |
| 一个事件关联多个合约 | 一条事件可以影响多个市场。 |
| 没有直接市场但有类似市场 | 从相似人物或事件发现同类市场。 |
| 涉及条件、期限或正式动作 | 区分主题相关与具体结算条件。 |
| 新闻后市场明显变化 | 观察市场如何重新定价。 |
| 重要新闻但市场不动 | 研究市场为何没有明显反应。 |
| 娱乐或名人八卦 | 从类似名人市场、事件预测或不确定性切入。 |
| 意外、死亡或灾害 | 从预测边界与世界的不确定性克制切入。 |
| 仅有宽泛联系 | 用一句预测、概率或未知结果的轻连接建立品牌认知。 |

选择规则：使用最贴近热点的一项主价值；只有第二项能明显增加理解时才增加辅助价值。

## 7. 选题排序

当前增长目标以曝光为先，候选默认按以下顺序综合排序：

1. 热度、时效性和传播潜力；
2. PredX 连接是否自然；
3. 是否容易让新用户理解 PredX；
4. 是否存在直接或类似市场；
5. 是否能带来后续访问或回访。

直接市场不是绝对优先条件。高传播热点即使只有 L2、L3 或 L4 连接，也可以优先成为内部选题。

## 8. 语气和风险

| 热点类别 | 默认语气 |
|---|---|
| 娱乐、名人、体育 | 轻松、有趣、有网感。 |
| 科技、商业 | 敏锐、简洁，可以提出研究问题。 |
| 政治、金融 | 准确、克制，不下交易结论。 |
| 死亡、灾害、战争 | 尊重、克制，不玩梗，不使用机会导向。 |

所有类别均使用事实支持的有限表达。市场关系、价格反应和因果判断分别表述，不互相替代。

## 9. 硬性表达边界

Agent 必须将内容落在以下正向边界内：

- 将 PredX 表述为独立的 Polymarket 新闻情报与研究产品；
- 将市场匹配表述为关联或研究路径；
- 将价格表述为交易活动形成的市场价格；
- 将未来能力明确表述为即将上线；
- 将最终判断和交易决定留给用户。

禁止声称：

- PredX 是 Polymarket 官方产品、合作伙伴或获其背书；
- PredX 能准确预测事件、死亡、灾难或未来结果；
- PredX 决定 Polymarket 的官方结算；
- PredX 保证某个市场结算为 Yes 或 No；
- PredX 提供个性化投资建议或保证收益；
- PredX 是自动交易或自动跟单机器人；
- 市场价格等于事实或有保证的真实概率；
- 新闻与价格在时间上接近即可证明因果；
- 类似市场就是当前热点的直接市场；
- 运营系统的接口匹配已经出现在 PredX 产品页；
- `Coming soon` 能力已经上线；
- 部分上线能力在缺少运行时验证时有具体数据或结果。

## 10. 内部选题输出合同

```yaml
predx_opportunity:
  status: supported | none
  association_level: L1_direct | L2_analogous | L3_thematic | L4_conceptual | none
  event_evidence_ids: []
  rationale: string
  matched_markets:
    source: predx_verified | operations_market_api | none
    relationship: direct | analogous | thematic | none
    items: []
  selected_product_value: string
  angle: string
  recommended_product_page: home | news | market | signal
  recommended_product_url: string
  url_reason: string
  x_topic_direction: string
  tone: light | sharp | neutral | restrained
  risk_notes: []
  prohibited_claims: []
  requires_runtime_verification: []
  checked_at: ISO-8601
  reference_version: v3
```

约束：

- `supported` 必须有连接层级、理由、产品价值、承接角度和官方链接；
- `L1` 或 `L2` 必须记录市场匹配来源；
- `operations_market_api` 的结果不得写成 PredX 页面已有内容；
- `L4` 的 `matched_markets.items` 可以为空；
- `none` 不生成产品角度或伪造链接承接理由；
- 输出是内部选题，不得标记为已发布内容。

## 11. 正反例

### 可用

1. 候选人正式退选 → 直接匹配退选相关市场，解释不同截止时间可能对应不同结果。
2. 明星恋爱八卦但无直接市场 → 用市场接口寻找其他名人婚恋类市场，明确称为类似市场。
3. 央行公布利率决定 → 连接相关活跃市场，观察市场如何定价公告。
4. 重要新闻发布但市场不动 → 从提前计价、结算无关或价格发现缓慢提出研究角度。
5. 名人去世 → 克制表达预测的边界和世事无常，使用 PredX 首页做轻量品牌承接。

### 不可用

1. 只因新闻和市场出现同一人物，就称市场受到直接影响。
2. 把相似名人的市场说成当前明星八卦的对应市场。
3. 把“考虑”“计划”写成“已经实施”或“已满足结算”。
4. 新闻后价格上涨，就确认新闻导致上涨并给出买入建议。
5. 借死亡或灾害宣传“PredX 提前发现交易机会”或暗示产品预测成功。

## 12. 维护规则

- 本文件是热点运营系统中 PredX 产品承接的单一事实源；其他提示词引用它，不复制维护同一套规则。
- 产品能力、页面状态、官方 URL 或增长目标变化时，先更新本文件，再允许下游使用新主张。
- 部分上线能力只有经产品确认或运行时验证后才能迁入“已确认上线”。
- 每周抽样复核各连接层级，重点检查 L2 是否被误写成 L1、L4 是否不尊重严肃事件。
- 每次修改记录版本、日期、变更原因和来源。
