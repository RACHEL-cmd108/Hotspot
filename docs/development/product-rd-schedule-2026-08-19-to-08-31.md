# 热点监控产品研发排期（8/19—8/31）

> 版本：v3.0（主链质量收敛版）  
> 当前状态：热搜榜与 Future Event 已能产出对应账号内容，但内容可用性、事件准确性和运营工作台尚未通过验收。  
> 目标：8 月 31 日交付“可信、去重、可管理、可扩展”的统一产品；爆款拆解完成最小可演示闭环。

## 一、结论

“能生成内容”只证明技术链路通了，不代表产品闭环完成。本期优先级调整为：

1. **P0：Event 与 Evidence 正确性。**
2. **P0：重复响应控制与运营任务生命周期。**
3. **P0：Signal、Future Event、主题圈进入响应系统的统一边界。**
4. **P1：可扩展性与 Agent 参与边界。**
5. **P1：爆款内容拆解 MVP。**

## 二、统一业务边界

### 2.1 对象与进入条件

```text
热搜榜 / 重点主题圈 / Future Event / 人工输入
                    ↓
                  Signal
                    ↓
             Candidate Event
        （聚合、证据补充、去重、判断）
                    ↓
    命中响应规则 / 人工触发 / 已授权自动触发
                    ↓
                  Event
                    ↓
 Account Response Task → 候选内容 → 人工发布 → 追踪
```

| 对象 | 定义 | 是否出现在事件管理 | 是否触发内容 |
|---|---|---:|---:|
| Signal | 一次原始观察，如榜单快照、主题圈帖子、官方日历更新 | 否 | 否 |
| Candidate Event | 多个 Signal 聚合后的待判断候选 | 仅待处理区 | 否 |
| Future Event | 未来事实与运营排期对象 | 运营排期页 | 默认否 |
| Event | 已进入响应系统、可向账号创建响应任务的事件 | 是 | 是 |
| Event Archive | 已完成或过期 Event 的持久记录 | 事件仓库 | 否 |

**规则变更：**Future Event 有官方链接也只表示它有 Evidence，不代表自动进入事件管理。只有运营手动触发、实时 Signal 命中或明确授权的自动规则命中后，才创建/复用 Event。

### 2.2 重复触发规则

同一 Event 每小时继续上榜时，只更新观察数据，不重复触发内容任务。重新响应必须同时满足：

- 出现新的、会改变内容表达的事实；或
- 事件状态发生实质变化；或
- 运营人员主动要求重新生成。

实现上必须具备：

- 稳定的 `event_identity_key`；
- Signal 与 Event 的关联记录；
- `material_fact_fingerprint` 或 Event 版本；
- `Event × Account × Skill Version` 唯一任务键；
- Trigger Ledger，记录本次为何只更新、为何重新响应。

单纯增加冷却时间不算修复，因为冷却结束后仍会重复生成。

### 2.3 生命周期与工作台

- Event 是长期记录，不因完成而删除。
- Account Response Task 是运营待办，完成、取消或超过响应窗口后离开“今日任务”。
- 内容发布首页默认只展示“今天需要处理”的任务。
- 已完成、过期、取消内容进入事件仓库，可按日期、来源类型、Event 类型、账号和状态检索。
- 筛选器使用少量业务分类和默认视图，不让运营面对全部 Event 的长列表。

建议默认视图：`今日待处理`、`待审核`、`待发布`、`发布失败`、`已完成`；历史记录进入`事件仓库`。

## 三、问题台账与验收标准

| ID | 问题 | 可能所属根因 | 产品规则/修复方向 | 验收信号 |
|---|---|---|---|---|
| Q-01 | Hayden 事件来源依据不对应 | X 热搜详情结果本身偏题；查询词错误；聚合错绑；展示关联错 | 保存榜单原始标题、查询、详情响应和关联理由；逐层回放定位 | 给定 Event 可追到原始榜单与每条 Evidence，错误层可明确指出 |
| Q-02 | 每小时重复触发 | 缺少稳定 Event 身份、事实版本或任务幂等 | 相同身份只更新 Signal/热度；新事实才新 Event 版本并评估是否重生成 | 连续 3 个相同小时快照只产生一个账号任务 |
| Q-03 | 完成 Event 一直占据面板 | Event 生命周期与任务收件箱混用 | 今日工作台只展示活跃任务；完成/过期进入仓库 | 默认页不再出现历史完成任务，仓库仍可查询 |
| Q-04 | 合并拆分莫名进入人工判断 | 缺少置信度分层与复核原因 | 高置信度自动合并；低置信度不合并；仅不确定区进入人工；拆分仅在证据出现内部冲突时建议 | 每个 HITL 项都有候选对象、相似/冲突依据和建议动作 |
| Q-05 | Future Event 自动进入且无证据 | 排期与响应边界混淆；官方 Evidence 未传递 | 官方链接进入 Future Event Evidence；默认不进入 Event；手动/Signal/授权规则触发后带证据创建 Event | 未触发事件只在排期；触发后 Event 显示官方网站 Evidence |
| Q-06 | 多地区榜单语言不一致 | 原始语言与统一检索/展示字段未分离 | 保留原始标题；增加统一工作语言的规范标题和语言标识；Evidence 原文不静默改写 | 可按统一标题聚合，同时能查看原文与语言 |
| Q-07 | Signal 与 Event 边界不清 | 领域定义和实现不一致 | 进入响应系统才成为 Event；此前为 Signal/Candidate Event | 任一对象可解释当前阶段及为什么进入下一阶段 |
| Q-08 | 重点主题圈不能进入事件处理 | 入口未接统一 Candidate/Event 管道 | 主题圈命中讨论广度/流量阈值时创建 Candidate Event，复用同一聚合与响应规则 | 主题圈案例可进入待处理区并在命中后形成 Event |
| Q-09 | 内容发布 Event 难筛选 | 页面以 Event 全量列表代替任务视图 | 默认按任务状态、日期和类型组织；历史进入仓库 | 运营能在两次点击内找到今日待发布任务 |
| Q-10 | 多地区仍只看到三条 Evidence | 采集只执行一次；去重后丢失地区关系；UI 截断 | 每地区保留最多 3 个 Evidence Slot；Evidence URL 可去重，但地区关联不能丢；展示唯一来源数与地区槽位数 | 两地区分别返回 3 条时显示 6 个槽位；链接重合时说明去重关系 |

## 四、Evidence 正确模型

```text
Event
  ├─ Region Snapshot: US / 08:00 / rank 3
  │    ├─ Evidence Slot 1 → Tweet A
  │    ├─ Evidence Slot 2 → Tweet B
  │    └─ Evidence Slot 3 → Tweet C
  └─ Region Snapshot: UK / 08:00 / rank 5
       ├─ Evidence Slot 1 → Tweet A（同链接，可复用 Evidence）
       ├─ Evidence Slot 2 → Tweet D
       └─ Evidence Slot 3 → Tweet E
```

页面应分别显示：

- 地区快照数量；
- Evidence 槽位数量；
- 去重后的唯一来源数量；
- 每条来源支持什么事实；
- 采集不足、查询偏题或被排除的原因。

“两个地区只显示 3 条”不一定是链接重合，也可能是采集只按 Event 执行一次或 UI 只取前三条，必须通过上述关系与原始运行记录定位。

## 五、Agent 参与边界

| 环节 | Agent 职责 | 不得做的事 |
|---|---|---|
| Candidate 聚合 | 给出同一事件概率、相似依据和冲突点 | 无依据直接合并/拆分 |
| Evidence 相关性 | 判断来源是否真正支持 Event/Fact，给出理由 | 删除原始来源或把热度当事实 |
| Event 摘要 | 在 Evidence 范围内拆分已确认、未知、冲突事实 | 补造事实、时间或来源 |
| 内容生成 | 按 Event Context、账号 Skill 生成候选 | 将生成成功等同于内容可用 |
| 内容质量评审 | 评估事实忠实度、账号适配、原创性、表达和风险 | 自动批准高风险内容 |
| 爆款拆解 | 提取 Hook、结构、节奏、互动机制和复刻边界 | 复制原文/素材或声称因果 |
| 复盘建议 | 根据结果提出规则/Skill 实验建议 | 自动改写线上规则 |

程序继续负责采集、唯一键、阈值、状态机、版本、审计和写入；人工负责不确定聚合、高风险内容、最终采用和规则发布。

## 七、8/31 验收门槛

必须通过：

- 同一事件连续多小时上榜但没有新事实时，不重复创建内容任务。
- 每个 Event 的事实可追到全部 Evidence、地区快照和官方来源。
- Future Event 未人工触发且未命中明确规则时，不进入事件管理。
- 重点主题圈可以进入统一 Candidate Event 处理链。
- 合并/拆分人工队列只包含有明确不确定性依据的项目。
- 今日工作台默认不出现已完成或过期任务，历史可在事件仓库查询。
- 多语言榜单具有统一规范标题，同时保留原始语言。
- 至少建立一套内容可用性评审结果，而不是只验证生成数量。

有余量再交付：

- 爆款内容拆解的完整样本库、自动筛选和 Insight 引用。
- 多 Agent 拆解、Agent 质量/成本看板。
- 更多平台与监测源扩展演示。

## 八、当前阻塞信息

Hayden 来源错配的根因不能仅凭页面现象判断。需要以下最小诊断材料：

- Event ID 或准确标题；
- 出现问题的地区与榜单快照时间；
- 系统保存的热搜原始项；
- X 热搜详情查询词与返回帖子 ID/URL；
- Event—Evidence 关联记录或页面截图。

拿到这些材料后，才能区分是 X 热搜详情本身偏题、查询构造错误、聚合错绑、Evidence 去重错误，还是前端展示截断。
