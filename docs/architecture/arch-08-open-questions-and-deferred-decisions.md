# 08 开放问题与延后决策

| 项目 | 当前处理 | 重新决策触发条件 |
| --- | --- | --- |
| 云供应商/区域/套餐 | 不绑定；以托管、可备份、可替换为约束。 | Staging 的连通性、恢复和成本验证完成。 |
| X API 配额与具体查询 | 已固定 Trends-by-WOEID、Recent Search 与公开指标读取的接口层次；具体 WOEID、查询模板和额度不绑定。 | Staging 用真实账号验证五地区、查询质量、限流和成本。 |
| AI 模型/供应商 | 端口化，不写入领域规则。 | 质量、成本、合规或可用性评估完成。 |
| Content Insight / 热点内容 | 仅保留概念边界，不建活跃采集与判定流水线。 | 产品定义输入、判定口径、字段、版权与验收。 |
| 多账号扩展与替代策略 | Phase 0 固定三个预配置账号，不替代；单账号异常不阻塞其他账号。 | 产品需要超过三个账号、动态匹配、优先级、容量或替代规则。 |
| 自动合并阈值 | 初始 `0.95`，作为版本化配置而非代码常量。 | 运行数据表明误合并率或人工复核负担需要调整。 |
| 自动 X 发布 | 当前明确不实现。 | 产品定义审批、回滚、平台写入授权与未知结果处置。 |
| 外部营销实际执行 | 只导出/交接 Campaign Proposal。 | 产品明确执行系统、预算/审批和回执语义。 |
| 服务拆分与多区容灾 | 维持模块单体与单区恢复。 | 容量、独立 SLO 或团队边界提供证据。 |

已关闭：承接账号、Content Skill 和“每账号候选”已由新版 PRD 定义为版本化配置与账号专属对象，不再是 OQ-01。

## 进入开发前的架构验收

1. 用 Staging 验证 Google 登录、X 五地区读取和 AI 生成，以及失败、限流、审计与人工接管。
2. 用代表数据验证每出现地区最多三条来源的记录、三个 Predx ART（或单账号异常）、每个可用账号至少三条候选、人工 URL/失败原因回填。
3. 完成备份恢复演练，并验证 RPO ≤1小时、RTO ≤4小时的证据。
4. 验证最新版 UX/UI 的代表任务；旧 UX v1.x 不参与开发验收。
5. 对同一 Event 并发触发、Event 校正期间 AI 返回、多人回填同一发布尝试分别做自动化测试；不得产生重复 ART、过时候选或被覆盖的终态回填。
