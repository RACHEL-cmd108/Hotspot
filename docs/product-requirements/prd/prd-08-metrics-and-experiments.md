# 08 指标与实验

## 8.1 完整产品成功指标

完整产品首先衡量三项价值：更早发现、在窗口内更快响应、以及借助账号适配与爆款拆解产出更好内容。除 Phase 0 已确认指标外，阈值应在两个连续运营周期建立基线后设定。

| ID | 指标 | 定义 | 目标值/复审条件 | 测量方式 |
|---|---|---|---|---|
| PM-01 | 合格热点发现时长 | 从首个满足监测条件的 Signal 出现，到 Candidate Event 进入核验的耗时。 | `[ASSUMPTION]` 建立人工基线后连续缩短。 | 采集日志与 Candidate Event 时间。 |
| PM-02 | 热点内容洞察覆盖率 | 完成来源与基础爆款拆解的热点内容样本 / 进入分析范围的热点内容样本。 | `[ASSUMPTION]` 首轮建立基线。 | Content Insight 与内容样本记录。 |
| PM-03 | 来源聚合响应就绪率 | 完成规定地区来源聚合并创建至少一个账号任务的合格 Event / 合格 Event。 | `[ASSUMPTION]` 试点目标 ≥ 90%。 | Event Card、来源、规则与任务记录。 |
| PM-04 | 候选生成耗时 | 从成功采集记录合格触发，到账号候选可在系统工作台操作的实际耗时分布。 | 首轮建立 P50/P95 基线，不设固定 SLA。 | 采集、任务、预检与候选可操作时间。 |
| PM-05 | 账号专属候选可用率 | 内容运营至少选择或经调整后发布一条候选的账号任务 / 候选已生成普通任务。 | `[ASSUMPTION]` 建立基线后提升。 | 候选选择、调整和发布链接。 |
| PM-06 | 内容洞察采用率 | 被账号任务显式引用的可引用 Content Insight / 可引用 Content Insight。 | `[ASSUMPTION]` 先验证洞察是否被认为有用。 | 任务—洞察引用与运营反馈。 |
| PM-07 | 账号内容表现改善度 | 按可比账号、内容类型、观察窗口和洞察引用情况计算的发布后基础表现变化。 | `[ASSUMPTION]` 建立基线；不以单次爆款判断。 | 平台指标、账号/Skill、洞察引用与样本分组。 |
| PM-08 | 活动准备建议采用率 | 用户主动启动方案生成的活动准备建议 / 有效建议。 | `[ASSUMPTION]` 先验证推荐解释是否有用。 | 建议、启动和忽略原因。 |
| PM-09 | 活动方案可用率 | 被用户选择、调整后导出或交接的活动方案 / 已生成活动方案。 | `[ASSUMPTION]` 先建立基线。 | 方案版本、选择和交接记录。 |
| PM-10 | 规则优化复用率 | 获批并被后续任务/洞察/建议规则使用的策略建议 / 已批准建议。 | `[ASSUMPTION]` 首个运营周期建立基线。 | 规则版本、对象引用与建议记录。 |

**反向指标：**未经人工审核的高风险内容发布数 = 0；无来源事实进入可发布候选数 = 0；候选跨账号复用次数 = 0；未经来源/边界标记的热点内容洞察数 = 0；系统自动创建营销活动数 = 0；系统内产生 KOL 触达任务数 = 0；私域消息自动发送数 = 0。

## 8.2 Phase 0 验证实验

| ID | 指标 | 定义 | 目标 | 衡量方式 |
|---|---|---|---:|---|
| P0-01 | 趋势采集完整率 | 实际获得趋势数 / 计划趋势数 | ≥ 95% | 每次采集日志。 |
| P0-02 | 地区前三条来源采集成功率 | 每个出现地区均获得热搜详情快照前三条推文的合格 Event / 合格 Event | ≥ 90% | X 快照、地区、排名与原始链接。 |
| P0-03 | 三账号路由覆盖率 | 形成 Event 后，三个预配置 Predx X 账号各自恰好创建一个任务，或对不可用账号记录异常的账号响应单元 / 应响应账号单元 | 100% | Event、账号配置、任务与异常记录。 |
| P0-04 | Event 形成完成率 | 已完成地区来源聚合并形成 Event/来源状态的 Candidate Event / 进入处理流程的 Candidate Event | ≥ 90% | Candidate Event、Evidence 与 Event Card。 |
| P0-05 | 账号专属候选供给达标率 | 至少生成 3 条绑定同一账号与 Content Skill 的候选的普通任务 / 已创建普通任务 | 100% | 任务、账号/Skill、草稿与预检记录。 |
| P0-06 | 来源状态与预检完整率 | 来源状态可见、未包含无来源断言或禁用表达的候选 / 可操作普通候选 | 100% | 自动检查加人工抽检。 |
| P0-07 | 人工选择与发布闭环率 | 在该任务选择一条、人工发布并回填 URL 的任务 / 候选已可操作的普通任务 | 首轮建立基线；记录实际耗时与未完成原因 | 任务状态、选择、候选可操作时间、URL 与回填时间。 |
| P0-08 | 高风险人工门禁符合率 | 被标记为高风险且未经明确审核即进入发布回填的任务数量 | 0 | 风险、审核、任务和 URL 记录。 |
| P0-09 | 来源采集异常记录完整率 | 未能获得规定来源条数时，已记录实际数量、地区、失败原因与时间的异常 / 来源采集异常 | 100% | 来源采集日志与异常记录。 |

**实验边界：**连续验证两周，最少覆盖 30 个进入处理流程的 Candidate Event，并以已创建的普通社媒账号任务为内容闭环样本单位。Phase 0 验证“合格热点触发 → 每个出现地区详情快照前三条来源聚合 → Event / Event Card → 三个预配置 Predx X 账号任务（每账号至少 3 条候选自动预检并在系统工作台可操作，或记录该账号异常）→ 人工选择、X 手动发布、URL 回填”；记录实际耗时而不验证固定分钟级 SLA。热点内容拆解、活动策划、私域话题建议和 Telegram 投递不作为 Phase 0 通过条件；也不验证系统向社媒账号直接发布。
