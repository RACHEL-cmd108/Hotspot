# 01 产品愿景与目标

## 1.1 产品愿景

Hotspot Monitor 是面向运营人员的热点内容运营系统。它将实时热点、未来事件和正在流行的具体内容转化为统一的事件上下文、账号专属内容候选与可复用的爆款灵感。

产品的两项核心价值是：**更快响应**——缩短从热点发现、来源聚合到可选候选的人工操作链路；**更好生产**——理解什么具体内容正在成功传播，将其中可复刻的结构作为账号内容生产的灵感，而不是只追逐热搜词。

## 1.2 产品目标

1. 从热搜榜、重点主题、跨区变化和热点内容中更早发现运营信号。
2. 通过 Event、Fact、Evidence 与 Event Card 提供可追溯的热点上下文，并明确来源一致、冲突或未知状态。
3. 将命中内容响应规则的 Event 直接转化为账号专属内容任务与候选。
4. 为热点内容/爆款拆解预留独立入口、概念对象和复刻边界；在后续单独定义来源与口径后，再服务内容生成。
5. 对具备活动准备条件的 Event（首版优先 Future Event）给出可解释的活动建议；仅在运营人员主动启动后生成三套活动方案草稿。
6. 将发布结果、账号表现、爆款洞察采用情况和异常原因反馈到监测、响应、账号/Skill 与活动建议规则。

## 1.3 成功定义

当热点出现时，内容运营不需要在热搜、原帖、账号资料和写作工具之间反复切换：系统能提供来源聚合后的 Event 与承接账号对应的候选内容；运营人员在系统中完成选择、必要调整、人工发布和链接回填。热点内容洞察是后续预留能力，不是当前闭环前提。

当运营人员寻找内容灵感时，系统不只告诉其“什么选题火”，还说明“什么内容为什么火、哪些部分可复刻、适合哪些账号和场景”。活动策划则只在用户需要时提供准备建议和三套方案草稿，不承担立项或执行。

## 1.4 当前验证目标

Phase 0 在 Predx 内容运营的突发热点场景验证最短内容闭环：合格热搜触发后，系统对每个出现地区采集热搜详情快照前三条推文，聚合为 Event 与 Event Card；随后为三个预配置 Predx X 账号分别创建账号响应任务，每个可用账号生成至少 3 条账号专属普通社媒候选。内容运营在系统工作台选择、复制或调整候选，在 X 手动发布并回填实际发布链接。账号或 Content Skill 不可用时，仅该账号任务进入异常，不创建替代任务，也不阻塞其他可用账号。

Phase 0 记录采集、聚合、生成、选择和回填的实际耗时，不以固定分钟级 SLA 判断通过。热点内容的发现、爆款拆解与可复刻要素沉淀是完整产品的 M1/M4 能力方向；Future Event 的活动策划是 M3 支线。KOL 工作流不属于本系统；私域只保留未来话题讨论建议方向。
