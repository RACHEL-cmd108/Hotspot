# 09 决策与开放问题

## 9.1 决策与变更记录

| ID | 决策 | 依据 | 影响 |
|---|---|---|---|
| D-01 | 第一优先用户是内容运营，核心场景是突发热点快速响应。 | Brief 与用户确认 | 需求围绕时效、账号候选质量与灵感供给组织。 |
| D-02 | Event 是跨页面、跨账号的共享根对象；事实、证据、热度和风险独立表达。 | 用户确认 | 任务、活动建议和结果均回溯到 Event。 |
| D-03 | 重点主题是语义聚合入口，不是 Event；具体趋势项命中规则后才形成 Candidate Event。 | HTML 原型终稿 v13 | 避免宽泛主题被误写成具体事实或响应对象。 |
| D-04 | 取消 Opportunity Card、是否参与热点决策和 Task Plan。 | 用户确认 | 已核验并命中内容规则的 Event 直接进入内容响应。 |
| D-05 | `Action Task` 的正式业务名为账号响应任务；一个承接账号/执行主体 × 一个 Event 是最小响应单元。 | HTML 原型终稿 v13、用户确认 | 同 Event 多账号独立生成候选、选择、发布与回填；候选不能跨账号互换。 |
| D-06 | 普通热点内容在完成地区来源聚合并命中规则后自动进入内容响应；重点领域关键词进入热搜即触发，普通主题首次排名 1—5 或相邻成功小时快照上升至少 10 位触发。 | 用户确认 | 来源冲突保留为上下文，不阻断普通候选生成，也不自动写成确认事实。 |
| D-07 | X 热搜每小时采集；成功采集时间用于计算采集、聚合、生成、选择与回填的实际耗时。 | 用户确认 | Phase 0 建立耗时基线，不以外部热搜首次出现时间或固定 SLA 计。 |
| D-08 | 不设 5 分钟、15 分钟、提醒或升级的固定交付承诺；每个正常账号任务仍须生成至少 3 条预检通过的账号专属候选，并记录各阶段实际耗时。 | 用户确认 | Phase 0 用耗时分布和人工闭环率评估链路，不用固定时限判定通过。 |
| D-09 | 系统工作台是候选查看/复制、选择和 URL 回填的唯一操作面；运营在 X 平台手动发布。Telegram 暂不承担投递、审核或离线分流。 | 用户确认 | 系统不直接向任何社媒账号发布；发布与回填保留在同一任务审计中。 |
| D-10 | Future Event 可以在窗口、授权提前启动或实时 Signal 匹配时进入同一 Event；未来预热内容沿用账号响应链。 | 用户确认 | 未来事件不必等待热搜发生才可准备内容。 |
| D-11 | 取消 KOL 筛选、邀约、私信、合作与回执；活动方案只能给出 KOL 扩散资源建议。 | 用户确认 | 移除 KOL 实体、工作流和连接器。 |
| D-12 | 私域保留为未来话题讨论建议能力；当前不做触达、发送、审批或回执。 | 用户确认 | 私域不进入 Phase 0 或活动方案执行链。 |
| D-13 | Future Event/关联 Event 可获得活动准备推荐；运营主动点击后才生成 3 套活动方案草稿。 | 用户确认与原型 | 推荐不等于是否参与或自动立项，不阻塞内容响应。 |
| D-14 | 活动准备首版优先处理关联 Future Event 的 Event；活动策划依据确认度、受众、窗口、价值、风险与资源。 | 模块图 V3、用户确认 | M3 是活动策划而非机会决策模块。 |
| D-15 | 热点内容是独立入口：热搜榜回答什么选题火，热点内容回答什么具体内容火、为何火和什么可复刻。 | 用户确认 | M1 增加热点内容/爆款拆解能力，不将内容样本混为 Topic/Event。 |
| D-16 | Content Insight 是具体内容的爆款拆解及可复刻要素对象；可被 M4 引用为灵感，但不替代事实核验、账号 Skill 或风险规则。 | 用户确认 | 形成内容洞察实体、引用关系和复刻边界。 |
| D-17 | 模块图 V3 为当前模块能力权威：M1 热点发现、M2 事件智能、M3 活动策划、M4 内容响应、M5 效果与学习。 | 最新架构图 V3 | Event Card 同时向 M3、M4 分流；两条支线可并行。 |
| D-18 | 产品核心价值是更快响应与更优质内容，而非全渠道增长行动编排。 | 用户确认 | 成功指标加入内容洞察覆盖/采用和账号内容表现改善。 |
| D-19 | 高风险内容不默认通过；热度/热点内容表现不替代事实、风险或人工高风险审核。 | 用户确认 | 保持自动化边界。 |
| D-20 | 配置修改先保存草稿，发布前展示影响范围；历史对象保留生效版本。 | HTML 原型终稿 v13 | 避免规则变化静默改写历史。 |
| D-21 | 当前 PRD 为 v2.8 独立草案，不覆盖 v2.5、v2.6、v2.7 或原 `prd/`。 | 用户明确要求 | 可与旧版并行评审。 |
| D-22 | Product Brief 已升级为 v1.5，对齐当前“热点发现与内容生产支持”的产品定位、M1—M5 边界和 Phase 0 三账号并行工作台闭环。 | 本次同步 | Brief 与当前 PRD 使用同一能力边界；旧 v1.4 表述不再作为基线。 |
| D-23 | 概念领域图升级为 v12，以 E01—E17 表达顶层实体、关系基数、Event Card 读模型和 M3/M4 并行分流。 | 本次同步 | 领域语义、FR 与后续 UX/架构须依据 v12 继续收敛。 |
| D-24 | 热点内容的“复刻”只允许复刻方法/结构，不复制原文、素材、未经授权资产或未经核验事实。 | 用户意图与产品风险边界 | 内容洞察、生成和审核均须保留来源与复刻边界。 |
| D-25 | Phase 0 对三个预配置 Predx X 账号分别匹配；账号或 Content Skill 不可用时仅该账号任务标记异常，不生成替代任务，也不阻塞其他账号。 | 用户确认 | 每个合格 Event 对每个预配置账号各产生 0 或 1 个 Phase 0 账号响应任务。 |
| D-26 | Phase 0 合格热搜进入详情后，每个出现地区采集快照前三条推文；跨地区 Event 对每个出现地区分别采集并保留地区、排名、时间和链接。 | 用户确认 | 地区来源聚合替代最低可信度门槛；冲突显示但不阻断普通候选生成。 |
| D-27 | 当前正式 HTML 原型使用“运营排期”“事件管理”“内容发布”作为运营页面名称；它们分别承载 Future Event、Event Intelligence 与 Content Response。 | HTML 原型终稿 v13 | 页面命名不改变 M1—M5 模块边界；PRD、原型与后续 UX 使用同一术语。 |

## 9.5 门禁结论

本 PRD 已对齐 Brief v1.5、模块图 V3 与概念图 v12，并新增“热点内容 → 爆款拆解 → Content Insight → 内容生成引用”的完整产品语义。

**门禁状态：可进入 UX/UI 与实施评审；当前 PRD 仍为对齐草案。** OQ-03 是预留窗口，不构成阻塞；OQ-04—OQ-06 分别在内容洞察引用、活动策划和效果评估能力单独实施前收口。当前 PRD 不覆盖此前版本。
