| ID | 决策 | 依据 | 影响 |

| D-02 | Event 是跨团队共享业务对象。 | Brief 与产品架构图 | 全部模块以统一事件链作为追溯主线。 |

| D-06 | Event Card 支持版本、置信度、人工校正、关闭和再激活。 | 产品架构图 | M2 要支持持续演化而非一次性归档。 |

| D-08 | PRD 按 `GUIDE.md` 采用分章节 Markdown 文档集。 | 用户指定 GUIDE.md | `prd-00-index.md` 为唯一入口；旧版单文件仅归档。 |
| D-09 | PRD 使用概念领域模型统一描述业务实体。 | GUIDE.md 最新规范 | 领域实体成为 UX/UI、架构和 Story 的共同业务语义输入。 |

| D-11 | Telegram 是可替换连接器，并区分内部审核目标与外部运营目标。 | 用户确认 | Phase 0 中 Bot 仅向管理员批准的审核目标投递可审核社媒内容草稿，不直接发送到社媒特定账号；系统内部是权威来源，Google Docs 可作协作出口。 |
| D-12 | KOL 合作以可解释性价比筛选和获批首封自动私信为首版边界。 | UX grilling 共识 | 首个平台为 X；后续回复由 AI 辅助但人工确认；拒绝/退订/异常自动停止。 |
| D-13 | 概念领域模型以 v7 为基线：Fact 与 Evidence 为独立实体，Event Card 是引用和呈现它们的有版本档案；CE-11 仅保留交付物草稿父实体，四类草稿为其类型。 | 用户确认与 `hotspot-monitor-conceptual-domain-model-v7.svg` | 清除独立“实体关系”实体，明确 Event 的跨模块根上下文与 Strategy Recommendation 的受控反馈范围。 |
| D-14 | Phase 0 热搜按小时采集；重点领域关键词进入热搜即触发，普通主题以首次排名 1—5 或相邻成功小时快照上升至少 10 位触发。 | 用户确认 | 触发阈值可实现、可复核；重点领域可使用较低热度门槛。 |
| D-15 | Phase 0 的合格普通内容事件按内容参与策略自动进入内容行动；从成功采集首次记录合格触发起，5 分钟内投递至少 3 条规则预检通过的普通社媒候选；内容运营投递后 15 分钟内选择、人工发布并回填链接。 | 用户确认 | 普通内容不等待人工 M3/M4 决策，以系统生成与预检为主；10 分钟提醒，15 分钟升级；高风险内容不默认通过且不自动发布。 |
| D-16 | Future Event 可由前/中/后窗口自动启动、授权用户手动提前启动或实时 Signal 匹配并行触发，并汇入同一 Event。 | 用户确认与产品架构图 | 未来准备不等待热搜匹配；后续触发更新既有 Event，不重复创建下游行动。 |
| D-17 | Task Plan 与跨渠道行动选项由系统生成；普通社媒内容默认生成，私域、活动和 KOL 采用推荐后人工选择推进/拒绝或按需生成。 | 用户确认与产品架构图 | 小周是选择和例外修改的门禁人，小陈负责普通内容的选择、发布与链接回填；人默认不从零创作方案。 |

## 9.5 门禁结论

本 PRD 已依据已确认的 Product Brief v1.4、终版产品架构图和 GUIDE.md 定义全局产品愿景、用户旅程、M1–M5 能力、概念领域模型、带稳定编号的功能需求、规则、NFR、指标及 Phase 0 验证切片。M4 与终版图一致包含内容发布、营销活动、私域触达和 KOL 合作；各行动采用明确的人工门禁与差异化执行方式。

**门禁状态：通过，可进入 UX/UI 设计。** 上游方向与完整产品架构已确认；Phase 0 范围、响应窗口治理、端到端时效、Action Task 状态机与具名用户情境均已按确认结论对齐。OQ-01—OQ-03 为后续扩展问题，不阻塞当前 UX/UI。
