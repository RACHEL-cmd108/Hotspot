# 07 非功能需求

产品容量与集成规模由后续架构阶段确认；以下阈值是设计与验收基线，不规定实现方案。

| ID | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-01 | 工作台可用性 | 工作台必须以文字/图标而非仅颜色呈现待办、窗口、风险和异常；授权用户可在两次操作内进入相关对象。 | 以 UJ-1、UJ-3、UJ-4 代表任务测试，100% 样本满足。 |
| NFR-02 | 性能 | `[ASSUMPTION]` 在确认的首个生产容量下，工作台、Event Card、Opportunity Card 的 95% 请求在 3 秒内完成首次可操作呈现。 | 使用代表性容量数据集连续测试不少于 20 次，P95 ≤ 3 秒。 |
| NFR-03 | 可靠性与可恢复性 | 单个数据源、执行系统或结果源故障时，已成功数据保留；故障、重试状态和人工接管入口对用户可见。 | 对每类依赖模拟失败，成功数据丢失数为 0，且每次均可见处置入口。 |
| NFR-04 | 审计完整性 | 事实、决策、审核、授权、任务分发、回执与结果不得被静默改写或删除。 | 抽样完整主链，关键审计字段完整率为 100%。 |
| NFR-05 | 安全与隐私 | 页面、导出、审计和异常信息不得暴露第三方密钥、令牌或密码；敏感字段按角色展示。 | 核心流程、导出和异常样本检查，敏感凭据暴露数为 0。 |
| NFR-06 | 兼容性与可访问性 | 支持当前主流 Chrome、Safari、Edge 桌面端；关键结构与状态可被辅助技术解读。 | 三类浏览器完成 UJ-1—UJ-4 核心任务无阻塞缺陷；键盘可达率 100%。 |
| NFR-07 | 数据时效与口径 | Signal、Event 更新、外部回执和 Outcome 必须展示最近更新时间、来源和口径；不同口径的数据不得无提示合并。 | 对每类对象抽样，时间、来源和口径字段完整率为 100%。 |
| NFR-08 | 服务可用性 | `[ASSUMPTION]` 已发布的首个生产版本，热点运营工作台和已交接 Action Task 的月度可用性应不低于 99.5%（计划维护窗口除外）。 | 按月统计可用时长 / 总服务时长，结果 ≥ 99.5%；计划维护须提前记录。 |
| NFR-09 | 故障恢复 | `[ASSUMPTION]` 核心 Event、Opportunity、Task Plan、Action Task 与审计记录发生服务故障后，恢复时间目标（RTO）≤ 4 小时，数据恢复点目标（RPO）≤ 1 小时。 | 在首个生产容量的恢复演练中，记录并验证 RTO、RPO 分别不超过阈值。 |
| NFR-10 | 隐私最小化与受控导出 | 系统仅收集完成事件运营所需的业务数据；导出含敏感业务数据时必须记录导出者、时间、对象范围和用途。 | 抽样全部敏感数据导出，审计字段完整率为 100%；不必要数据字段的采集数为 0。 |
| NFR-11 | Phase 0 内容响应时效 | 对每次成功小时采集首次记录到合格触发的普通内容事件，系统须在 5 分钟内向批准 Telegram 审核目标投递至少 3 条通过规则预检的社媒内容候选。 | 在验收环境中覆盖重点领域关键词、普通主题排名 1—5、普通主题排名上升三类触发条件逐项验证；每个合格样本的 `T0 → 投递完成` 耗时均 ≤ 5 分钟。 |
