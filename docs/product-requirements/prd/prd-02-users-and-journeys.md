# 02 用户与旅程

## 2.1 目标用户与 JTBD

| 用户 | 核心任务 | 预期结果 |
|---|---|---|
| 增长负责人 | 判断价值、协调资源和目标优先级 | 高价值机会获得恰当投入和可解释结果 |
| 热点/研究运营 | 发现信号、核验事实、跟踪事件变化 | 更早形成可信、共享的 Event |
| 内容运营（第一优先） | 基于事实和风险边界形成内容行动 | 更快得到可审核、可修订的内容草稿 |
| 产品运营 | 设计事件与产品承接路径 | 事件注意力转化为产品参与与用户价值 |
| 渠道运营 | 选择渠道、时机和分发动作 | 触达效率与事件窗口匹配 |
| 品牌/风控 | 审核高风险事件与行动 | 风险边界被执行且可审计 |
| 数据团队 | 连接结果、成本与复盘 | 事件到结果的证据可复用 |

- **JTBD-1 共享事件上下文：**当外部或内部变化出现时，我要查看可信且持续更新的 Event，以避免团队重复查证。
- **JTBD-2 做出机会决策：**当 Event 可被理解时，我要判断是否参与、面向谁、如何承接和投入多少，以避免无价值或高风险追逐。
- **JTBD-3 协同执行：**当决策完成时，我要将上下文发送为各专业系统可执行的任务，并看见审核、进度和异常。
- **JTBD-4 证明并复用结果：**当行动结束时，我要理解传播、产品和成本结果，以优化下一轮判断和行动。

## 2.2 用户旅程

### UJ-1 突发热点发现与候选形成

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 热点/研究运营从实时雷达、监控提醒或内部人工录入进入。 |
| 主流程 | 查看新 Signal → 处理重复与异常 → 将突发信号形成 Candidate Event → 交由 M2 核验。 |
| 价值结果 | 重要信号可追溯地进入共享事件链，无效或重复信号有处置原因。 |
| 分支与异常 | 数据源缺失、提醒失败或疑似重复时，显示影响并生成待处理项；不得静默丢弃。 |

### UJ-2 未来事件准备与候选匹配

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 热点、增长、内容或产品运营创建/导入未来事件，或预设窗口到达。 |
| 主流程 | 定义日期、范围和预案 → 设定监测条件 → 独立触发或与实时 Signal 匹配 → 进入 Candidate Event。 |
| 价值结果 | 团队可从被动追踪转为提前准备；预案在实时事实和风险核验后才可激活。 |
| 分支与异常 | 未来事件取消、改期或匹配不足时保留原因并重新排程，不自动进入行动。 |

### UJ-3 事件理解与机会决策

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 热点/研究运营、增长负责人或指定业务所有者打开待理解 Event。 |
| 主流程 | 聚合并核验事实 → 维护 Event Card 和生命周期 → 分析平台/受众机会 → 评估价值、风险与资源 → 作出四档机会决策。 |
| 价值结果 | 形成可追溯的 Opportunity Card，并明确优先参与、参与、观察或不参与的原因。 |
| 分支与异常 | 证据不足保持待核验；观察事件带重新评估时间并回流监测；不参与记录原因后进入复盘。 |

### UJ-4 跨团队行动与执行协同

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 增长负责人、内容、产品或渠道运营处理已决定参与的 Opportunity Card。 |
| 主流程 | 草拟并选定跨渠道 Task Plan，明确各渠道参与/不参与及其作用边界 → 为需要响应的渠道生成对应交付物草稿并预检 → 按类型人工审核/修订 → 基于可交接草稿创建渠道级 Action Task，分配责任人与依赖并执行/交接 → 跟踪 Task Receipt 和异常。 |
| 价值结果 | 每个参与决定都有责任人、目标、受众、窗口、风险约束、审核结论和交接状态。 |
| 分支与异常 | 审核驳回或需修改时回到草稿修订；社媒内容等待人工发布，私域触达草稿按获批目标和渠道规则交接，活动方案由负责人实施，KOL 首封按批准批次发送；回执延迟、失败、拒绝/退订或冲突在工作台显示并可人工接管。Phase 0 中，Telegram Bot 仅向已批准审核目标投递可审核社媒内容草稿，不构成社媒发布。 |

### UJ-5 结果学习与策略反馈

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 数据团队、增长负责人或行动责任人在执行完成、关闭或异常后进入。 |
| 主流程 | 汇总执行回报 → 记录传播、产品和成本结果 → 标注归因置信度 → 复盘 → 提出策略优化建议 → 经批准反馈 Monitoring Scope、Opportunity Card 判断策略与 Task Plan 模板。 |
| 价值结果 | 团队获得可复用的事件类型、受众、渠道、行动与结果模式。 |
| 分支与异常 | 结果数据缺失或口径冲突时标记缺口，不得作出完整或精确归因结论。 |
