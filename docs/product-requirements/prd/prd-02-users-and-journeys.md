# 02 用户与旅程

## 2.1 目标用户与 JTBD

| 用户 | 核心任务 | 预期结果 |
|---|---|---|
| 增长负责人 | 判断价值、协调资源和目标优先级 | 高价值机会获得恰当投入和可解释结果 |
| 热点/研究运营 | 发现信号、核验事实、跟踪事件变化 | 更早形成可信、共享的 Event |
| 内容运营（第一优先） | 基于事实和风险边界形成内容行动 | 更快得到可审核、可修订的内容草稿 |
| 产品运营 | 设计事件与产品承接路径 | 事件注意力转化为产品参与与用户价值 |
| 渠道运营 | 选择渠道、时机和分发动作 | 触达效率与事件窗口匹配 |
| 品牌/风控 | 审核高风险事件与行动 | 风险边界被执行且可审计 |
| 数据团队 | 连接结果、成本与复盘 | 事件到结果的证据可复用 |

- **JTBD-1 共享事件上下文：**当外部或内部变化出现时，我要查看可信且持续更新的 Event，以避免团队重复查证。
- **JTBD-2 做出机会决策：**当 Event 可被理解时，我要判断是否参与、面向谁、如何承接和投入多少，以避免无价值或高风险追逐。
- **JTBD-3 协同执行：**当决策完成时，我要将上下文发送为各专业系统可执行的任务，并看见审核、进度和异常。
- **JTBD-4 证明并复用结果：**当行动结束时，我要理解传播、产品和成本结果，以优化下一轮判断和行动。

## 2.2 用户旅程

### UJ-1 突发热点发现与候选形成

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小林（热点/研究运营）维护重点领域、关键词与阈值；系统按小时采集热搜，小林在数据源异常、重复事件或需校正时进入。 |
| 主流程 | 系统采集新 Signal → 按监测范围自动判定触发 → 形成或更新 Candidate Event → 小林仅处理重复、异常与校正 → 交由 M2 核验。 |
| 价值结果 | 重要信号可追溯地进入共享事件链，无效或重复信号有处置原因。 |
| 分支与异常 | 数据源缺失、提醒失败或疑似重复时，显示影响并生成待处理项；不得静默丢弃。 |

### UJ-2 未来事件准备与候选匹配

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小林（热点/研究运营）或获授权业务人员创建/导入未来事件；预设的发生前、发生中或结果期窗口到达，或用户决定提前准备时进入。 |
| 主流程 | 定义日期、范围和预案 → 配置前/中/后窗口 → 系统在窗口到达时自动启动，或授权用户手动提前启动，或实时 Signal 匹配后启动 → 汇入同一 Event/Event Card 并向后续模块提供准备上下文。 |
| 价值结果 | 团队可从被动追踪转为提前准备；未来事件不必等待热搜匹配才可开始生成相应时期的方案或草稿。 |
| 分支与异常 | 未来事件取消、改期或匹配不足时保留原因并重新排程；后续触发更新既有 Event，不重复创建下游行动。 |

### UJ-3 事件理解与机会决策

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小周（增长负责人）与热点/研究运营打开待理解 Event；小周需要在窗口和资源约束下决定是否参与。 |
| 主流程 | 聚合并核验事实 → 维护 Event Card 和生命周期 → 分析平台/受众机会 → 评估价值、风险与资源 → 作出四档机会决策。 |
| 价值结果 | 形成可追溯的 Opportunity Card，并明确优先参与、参与、观察或不参与的原因。 |
| 分支与异常 | 证据不足保持待核验；观察事件带重新评估时间并回流监测；不参与记录原因后进入复盘。 |

### UJ-4 跨团队行动与执行协同

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小周（增长负责人）处理已决定参与的 Opportunity Card；小陈（内容运营）承接已投递的普通社媒内容候选。 |
| 主流程 | 系统自动生成跨渠道 Task Plan 与行动选项 → 小周选择推进、拒绝或在必要时要求修改各渠道动作 → 合格内容事件默认生成至少 3 条普通社媒内容候选；私域、活动和 KOL 仅在小周选定建议或主动请求时生成草稿 → 草稿通过适用预检与审核 → 基于可交接草稿创建渠道级 Action Task 并跟踪 Task Receipt。Phase 0 中，小陈在 Telegram 收到 3 条已通过规则预检的候选后，选择一条人工发布并回填发布链接。 |
| 价值结果 | 人只做选择、例外审核与发布，而非从零创造默认方案；每个参与决定都有责任人、目标、窗口、风险约束、选择/审核结论和交接状态。 |
| 分支与异常 | 高风险内容先进入品牌/风控审核，不得默认通过；小周可拒绝推荐动作或主动请求生成私域、活动或 KOL 草稿。社媒普通候选投递后 10 分钟提醒小陈，15 分钟未发布即升级给备援内容运营/负责人并记录错过窗口；系统不自动发布。回执延迟、失败、拒绝/退订或冲突在工作台显示并可人工接管。 |

### UJ-5 结果学习与策略反馈

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小王（运营策略/数据负责人）在执行完成、关闭或异常后进入，并需要判断哪些事件策略值得复用。 |
| 主流程 | 汇总执行回报与发布链接 → 记录传播、产品和成本结果 → 标注归因置信度 → 复盘 → 提出策略优化建议 → 小王确认建议后，经批准反馈 Monitoring Scope、Opportunity Card 判断策略与 Task Plan 模板。 |
| 价值结果 | 团队获得可复用的事件类型、受众、渠道、行动与结果模式。 |
| 分支与异常 | 结果数据缺失或口径冲突时标记缺口，不得作出完整或精确归因结论。 |
