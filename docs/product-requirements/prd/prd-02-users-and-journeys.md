# 02 用户与旅程

## 2.1 目标用户与 JTBD

| 用户 | 核心任务 | 预期结果 |
|---|---|---|
| 内容运营（第一优先） | 发现热点和热点内容；为所承接账号选择、调整并发布内容 | 更快获得可信、账号专属且有爆款灵感支撑的候选 |
| 热点/研究运营 | 配置发现范围、核验事件、管理异常 | 重要热点稳定进入响应链，错误信息不进入发布链 |
| 运营负责人 | 维护监测、响应、账号/Skill、风险与活动建议规则；复盘效果 | 响应速度与内容质量能够持续优化 |
| 活动运营 | 对具备条件的 Event 判断是否启动活动准备 | 快速获得可选择、可调整的三套活动方案草稿 |

- **JTBD-1 找到正在发生的机会：**当我查看热搜和热点内容时，我要区分正在火的选题与正在成功传播的具体内容，避免只凭直觉找灵感。
- **JTBD-2 快速发布：**当热点进入关注范围且事实可核验时，我要立即获得我负责账号的可发布候选，以赶上流量窗口。
- **JTBD-3 复刻有效内容：**当我需要写内容时，我要看见爆款内容的可复刻结构与适用边界，以提高候选质量而不是机械抄写。
- **JTBD-4 提前准备活动：**当未来事件具备活动准备条件时，我要理解系统建议的原因，并在需要时启动三套方案草拟。
- **JTBD-5 让下一次更好：**当内容发布、活动采用或链路异常后，我要看到结果与原因，以调整规则和素材策略。

## 2.2 用户旅程

### UJ-1 热点与热点内容发现

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小林（热点/研究运营）或小陈（内容运营）进入热点发现；系统按小时采集热搜、持续汇集热点内容。 |
| 主流程 | 用户在“热搜榜/重点主题”查看什么选题或话题正在上升 → 在“热点内容”查看具体内容样本、账号、内容形态和互动线索 → 可进入内容详情进行爆款拆解，保存可复刻要素或引用为灵感。 |
| 价值结果 | 热搜 Topic 与具体 Content 明确分离：前者用于选题判断，后者用于内容灵感与复刻学习。热点内容不因热度自动被视为事实或 Event。 |
| 分支与异常 | 内容来源、互动数据、发布时间或授权状态缺失时明确标注；无法验证的内容样本不能被标注为可复刻结论。 |

### UJ-2 候选形成、事件核验与持续监测

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小林维护重点主题、关键词、地区和触发规则；新 Signal、Future Event 窗口或两者匹配时进入。 |
| 主流程 | 系统依据触发规则形成/归并 Candidate Event → 对合格热搜的每个出现地区采集详情快照前三条推文 → 按地区聚合来源、形成或更新 Event 与 Event Card → 持续监测新来源、热度、生命周期和窗口变化。 |
| 价值结果 | 响应前具有可追溯来源、地区、快照和事实状态；Future Event 与实时热点可以汇入同一 Event。 |
| 分支与异常 | 来源缺失、重复或冲突时保留原因和状态；冲突不阻断候选生成，但不得被静默写成已确认事实。 |

### UJ-3 Event 的账号内容响应

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小陈负责一个或多个承接账号；已核验 Event 命中生效内容响应规则，或 Future Event 进入内容预热窗口时进入。 |
| 主流程 | 系统从 Event Card、响应规则、Predx X 主账号与 Content Skill 匹配上下文，并可引用适用 Content Insight → 创建一个账号响应任务 → 生成至少 3 条账号专属候选并规则预检 → 小陈在系统工作台直接查看/复制候选、选择一条、必要时调整、在 X 手动发布并回填链接。 |
| 价值结果 | 每个 Event 的 Phase 0 内容响应都有唯一账号任务、候选、选择和发布回填；热点内容洞察帮助生成更适配、而非照搬的候选。 |
| 分支与异常 | 账号/Skill 缺失、生成失败或风险升级时任务进入异常；来源冲突可见但不阻断候选生成；不得自动向 X 发布。系统记录各阶段实际耗时，不以固定 SLA 关闭任务。 |

### UJ-4 Event 的活动策划

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小周（活动运营或运营负责人）在 Event Card 查看活动准备上下文；首版优先处理关联 Future Event 且命中活动建议规则的 Event。 |
| 主流程 | 系统依据 Event Card 的确认度、受众匹配、窗口、目标价值、风险与资源可行性生成活动准备建议及依据 → 小周决定是否点击启动 → 系统生成 3 个营销活动方案草稿 → 小周选择、调整、导出或交接给外部活动团队。 |
| 价值结果 | 系统帮助提前策划但不替代“是否追热点”的决策、活动立项或实际执行；活动策划可与内容响应并行，且不阻塞其时效。 |
| 分支与异常 | 未确认日期/事实或资源条件不满足时，只显示观察或限制原因；用户不点击不生成方案。KOL 仅可作为资源建议写入方案，不能创建 KOL 任务。 |

### UJ-5 效果学习与规则优化

| 项目 | 内容 |
|---|---|
| 角色与进入条件 | 小王（运营负责人）在内容任务完成、活动方案被采用/忽略、窗口错过或异常后进入。 |
| 主流程 | 汇总发布链接、内容基础表现、账号表现、热点内容洞察的引用/采用及异常原因 → 比较不同 Event、账号、Skill、内容洞察和触发来源 → 形成策略优化建议 → 经批准后更新配置。 |
| 价值结果 | 团队把“更快”和“更好”的结果沉淀为监测、响应、账号/Skill、爆款拆解和活动建议规则。 |
| 分支与异常 | 指标缺失、追踪失败或样本不足明确标注；不得将相关性表述为因果，也不得自动覆盖生产规则。 |
