# 06 业务与数据规则

实体定义、关联和生命周期请参见 [概念领域模型](./prd-05-conceptual-domain-model.md)。本章仅定义这些实体在业务流程中的治理和约束。

## 6.1 共享对象与数据要求

1. 所有后续对象必须能追溯到上一个主链对象；Action Package 必须关联唯一 Opportunity Card，Opportunity Card 必须关联 Event Card。
2. Event、Opportunity、Action Package、审核、授权、回执、结果和策略建议的关键变更必须记录操作人、时间、原值、新值和原因。
3. 事实真实性、事件热度、增长价值、品牌风险和归因置信度为独立字段，不能相互推定。
4. Source Evidence 至少包含来源、采集/观察时间、可信等级、适用事实及可访问引用；无法复核的输入标记为待确认或不可用。
5. Event Card 的版本仅在事实边界、关键证据、风险、生命周期或窗口发生实质改变时产生；版本不覆盖历史审计记录。

## 6.2 事实、热度与风险治理

1. 官方或一手来源可支持事实，但高风险行动仍需要人工核验。
2. 非官方事实至少需要两个相互独立的可靠来源交叉确认；单一非官方来源保持“待确认”。
3. 观点、预测、传闻和系统推断必须标明性质，不得作为已确认事实进入可发布或高风险行动。
4. 热度可由跨来源讨论、传播速度、跨地区出现和持续时间判断；热度不能替代事实真实性或业务价值。
5. 品牌、法律、平台政策或用户安全的高风险标记必须从 Event Card 传递至 Opportunity Card 和 Action Package。

## 6.3 状态规则

| 对象 | 状态与流转 | 规则 |
|---|---|---|
| Candidate Event | 新建 → 待形成 → 已形成 / 已忽略 / 已合并 | 忽略和合并必须保留原因与原始 Signal。 |
| Event | 待核验 → 监测中 / 待决策 → 已关闭；监测中可再激活 | 证据不足进入监测中；重新活跃、事实更新或窗口变化可再激活。 |
| Opportunity | 待评估 → 优先参与 / 参与 / 观察 / 不参与 | 观察需重新评估时间；不参与记录原因；前两档才可创建行动。 |
| Action Package | 行动设计 → 待审核 → 待修改 / 已授权 / 已取消 → 执行中 → 已完成 / 执行异常 | 需要授权的任务未授权不得分发；异常必须可见、可分派和可关闭。 |
| Strategy Recommendation | 草拟 → 待批准 → 已批准 / 已拒绝 / 已归档 | 已批准建议必须注明回写范围；不得自动覆盖既有规则。 |

## 6.4 权限与决策权

| 业务动作 | 默认角色 | 规则 |
|---|---|---|
| 监测范围、Candidate Event 与 Event 校正 | 热点/研究运营 | 可维护事实和关系，但不具备高风险行动授权权。 |
| 机会价值、资源和参与决策 | 增长负责人、指定业务所有者 | 覆盖系统建议必须记录依据和原因。 |
| 高风险行动审核 | 品牌/风控和指定审核者 | 未授权动作不得分发给执行系统。 |
| 执行回报、结果和复盘录入 | 行动责任人、数据团队 | 估算、缺失和异常结果必须标注口径。 |
| 共享业务字典管理 | 指定字典管理员 | 修改应评估生效范围；历史记录不被改写。 |

## 6.5 外部依赖与约束

- 多源外部数据需具备合规接入、可持续成本和可识别的来源状态。
- 专业执行系统需接受已授权 Action Package，并回传进度、异常、完成和结果；回传失败不应删除原任务或已成功数据。
- 产品、渠道和业务结果连接依赖统一事件标识、行动标识和预先确认的指标口径。
- 外部数据或回执存在延迟、缺失、冲突时，系统显示数据状态和人工处理入口，而非隐式覆盖。
