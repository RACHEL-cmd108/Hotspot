# 04 功能需求

每条需求均为业务能力要求；技术实现由后续系统架构定义。除另有说明外，关键创建、变更、覆盖和关闭动作必须记录操作人、时间、原因与适用规则版本。

## 4.1 M1 热点发现

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-01 热点雷达与热搜榜 | UJ-1、UJ-2 | 热点/研究运营、内容运营；计划采集、手动刷新或查看热点雷达时 | 展示已接入来源的趋势项、地区、排名变化、热度、采集时间、来源状态与新鲜度。趋势项不是事实，也不因展示而自动成为 Event。Phase 0 对 X 热搜每小时计划采集一次。 | 可按地区与快照筛选；缺失、延迟或异常来源明确标记；成功采集时间可追溯。 |
| FR-02 重点主题与跨区聚合 | UJ-1、UJ-2 | 热点/研究运营；配置主题或查看聚合时 | 将语义相近的趋势项归入重点主题，展示具体上升话题、地区扩散和热度变化。重点主题是聚合入口，不是 Event；只有具体条目命中触发规则后才形成/归并 Candidate Event。 | 可查看主题内具体条目及其 Event 状态；不会把宽泛主题直接创建为 Event。 |
| FR-03 热点内容入口（预留） | UJ-1 | 内容运营、热点/研究运营；查看热点内容入口时 | 在 M1 中保留与热搜榜可见区分的“热点内容”入口及其概念边界；它不等于 Topic 或 Event，也不自动形成 Candidate Event。当前不规定数据接入、样本采集或展示行为。 | 当前页面明确标识为后续能力；不以模拟样本或未定义数据冒充已启用功能。 |
| FR-04 爆款拆解与 Content Insight（预留） | UJ-1、UJ-3、UJ-5 | 内容运营、系统；后续能力经单独立项启用时 | 预留 Content Insight 作为热点具体内容的爆款拆解及内容生成上下文对象；当前只定义其不复制原文、素材、未经授权资产或未经核验事实的边界。 | 在未定义首批来源、爆款判定和最小字段前，不生成或验收 Content Insight。 |
| FR-05 Future Event 与运营排期 | UJ-2、UJ-4 | 热点、内容或活动运营；创建、导入、更新或查看日历时 | 维护未来事件的日期/范围、类别、来源、证据/确认状态、重要性、监测范围、响应窗口与负责人。未确认日期或事件不得作为确定事实写入内容/活动方案。 | 改期、取消、来源和确认度变化可追溯；日历可按类别、来源、确认状态与准备状态筛选。 |
| FR-06 信号生成与事件触发 | UJ-2 | 系统、授权用户；新 Signal、Future Event 窗口、手动启动或二者匹配时 | 支持实时热点独立、Future Event 窗口/人工提前启动、Future Event × 实时热点匹配三类触发。Phase 0 中，重点领域关键词进入热搜即触发；普通主题首次排名 1—5，或相邻成功小时快照上升至少 10 位时触发。 | Candidate Event 标明触发路径、输入引用和规则版本；后续触发更新既有 Event，不重复创建下游任务。 |

## 4.2 M2 事件智能

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-07 Candidate Event 形成与地区来源聚合 | UJ-2 | 系统、热点/研究运营；触发规则命中或人工录入时 | 将 Signal/Future Event 形成、去重、合并、拆分或忽略为 Candidate Event。系统可对高置信度合并自动执行；拆分始终由授权人员确认。Phase 0 中，合格热搜进入详情后，每个出现地区采集该快照前三条推文，并按地区、排名、时间和原始链接聚合为 Event 输入。 | 合并、拆分与忽略保留原始输入、原因、责任人/系统决策、置信度与依据；单地区合格热搜有 3 条来源记录，跨地区 Event 的每个出现地区均有 3 条来源记录或明确采集异常。 |
| FR-08 Event 来源状态、事实与证据 | UJ-2、UJ-3 | 热点/研究运营、内容运营；候选进入处理或出现新材料时 | 将 Candidate Event 形成 Event；维护 Fact、Evidence、来源一致/冲突/未知状态、风险和可公开表达边界。来源冲突不阻断内容候选生成，但不得被自动表述为确认事实。 | 每个 Event 可查看按地区聚合的 Evidence；候选引用的事实显示来源状态；人工校正不被自动推断覆盖。 |
| FR-09 有版本 Event Card | UJ-2—UJ-4 | 系统或授权用户；Event 首次形成或发生实质变化时 | 将 Event 边界、事实、证据、热度、风险、窗口、关联热点内容和响应状态汇集呈现为有版本档案。它不是 Opportunity Card，也不要求“是否参与”决策。 | 可查看版本、依据、关联内容洞察和下游活动/内容状态；未完成字段不默认已确认。 |
| FR-10 事件监测与演化 | UJ-2、UJ-5 | 系统或热点/研究运营；热度变化、窗口到期或重新活跃时 | 观察新事实、热度、生命周期和跨区变化；依据生效规则或有依据的人工操作更新窗口、关闭或再激活 Event。 | 关闭 Event 可再激活；状态调整保留依据，热度观察本身不静默改变事实或窗口。 |
| FR-11 Event 形成后内容响应分流 | UJ-3 | 系统；Event 完成来源聚合并命中生效内容响应规则时 | 从 Event Card 直接匹配可用承接账号并创建内容响应任务；不创建 Opportunity Card、不等待“是否参与”选择，也不生成 Task Plan。来源冲突作为任务上下文保留，但不是普通候选生成门禁；活动策划可以同时收到 Event Card 上下文，也不是 M4 的门禁。 | 自动响应可追溯 Event、来源状态、规则与账号匹配版本；账号或 Skill 不可用时显示阻塞原因。 |

## 4.3 M3 活动策划

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-12 受众匹配 | UJ-4 | 系统、活动运营；Event Card 可供活动策划分析时 | 基于目标受众、覆盖范围、进入窗口和生效受众定义形成活动策划上下文。首版优先处理关联 Future Event 的 Event。 | 每项匹配可追溯 Event Card、受众口径与数据来源；推断必须明确标记。 |
| FR-13 活动准备综合评估与推荐 | UJ-4 | 系统；Event Card 具备活动策划所需上下文时 | 评估确认度、目标价值、风险、资源可行性、受众匹配和窗口，生成“建议做活动准备”及原因。推荐不是是否参与热点的决策，不自动立项或阻塞内容响应。 | 推荐可追溯 Event Card、活动建议规则和依据；不满足规则时显示不建议/限制原因。 |
| FR-14 三套活动方案草稿 | UJ-4 | 活动运营；主动点击“生成活动方案”时 | 只在用户主动启动后，为该 Event 生成 3 套 Campaign Proposal Drafts。每套至少包含目标、受众、窗口、传播主题、机制/玩法、资源、风险边界与外部执行前提；可包含 KOL 扩散资源建议，但不创建 KOL 对象或任务。 | 三个候选可区分、比较并回溯 Event Card 和确认度；不点击不生成活动方案。 |
| FR-15 活动方案选择、修订与外部交接 | UJ-4 | 活动运营；方案生成后 | 支持选择、调整、生成新版本、导出或交接外部活动团队；不创建预算、落地页、投放、上线或活动执行任务。 | 选择/调整/交接可审计；外部交接不被推定为活动已执行。 |

## 4.4 M4 内容响应

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-16 承接账号与 Content Skill 管理 | UJ-3、UJ-5 | 字典管理员、运营负责人；新增账号、调整边界或生成任务前 | 维护账号身份、平台、角色、可用状态和风险限制及其 Content Skill（表达角色、格式偏好、事实/风险边界）。Phase 0 配置三个 Predx X 承接账号。配置先保存草稿，发布前展示影响范围和版本差异。 | Phase 0 任务只能匹配三个已配置、可用且具备适用 Skill 的 Predx X 账号；历史任务保留当时账号/Skill 版本。 |
| FR-17 账号匹配与账号响应任务 | UJ-3 | 系统、内容运营；Event 命中内容响应规则或 Future Event 进入内容预热时 | 以 `Event × 响应规则 × 账号/Skill` 匹配上下文创建账号响应任务。Phase 0 对每个合格 Event 的三个预配置账号分别创建至多一个任务；账号或 Skill 不可用时，仅该账号任务标记异常，不生成替代任务，也不阻塞其他账号。 | 任务绑定唯一 Event 和账号；Phase 0 的每个合格 Event 对每个预配置账号各有 0 或 1 个任务，异常原因可见。 |
| FR-18 账号专属内容生成与洞察引用 | UJ-3 | 系统；普通社媒账号响应任务创建后 | 为每个任务按账号的 Content Skill 生成至少 3 条社媒候选。生成可引用适用 Content Insight 作为灵感上下文，并标记引用关系；候选必须保持账号专属，不复制热点内容原文或未经授权素材。来源冲突/未知状态作为上下文展示，不自动写成确认事实。 | 每个普通任务有至少 3 条候选或明确生成异常；每条候选可追溯账号、Skill、来源状态及采用的内容洞察。 |
| FR-19 预检、审核与修订 | UJ-3 | 系统、内容运营、品牌/风控；候选生成或调整后 | 检查事实/来源状态、禁用表达、产品资料、平台政策和风险规则。普通低风险候选可自动通过规则预检；高风险候选必须人工审核。运营可在任务边界内选择、调整或重新生成。 | 检查结果、命中规则和版本可见；高风险候选不能标记为可发布或进入发布回填。 |
| FR-20 系统内选择、人工发布与链接回填 | UJ-3 | 系统、内容运营；普通候选通过规则预检时 | 系统工作台是唯一操作面：内容运营可直接查看/复制同一账号任务的至少 3 条候选、选择一条、必要时调整，并回填实际发布 URL 或失败原因。运营在 X 平台手动发布；系统不直接向社媒账号发布，也不使用 Telegram 作为当前链路入口。 | 选择、调整和回填均关联同一任务与候选版本；无真实 URL/终止原因不得关闭任务；系统记录候选生成、选择、发布和回填时间。 |

## 4.5 M5 效果与学习

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-21 结果汇总与账号表现 | UJ-5 | 系统、内容运营；URL 回填或结果数据可获得时 | 以账号响应任务为根记录发布、基础传播、账号表现、追踪状态和异常；按 Event、账号、Skill、触发规则和引用洞察查询。 | 缺失/延迟数据单独标记；不以无数据推定表现为零或成功。 |
| FR-22 效果评估与洞察采用评估 | UJ-5 | 运营负责人；达到观察窗口或可比较样本形成时 | 比较响应时效、候选采用、账号表现、内容洞察引用/采用和活动建议采用。评估结果必须说明样本、窗口和口径。 | 可区分事实结果与推断；样本不足或口径不一致时明确显示限制。 |
| FR-23 异常与复盘 | UJ-5 | 运营负责人；任务异常、来源聚合问题、内容洞察问题或活动方案被忽略后 | 汇总采集、聚合、生成、发布、追踪和方案采用异常，以及内容调整/放弃原因。 | 每类异常有影响对象、责任人和恢复入口；复盘可回溯原任务、洞察及规则版本。 |
| FR-24 策略建议与受控回写 | UJ-5 | 运营负责人、授权策略所有者；复盘形成建议时 | 提出对监测范围、热点内容发现/拆解规则、触发规则、账号画像、Content Skill 或活动建议规则的优化建议。获批后只在明确范围内生效，不得改写历史。 | 建议关联结果/复盘证据、适用范围和批准状态；未批准建议不影响生产规则。 |
| FR-25 私域话题讨论建议（未来） | UJ-5 | 授权运营人员；未来能力启用且已核验 Event 可作为讨论输入时 | 将已核验 Event 与可用 Content Insight 转化为私域话题讨论建议；不包含发送、审批、社群管理或回执。 | 建议可回溯 Event/洞察来源；当前未启用时不在执行任务中创建占位任务。 |
