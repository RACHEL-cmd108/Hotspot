# 04 功能需求

每条需求均为业务能力要求；技术实现由后续系统架构定义。除另有说明外，所有关键创建、变更、覆盖和关闭动作必须记录操作人、时间和原因。

## 4.1 M1 热点发现

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-01 实时热点雷达 | UJ-1 | 热点/研究运营；打开监测范围或收到提醒时 | 展示已接入来源的 Signal、时间、热度变化、来源状态与新鲜度；不把 Signal 表述为事实。 | 可按范围筛选；缺失、延迟或异常来源被明确标记。 |
| FR-02 未来事件中心 | UJ-2 | 热点、增长、内容或产品运营；创建、导入或更新未来事件时 | 维护日期、地区、重要性、监测范围、预案与负责人；支持发生前、发生中和结果期。 | 改期、取消、窗口到达均保留历史并触发相应待办。 |
| FR-03 事件触发与候选匹配 | UJ-1, UJ-2 | 系统规则或人工；新 Signal、预案到期或两者满足匹配条件时 | 支持预案独立触发、突发事件独立进入、未来事件×实时 Signal 匹配三种路径。 | 每个 Candidate Event 标明触发路径、输入引用和待处理状态。 |
| FR-04 监控范围与提醒 | UJ-1, UJ-2 | 热点/研究运营；配置主题、地区、来源、阈值或处置时限时 | 创建监控对象与提醒规则，指定负责人；同一监测范围内、指向同一 Candidate Event 或 Event 且无重大事实、风险或响应窗口变化的提醒应合并处理。 | 触发后生成可追溯待办；合并后保留全部来源且不产生无归属告警；存在重大变化时生成原事件的更新提醒。 |
| FR-05 内部事件录入 | UJ-1, UJ-2 | 授权业务人员；录入产品发布、营销活动、客户或内部信号时 | 将内部输入按同一 Signal/Candidate Event 规则纳入流程，不绕过审计。 | 内部输入可追溯到原始提交人、时间和后续 Event。 |

## 4.2 M2 事件智能

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-06 事件形成与聚合 | UJ-1, UJ-3 | 热点/研究运营；Candidate Event 进入处理时 | 支持标准化、去重、合并、拆分和聚类，将多个 Signal 关联到 Event。 | 合并、拆分、忽略均保留原始引用与原因。 |
| FR-07 身份关系与人工校正 | UJ-3 | 热点/研究运营；发现人物、组织、地点或事件关系冲突时 | 维护事件与关键实体的关系，并允许有权限者人工纠错；不以自动推断覆盖人工确认。 | 校正前后值、理由和操作人可审计。 |
| FR-08 事实、证据与置信度 | UJ-3 | 热点/研究运营、内容运营；新增或核验事实时 | 将 Fact Item 区分为确认、待确认、排除；关联 Source Evidence 与置信度。 | 事实、热度、观点、传闻和预测独立展示；不满足证据规则的事实不可用于可发布行动。 |
| FR-09 有版本 Event Card | UJ-3 | 系统或授权用户；Event 首次形成或发生实质更新时 | 呈现边界、事实、证据、关系、热度、风险、窗口和状态，并保存版本。 | 可查看 Event Card v1 及后续更新；未完成字段不默认已确认。 |
| FR-10 事件监测与演化 | UJ-3, UJ-5 | 系统或热点/研究运营；新证据、热度变化、窗口到期或重新活跃时 | 跟踪生命周期、窗口调整、关闭、再激活和提醒。 | 关闭 Event 可再激活；调整保留依据，超时 Event 不被删除。 |

## 4.3 M3 机会决策

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-11 平台与受众机会分析 | UJ-3 | 增长负责人、内容/产品/渠道运营；Event 可判断时 | 描述平台、受众重合、传播路径、进入窗口及变化；推断必须标记为推断。 | 每条分析可追溯 Event 与来源，不把推断当作已验证事实。 |
| FR-12 价值、风险与资源评估 | UJ-3 | 增长负责人和指定业务所有者；准备决策时 | 评估目标价值、业务相关性、资格边界、品牌风险、响应时机和资源可行性。 | 每项评估显示依据、信心度、所有者和审核状态。 |
| FR-13 Opportunity Card 与排序 | UJ-3 | 系统或增长负责人；Event 完成初步评估时 | 基于 Event 形成机会卡片，包含目标、受众、价值、风险、资源和承接路径；支持比较与排序。 | Opportunity Card 可追溯 Event Card，且不可脱离 Event 单独创建。 |
| FR-14 四档机会决策 | UJ-3 | 增长负责人或授权决策人；Opportunity Card 完成评估时 | 支持优先参与、参与、观察、不参与；优先参与与参与应明确资源或时限优先级。 | 观察必须有重新评估时间；不参与和覆盖建议必须记录原因；仅前两档可进入 M4。 |

## 4.4 M4 任务中心

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-15 任务方案 | UJ-4 | 增长负责人、行动责任人；Opportunity 为优先参与或参与时 | 形成 Task Plan，明确目标、成功标准、参与策略、受众、渠道、时间窗口、资源、风险约束与预期结果；可比较不同参与策略，但系统建议不替代人工决定。 | 选定方案可追溯 Opportunity Card；缺少目标、责任人或窗口时不得进入任务拆解。 |
| FR-16 任务拆解 | UJ-4 | 行动责任人；Task Plan 已选定时 | 将任务方案拆解为渠道动作、交付物、责任人、截止时间和依赖；每项 Action Task 继承 Event、Opportunity、目标和风险上下文。 | 每项行动均有责任人、交付物和状态；依赖未满足时明确阻塞原因，不能显示为已交接。 |
| FR-17 可审核草稿、预检与修订 | UJ-4 | 系统、内容/产品/渠道运营与审核者；需要内容或其他交付物时 | 基于已核验事实和 Task Plan 生成 Review Draft；进行来源、禁用表述、异常数字和版本相似度预检；支持人工通过、要求修改或驳回，以及基于意见生成新版本。 | 草稿保留事实/来源引用、版本、预检结果与审核结论；未通过审核的草稿不得被标记为已交接或已完成。 |
| FR-18 任务分发、Telegram 审核投递与看板 | UJ-4 | 行动责任人或系统；Review Draft 进入待审核，或已审核交付物对应的 Action Task 可交接时 | 在草稿待审核时，向指定审核目标投递 Review Draft；在任务可交接时，向责任人或已接入专业执行系统分发 Action Task，并汇总接收、进度、异常和完成状态。Phase 0 仅允许 Telegram Bot 向管理员已批准的频道、群组或讨论群投递 Review Draft 供人工审核。 | 审核投递和任务分发均保留目标、时间和接收回执；Phase 0 的 Telegram 目标必须来自批准目录、投递回执可见，且 Bot 不得向社媒特定账号自动发布。 |
| FR-19 外部执行协同、例外升级与回执 | UJ-4 | 外部专业执行系统、行动责任人或有权限用户；任务被接收、状态变化或发生事实/风险/执行异常时 | 外部系统自主完成具体制作、账号发布、产品上线、活动或关系协作，并将 Task Receipt 回传。发生越界、连接失败、负面反馈或人工停止时，系统标记异常、保留已知状态并提供人工接管与升级入口。 | 回执延迟不得默认视为完成、取消或失败；异常明确显示影响对象、下一责任人和处置入口，不得静默替外部系统执行。 |
| FR-20 热点运营工作台 | UJ-1, UJ-3, UJ-4 | 全部授权角色；进入系统时 | 聚合重点事件、待办、风险提醒、响应窗口、行动进度和执行异常，并按角色展示待处理事项。 | 用户可在两次操作内由待办进入对应 Event、Opportunity、Task Plan 或 Action Task。 |

## 4.5 M5 效果与学习

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-21 执行结果汇总 | UJ-5 | 行动所有者或外部执行系统；执行完成、取消或异常时 | 按 Event、Opportunity、Task Plan 与 Action Task 汇总执行回报、状态和异常。 | 每条结果可追溯到行动、执行者和回执来源。 |
| FR-22 传播与产品结果追踪 | UJ-5 | 数据团队、行动所有者；可获得结果数据时 | 记录触达、互动、分发、访问、注册、参与、转化等结果，并标注来源、时间和口径。 | 可按 Event、Opportunity、Task Plan 和 Action Task 查询；缺失数据不显示为完整结果。 |
| FR-23 成本与结果关联 | UJ-5 | 增长负责人、数据团队；记录投入或分析结果时 | 记录费用、人力和资源投入，并与可获得的 Outcome 关联。 | 成本来源、口径和缺口可见；不充分数据不得表述为精确 ROI。 |
| FR-24 行动复盘 | UJ-5 | 数据团队、增长负责人和行动所有者；行动关闭或结束时 | 记录有效/无效因素、风险事件、结果解释和后续建议。 | 已参与或关闭行动能关联复盘；缺失数据有明确说明。 |
| FR-25 策略优化建议 | UJ-5 | 增长负责人或授权策略所有者；复盘完成时 | 生成并管理对发现规则、事件判断、机会策略或行动模板的优化建议。 | 每项建议关联证据、适用范围和批准状态；批准后可回写相应策略项。 |
| FR-26 共享业务字典 | UJ-1—UJ-5 | 字典管理员；新增/调整跨模块定义时 | 维护来源可信等级、平台/渠道、受众、风险政策、目标与指标口径。 | M1—M5 对同一字典项使用一致标识；修改具有生效范围和审计记录。 |
