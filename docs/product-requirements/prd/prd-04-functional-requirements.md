# 04 功能需求

每条需求均为业务能力要求；技术实现由后续系统架构定义。除另有说明外，所有关键创建、变更、覆盖和关闭动作必须记录操作人、时间和原因。

## 4.1 M1 热点发现

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-01 实时热点雷达 | UJ-1 | 热点/研究运营；打开监测范围或收到提醒时 | 展示已接入来源的 Signal、时间、热度变化、来源状态与新鲜度；不把 Signal 表述为事实。 | 可按范围筛选；缺失、延迟或异常来源被明确标记。 |
| FR-02 未来事件中心 | UJ-2 | 热点、增长、内容或产品运营；创建、导入或更新未来事件时 | 维护日期、地区、重要性、监测范围、预案与负责人；支持发生前、发生中和结果期。 | 改期、取消、窗口到达均保留历史并触发相应待办。 |
| FR-03 事件触发与候选匹配 | UJ-1, UJ-2 | 系统规则或人工；新 Signal、预案到期或两者满足匹配条件时 | 支持预案独立触发、突发事件独立进入、未来事件×实时 Signal 匹配三种路径。 | 每个 Candidate Event 标明触发路径、输入引用和待处理状态。 |
| FR-04 监控范围与提醒 | UJ-1, UJ-2 | 热点/研究运营；配置主题、地区、来源、阈值或处置时限时 | 创建监控对象与提醒规则，指定负责人；同一监测范围内、指向同一 Candidate Event 或 Event 且无重大事实、风险或响应窗口变化的提醒应合并处理。 | 触发后生成可追溯待办；合并后保留全部来源且不产生无归属告警；存在重大变化时生成原事件的更新提醒。 |
| FR-05 内部事件录入 | UJ-1, UJ-2 | 授权业务人员；录入产品发布、营销活动、客户或内部信号时 | 将内部输入按同一 Signal/Candidate Event 规则纳入流程，不绕过审计。 | 内部输入可追溯到原始提交人、时间和后续 Event。 |

## 4.2 M2 事件智能

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-06 事件形成与聚合 | UJ-1, UJ-3 | 热点/研究运营；Candidate Event 进入处理时 | 支持标准化、去重、合并、拆分和聚类，将多个 Signal 关联到 Event。 | 合并、拆分、忽略均保留原始引用与原因。 |
| FR-07 事件上下文与人工校正 | UJ-3 | 热点/研究运营；发现人物、组织、地点、话题或事件上下文冲突时 | 维护 Event 的关键上下文信息，并允许有权限者人工纠错；上下文是 Event 的业务信息，不另设独立概念实体；不以自动推断覆盖人工确认。 | 校正前后值、理由和操作人可审计。 |
| FR-08 事实、证据与置信度 | UJ-3 | 热点/研究运营、内容运营；新增或核验事实时 | 将 Fact 区分为确认、待确认、排除；Evidence 分别记录支持、质疑或排除该事实的来源材料与可信等级。 | 事实、热度、观点、传闻和预测独立展示；不满足证据规则的事实不可用于可发布行动。 |
| FR-09 有版本 Event Card | UJ-3 | 系统或授权用户；Event 首次形成或发生实质更新时 | 将 Event 的边界、关联 Fact 与 Evidence、热度、风险、窗口和状态汇集呈现为有版本档案；Event Card 引用这些对象，不改变其独立实体边界。 | 可查看 Event Card v1 及后续更新；未完成字段不默认已确认。 |
| FR-10 事件热度监测与演化 | UJ-3, UJ-5 | 系统或热点/研究运营；新证据、热度变化、窗口到期或重新活跃时 | 监测热度与生命周期变化并提供提醒信息；授权规则或用户基于明确依据，更新 Event Card 的窗口、关闭或再激活状态。热度监测本身不自动调整窗口或关闭/再激活事件。 | 关闭 Event 可再激活；调整保留依据，超时 Event 不被删除。 |

## 4.3 M3 机会决策

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-11 平台与受众机会分析 | UJ-3 | 增长负责人、内容/产品/渠道运营；Event 可判断时 | 描述平台、受众重合、传播路径、进入窗口及变化；推断必须标记为推断。 | 每条分析可追溯 Event 与来源，不把推断当作已验证事实。 |
| FR-12 价值、风险与资源评估 | UJ-3 | 增长负责人和指定业务所有者；准备决策时 | 评估目标价值、业务相关性、资格边界、品牌风险、响应时机和资源可行性。 | 每项评估显示依据、信心度、所有者和审核状态。 |
| FR-13 Opportunity Card 与排序 | UJ-3 | 系统或增长负责人；Event 完成初步评估时 | 基于 Event Card 的直接输入形成机会卡片，包含目标、受众、价值、风险、资源和承接路径；支持比较与排序。 | Opportunity Card 可追溯 Event Card 与根 Event，且不可脱离 Event 单独创建。 |
| FR-14 四档机会决策 | UJ-3 | 增长负责人或授权决策人；Opportunity Card 完成评估时 | 支持优先参与、参与、观察、不参与；优先参与与参与应明确资源或时限优先级。 | 观察必须有重新评估时间；不参与和覆盖建议必须记录原因；仅前两档可进入 M4。 |

## 4.4 M4 任务中心

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-15 跨渠道任务方案 | UJ-4 | 增长负责人、行动责任人；Opportunity 为优先参与或参与时 | 草拟并选定 Task Plan，明确目标、成功标准、受众、窗口、资源和风险；对每个相关渠道定义参与/不参与、渠道作用、边界与优先级，可组合内容发布、营销活动、私域触达与 KOL 合作。 | 选定方案可追溯 Opportunity Card；每个渠道的参与结论、目标、责任角色与适用审核门禁明确。 |
| FR-16 渠道级行动任务拆解与统一状态 | UJ-4 | 行动责任人；Task Plan 已选定且存在可交接交付物草稿时 | 基于交付物草稿，为每个需要响应的渠道创建独立 Action Task，明确责任人、截止时间、依赖、执行方式与交接目标。主状态仅为待交接、已接收、进行中、已完成/暂停/异常/取消；草拟、审核与批准属于 Task Plan 或交付物草稿，不属于 Action Task 主状态。 | 每项任务继承 Event、Opportunity、Task Plan、目标和风险上下文；阻塞原因、下一责任人和执行方式可见。 |
| FR-17 四类交付物草稿、预检与审核 | UJ-4 | 系统、相应行动审核者；已选定 Task Plan 的某渠道需要响应时 | 以单一父实体 Execution Deliverable Draft 生成四种交付物类型：Social Content Draft、Private Outreach Draft、Campaign Proposal Draft、KOL Outreach Draft；草稿须继承其渠道在 Task Plan 中的作用与边界，保留事实/来源，运行类型适用的预检，支持直接编辑或按意见生成新版本，以及通过、需修改、驳回和低风险同类批量审核。 | 四种类型不是独立概念实体；已通过版本不可静默覆盖；仅可交接草稿可据以创建对应的 Action Task；批量审核显示数量、目标与差异，高风险项自动拆出并由品牌/风控审核。 |
| FR-18 分类型执行与连接器 | UJ-4 | 系统、行动责任人；交付物已通过适用审核时 | 社媒内容进入人工筛选/发布交接并记录声明或平台验证；Phase 0 的可审核社媒内容草稿由 Telegram Bot 投递至管理员批准审核目标，不直接发送到任何社媒特定账号；Private Outreach Draft 按已批准目标与渠道规则交接；Campaign Proposal Draft 形成执行清单交负责人实施；KOL 名单、首封模板、账号和频率获批后，通过 X 自动发送首封私信，能力不可用时降级人工发送。 | 系统内部为权威版本；Google Docs/Telegram 可作协作出口；每项执行方式和实际 Task Receipt 可见；任何外部发送目标均须具有明确批准记录。 |
| FR-19 回执、回复与例外升级 | UJ-4 | 人工、连接器、平台或有权限用户；执行、回复或异常发生时 | 关联 Task Receipt；KOL 回复进入合作收件箱，AI 可判断意向并生成回复建议，但后续消息由人工确认；事实/风险越界、连接失败、拒绝/退订、负面反馈或频率异常时暂停相应动作并升级。 | 无真实回执时显示等待/延迟，不推定完成；异常明确影响范围、下一责任人和恢复入口。 |
| FR-20 热点运营工作台 | UJ-1, UJ-3, UJ-4 | 全部授权角色；进入系统时 | 聚合重点事件、待办、风险提醒、响应窗口、行动进度和执行异常，并按角色展示待处理事项。 | 用户可在两次操作内由待办进入对应 Event、Opportunity、Task Plan 或 Action Task。 |

## 4.5 M5 效果与学习

| ID | 关联旅程 | 角色与触发条件 | 行为与边界 | 可测试结果 |
|---|---|---|---|---|
| FR-21 执行结果汇总 | UJ-5 | 行动所有者或外部执行系统；执行完成、取消或异常时 | 按 Event、Opportunity、Task Plan、Action Task 与 Task Receipt 汇总执行回报、状态和异常。 | 每条结果可追溯到行动、执行者和回执来源。 |
| FR-22 传播与产品结果追踪 | UJ-5 | 数据团队、行动所有者；可获得结果数据时 | 记录触达、互动、分发、访问、注册、参与、转化等结果，并标注来源、时间和口径。 | 可按 Event、Opportunity、Task Plan 和 Action Task 查询；缺失数据不显示为完整结果。 |
| FR-23 成本与结果关联 | UJ-5 | 增长负责人、数据团队；记录投入或分析结果时 | 记录费用、人力和资源投入，并与可获得的 Outcome 关联。 | 成本来源、口径和缺口可见；不充分数据不得表述为精确 ROI。 |
| FR-24 行动复盘 | UJ-5 | 数据团队、增长负责人和行动所有者；行动关闭或结束时 | 记录有效/无效因素、风险事件、结果解释和后续建议。 | 已参与或关闭行动能关联复盘；缺失数据有明确说明。 |
| FR-25 策略优化建议 | UJ-5 | 增长负责人或授权策略所有者；复盘完成时 | 生成并管理对 Monitoring Scope、Opportunity Card 判断策略或 Task Plan 模板的优化建议。 | 每项建议关联 Outcome/复盘证据、适用范围和批准状态；仅批准后才可回写相应策略项，且不得自动覆盖既有规则。 |
| FR-26 共享业务字典 | UJ-1—UJ-5 | 字典管理员；新增/调整跨模块定义时 | 维护来源可信等级、平台/渠道、受众、风险政策、目标与指标口径。 | M1—M5 对同一字典项使用一致标识；修改具有生效范围和审计记录。 |
