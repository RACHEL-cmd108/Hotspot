# 热点运营 Agent 三子系统业务边界、验收标准与 MVP 时间表

## 1. 总体业务链路

三个子系统按“事实与洞察 → 运营判断 → 内容执行与反馈”分工：

1. **热点情报中心**回答“外部发生了什么、大家在讨论什么、什么内容正在热门，以及依据是什么”。
2. **运营决策与 Agent 中心**回答“当前是否值得承接、为什么现在承接、应该选择什么 Angle”。
3. **内容运营与反馈中心**回答“如何把已确认 Angle 形成可编辑内容，以及真实采用结果是什么”。

核心边界原则：

- 上游拥有其业务对象的解释权，下游只能引用版本，不得静默改写。
- 每次跨系统交接必须携带来源对象 ID、对象版本、分析版本、状态、风险和数据边界。
- “事实错误”回到热点情报中心；“机会或 Angle 判断错误”回到运营决策中心；“草稿表达或格式问题”由内容运营中心处理。
- 项目配置是共享平台能力，不属于某一个业务子系统。各子系统只拥有自身配置域的业务解释权。
- 第一期所有发布动作均由人工完成，任何子系统都不得自动发布。

## 2. 跨系统所有权矩阵

| 业务能力或对象 | 热点情报中心 | 运营决策与 Agent 中心 | 内容运营与反馈中心 |
| --- | --- | --- | --- |
| 外部采集、Signal、Evidence | 创建、更新、纠错 | 只读引用 | 只读引用 |
| Event、Discussion、Hot Content Sample | 创建、合并、拆分、版本化 | 只读消费 | 只读消费 |
| Context Pack、Discussion Analysis、Content Insight | 创建、更新、声明边界 | 只读消费并检查版本 | 只读消费并检查版本 |
| Operational Opportunity | 不创建 | 创建、排序、关闭、版本化 | 只读消费并回传采用结果 |
| Angle | 不创建 | 生成、修改、选择、否定、版本化 | 只读继承；允许形成表达版本但不得改变核心主张 |
| Draft / Reference Video Script | 不创建 | 不创建最终草稿 | 创建、编辑、版本化、采用或放弃 |
| Preference Feedback | 接收相关参考，不自动改事实 | 接收排序和 Angle 反馈 | 采集并路由 |
| Quality Correction | 接收事实、聚合和来源纠错 | 接收机会、排序和 Angle 纠错 | 采集、分类并路由 |
| 项目配置 | 消费来源、主题圈和采集配置 | 消费产品画像、机会框架和长期偏好 | 消费账号角色、内容形式和表达偏好 |

## 3. 子系统一：热点情报中心

### 3.1 业务边界

**负责：**

- 从 X 热搜榜、未来事件配置、X 主题圈和 YouTube 固定来源发现外部变化。
- 将原始变化聚合为 Event、Discussion 或 Hot Content Sample。
- 维护事实、证据、来源、时间线、热度/注意力快照、对象状态和版本。
- 形成 Context Pack、Discussion Analysis、Content Insight 与可解释变化标签。
- 支持对象去重、合并、拆分、人工纠错和审计。

**接收：**

- X 热搜任务、未来事件、X 主题圈和 YouTube 发现任务配置；
- X 帖子或 YouTube 视频用户提交；
- 内容运营中心路由回来的事实、来源、聚合和分析纠错。

**交付：**

- Event Record、Trend Footprint、Fact/Evidence、Event Timeline、Context Pack、Response Moment；
- Discussion Record、Attention Snapshot、Viewpoint Map、Representative Posts、Controversy/Q&A、Discussion Analysis；
- Hot Content Sample、Performance Snapshot、Content Timeline、Audience Response、Content Insight、Transferable Playbook；
- 对象 ID、版本、数据完整度、状态、风险和表达边界。

**不负责：**

- 判断对象是否值得运营承接或给机会排序；
- 选择运营目标、受众或 Angle；
- 生成社媒草稿、视频脚本或执行发布；
- 根据偏好反馈修改事实；
- 把缺失数据推算为事实、精确传播曲线或因果结论。

### 3.2 MVP 验收标准

**来源与配置：**

- 可以分别建立、编辑、启停 X 热搜、未来事件、X 主题圈和 YouTube 发现任务。
- 每项任务显示负责人、最近成功时间、失败状态和失败原因。
- 重复执行同一采集任务不会重复创建原始内容或业务对象。

**对象形成：**

- X 热搜默认进入 Event 聚合流程，并能在“关联已有 Event、创建正式 Event、创建 Candidate Event、拆分多个 Event、保留 Trend Signal”之间给出明确结果和理由。
- Discussion 必须能够追溯到主题圈和代表帖子；单条命中关键词的普通帖子不能直接成为 Discussion。
- YouTube 样本必须保存视频 ID/URL、标题、封面、时长、频道、发现来源和采集时间。

**产品产出：**

- 三类主对象均可从卡片进入完整档案，并展示各自约定的六项产品产出或明确的“未取得/无法生成”状态。
- Event 的关键 Fact 100% 关联 Evidence；待确认内容不得展示为已确认。
- 趋势和注意力标签可以展开查看来源快照、比较时间点和计算依据。
- 对象和分析更新产生新版本，不覆盖历史版本。

**边界与治理：**

- 在验收用例中，缺失字幕、互动数据、评论或连续快照时，页面明确显示未知，不生成伪造值。
- 合并、拆分、事实状态修改和分析纠错全部保留操作者、时间、前后版本和原因。
- 只有主对象、最新分析版本、来源追溯和数据边界齐全的对象才能标记为“可供下游使用”。

### 3.3 独立 MVP 时间表（6 周）

| 周期 | 可验收增量 | 退出条件 |
| --- | --- | --- |
| 第 1 周 | 业务对象、状态机、四类来源配置和跨系统交付契约 | 能用固定样例创建/查看三类对象和配置，字段与版本契约冻结 |
| 第 2 周 | X 热搜、未来事件与 Event 聚合最小闭环 | 热搜可形成正式/候选/复用/拆分/Signal 五类结果；未来事件可进入观察队列 |
| 第 3 周 | Event 档案、Trend Footprint、Fact/Evidence、Timeline 和 Response Moment | Event 卡片与详情完整；证据、趋势标签和更新版本可追溯 |
| 第 4 周 | X 主题圈与 Discussion 闭环 | 主题圈配置、聚类、注意力快照、观点地图和代表帖子可用 |
| 第 5 周 | YouTube 发现、视频样本和内容拆解闭环 | 视频封面卡、Performance Snapshot、时间轴、Content Insight 和 Playbook 可用 |
| 第 6 周 | 去重、纠错、审计、失败状态和跨系统交付验收 | 完成三类标准验收样例的端到端验收，并能稳定交付给运营决策中心 |

## 4. 子系统二：运营决策与 Agent 中心

### 4.1 业务边界

**负责：**

- 消费热点情报中心中“可供下游使用”的对象和分析版本。
- 结合项目目标、产品画像、时效、相关性、风险和响应窗口形成 Operational Opportunity。
- 对机会进行可解释排序、筛选和处理状态管理。
- 在单一对象范围内进行解释、补充研究、条件重分析和 Angle 探索。
- 保存 Angle 的选择、修改、否定和对象级记忆。
- 将用户确认的 Angle 和完整生成上下文交给内容运营中心。

**接收：**

- 来源对象、分析版本、Evidence、Response Moment、数据完整度和表达边界；
- 产品画像、Monitoring Scope、机会框架和用户明确保存的 Project Preference；
- 内容运营中心回传的机会、Angle 判断纠错和采用结果。

**交付：**

- Operational Opportunity、Opportunity Type、相关性、响应窗口、风险、限制和推荐依据；
- 一个或多个结构化 Angle；
- 用户选择、修改或否定的方向；
- 交给内容运营中心的来源对象版本、Opportunity、Angle、账号角色、受众和用户限制。

**不负责：**

- 修改 Event、Discussion、Hot Content Sample、Fact 或 Evidence；
- 在对象范围外进行无边界通用聊天；
- 把推断写回事实底座；
- 创建最终社媒草稿或视频脚本；
- 自动执行、排期或发布运营动作。

### 4.2 MVP 验收标准

**机会形成：**

- 对三个上游对象类型均能生成或明确拒绝生成 Opportunity，并说明原因。
- 每张机会卡完整展示来源对象、机会类型、为什么是现在、相关性、响应窗口、证据状态、风险和更新时间。
- 排序结果可解释，不出现无法说明来源的统一“热度分”。

**对象工作台与 Agent：**

- 从机会卡进入 Object Workspace 后，Agent 继承正确的对象 ID、对象/分析版本、Evidence、已有 Opportunity、Angle 和用户限制。
- Agent 可以解释判断、在授权工具范围内补充研究、改变条件重新分析并探索不重复 Angle。
- 信息不足时能够输出“无法判断”；高风险或事实冲突时不能生成确定性结论。
- 上游分析版本更新后，系统提示用户并检查旧 Opportunity、Angle 和相关草稿是否过时。

**Angle 与交接：**

- 每个 Angle 至少包含核心主张、受众、运营目标、借鉴机制、推荐形式、时效、难度、风险和差异点。
- 用户否定的 Angle 在同一对象后续生成中不重复出现，除非用户主动清除否定记录。
- 用户确认 Angle 后，内容运营中心收到完整交付字段；缺少来源版本、Angle 或表达边界时不能进入生成。

**边界与记忆：**

- 任何重分析都不得改变上游 Fact/Evidence；事实纠错必须路由回热点情报中心。
- 临时会话要求不会静默写入 Project Preference；只有用户明确保存才进入长期偏好。
- Opportunity、Angle 和状态变更均保存版本、操作者和时间。

### 4.3 独立 MVP 时间表（5 周）

启动条件：热点情报中心在第 1 周末冻结对象与分析版本契约；开发可先使用固定样例，不必等待真实采集完成。

| 周期 | 可验收增量 | 退出条件 |
| --- | --- | --- |
| 第 1 周 | Opportunity 对象、六类机会框架和固定样例输入 | 三类上游对象均能生成/拒绝机会并输出完整理由 |
| 第 2 周 | 今日机会卡、可解释排序、筛选和处理状态 | 用户能完成查看、收藏、观察、采用、拒绝和判断错误闭环 |
| 第 3 周 | Object Workspace 与对象绑定 Agent | Agent 继承版本化上下文并完成解释、补充、重分析和更新提醒 |
| 第 4 周 | Angle 结构、选择/否定、Object Memory 和内容交接 | Angle 不重复；选定 Angle 能形成完整内容生成上下文 |
| 第 5 周 | 风险边界、记忆边界、审计和真实上游集成验收 | 完成 Event、Discussion、YouTube 各一条端到端机会与 Angle 验收 |

## 5. 子系统三：内容运营与反馈中心

### 5.1 业务边界

**负责：**

- 消费已确认 Angle 和完整内容生成上下文。
- 根据账号角色、受众、目标、内容形式、语气、长度和限制生成可编辑草稿。
- 生成 X 单帖、Thread、短视频大纲、Reference Video Script 和互动回复方向。
- 支持草稿编辑、差异化版本、复制、保存、采用、放弃和人工发布记录。
- 检查来源版本更新后旧草稿是否过时、冲突或突破表达边界。
- 采集 Preference Feedback 与 Quality Correction，并路由给正确的对象所有者。
- 展示采用、效率、可信度和系统健康指标。

**接收：**

- 来源对象及分析版本、Opportunity、选定 Angle、Evidence、风险和表达边界；
- 账号角色、受众、内容形式、语气、长度和用户追加要求；
- 上游对象或 Angle 的版本更新通知。

**交付：**

- Social Content Draft、Reference Video Script 和 Draft Version；
- Adoption Record、人工发布记录和拒绝原因；
- Preference Feedback 或 Quality Correction；
- 采用、效率、可信度和健康指标。

**不负责：**

- 重新判断事实、修改 Evidence 或重写 Opportunity/Angle 的核心主张；
- 自动发布、自动排期和账号调度；
- 复杂审批、完整富文本编辑器和批量生成；
- 自动找齐素材、配音、剪辑或生成完整视频；
- 承诺内容获得爆款或完成完整流量归因。

### 5.2 MVP 验收标准

**生成入口：**

- 缺少来源对象版本、分析版本、选定 Angle 或表达边界时，系统阻止生成并提示缺失项。
- 生成页面明确展示账号角色、受众、目标、形式、语气、长度及必须保留/避免内容。

**草稿与视频脚本：**

- 五类内容形式均可生成、编辑、复制和保存；每份产出可追溯到来源对象、分析版本、Opportunity 和 Angle。
- 待确认信息不会被写成确定事实；草稿中的关键事实与引用的分析版本一致。
- Reference Video Script 包含目标、受众、核心主张、时长、借鉴机制、差异化、分段画面/旁白、字幕、素材、CTA、依据和风险。
- 内容复刻只迁移机制，不逐句改写或复制独特表达、独家素材。

**版本、状态与有效性：**

- 重新生成或人工编辑产生新 Draft Version，旧版本不被覆盖。
- 草稿完整支持已生成、已编辑、已采用、人工记录已发布和已放弃状态。
- 上游版本实质更新后，旧草稿自动进入重新检查；事实冲突或越界草稿不能保持“可发布”。
- 系统不存在自动发布路径；人工记录发布必须由用户明确操作。

**反馈和复盘：**

- 暂不采用必须记录结构化原因。
- Preference Feedback 与 Quality Correction 分开保存；事实类纠错回到热点情报中心，机会/Angle 类纠错回到运营决策中心。
- 所有采用、编辑、状态和反馈动作保存对象版本、操作者和时间。
- 复盘页不以生成量作为成功结论，能够展示采用、编辑后采用、拒绝原因、耗时和纠错情况。

### 5.3 独立 MVP 时间表（5 周）

启动条件：运营决策中心在第 1 周末冻结 Opportunity 与 Angle 交付契约；开发可先使用固定 Angle 样例。

| 周期 | 可验收增量 | 退出条件 |
| --- | --- | --- |
| 第 1 周 | 生成上下文契约、生成配置和来源追溯 | 缺少必需上下文时阻止生成；完整样例可进入生成 |
| 第 2 周 | X 单帖、Thread、互动回复和草稿版本 | 三类文本产出可生成、编辑、复制、保存并追溯来源 |
| 第 3 周 | 短视频大纲、Reference Video Script 和版权边界 | 视频脚本字段完整，复刻用例通过差异化与版权检查 |
| 第 4 周 | 草稿状态、采用/放弃、人工发布记录、反馈分流 | 草稿生命周期闭环；偏好和质量纠错能正确路由 |
| 第 5 周 | 上游更新失效检查、复盘指标、审计和真实集成验收 | 完成选 Angle—生成—编辑—采用—反馈端到端验收 |

## 6. 建议的并行实施节奏

三份独立时间表不要求串行相加为 16 周。建议以契约先行为原则并行：

| 总体周次 | 热点情报中心 | 运营决策与 Agent 中心 | 内容运营与反馈中心 |
| --- | --- | --- | --- |
| 总第 1 周 | 冻结情报对象和分析契约 | 参与评审并准备固定样例 | 参与评审内容交付字段 |
| 总第 2 周 | Event 最小闭环 | 使用固定样例开发 Opportunity | 准备生成上下文与账号样例 |
| 总第 3 周 | Event 完整档案 | 今日机会与排序 | 使用固定 Angle 开发生成入口 |
| 总第 4 周 | Discussion 闭环 | Object Workspace 与 Agent | 文本草稿与版本 |
| 总第 5 周 | YouTube 闭环 | Angle 与内容交接 | 视频脚本与版权边界 |
| 总第 6 周 | 情报治理与交付验收 | 真实情报集成与边界验收 | 状态、反馈与纠错路由 |
| 总第 7 周 | 支持联调 | 决策系统最终验收 | 上游更新检查、复盘与最终验收 |

建议将**总第 7 周**设为三个子系统共同的 MVP 集成验收点，但每个子系统仍按自身时间表和退出条件独立验收。

## 7. 端到端共同验收场景

MVP 最终至少通过以下三条完整场景：

1. **Event 场景：**X 多地区热搜 → 聚合 Event → Context Pack/Response Moment → Opportunity → 选择 Angle → 生成 X 草稿 → 编辑后采用 → 反馈记录。
2. **Discussion 场景：**主题圈讨论升温 → Discussion Analysis → 用户洞察型 Opportunity → 选择教育/互动 Angle → 生成 Thread 或回复方向 → 暂不采用并记录原因。
3. **YouTube 场景：**热门视频发现 → Content Insight/Transferable Playbook → 内容复刻型 Opportunity → 选择差异化 Angle → Reference Video Script → 版权边界检查 → 人工进入制作准备。

共同失败场景也必须通过：上游事实更新或 Evidence 冲突后，Opportunity、Angle 和旧草稿收到更新提示；不再满足条件的草稿不能继续保持可发布状态。
