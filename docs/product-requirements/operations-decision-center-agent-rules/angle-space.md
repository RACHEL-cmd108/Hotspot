# 产品承接角度探索空间

## 1. Angle 定义

Angle 是针对一个已成立的选题机会提出的切入主张，回答“通过哪个 PredX 对象或产品价值，为哪类用户解释什么”。它不是最终标题、文案、大纲、脚本或内容形式。

Angle 由以下因素组合：

```text
承接对象 × 切入机制 × 事件阶段 × 目标用户 × 用户价值 × 运营目标
```

## 2. 实时市场承接面

| ID | 承接面 | 核心问题 |
|---|---|---|
| MA-01 | 当前市场预期 | 市场现在如何判断该结果？ |
| MA-02 | 概率变化 | 何时、如何发生变化，变化是否显著？ |
| MA-03 | 新证据影响 | 哪条新信息可能改变市场判断？ |
| MA-04 | 市场—事实偏差 | 市场是否尚未反映最新事实，依据是什么？ |
| MA-05 | 判断分歧 | 不同判断由哪些假设或信息造成？ |
| MA-06 | 条件路径 | 哪些条件会把结果推向不同方向？ |
| MA-07 | 时间节点 | 截止、发布、投票、决定或下一观察点是什么？ |
| MA-08 | 结算条件 | 什么事实满足或不满足市场定义的结果？ |
| MA-09 | 关联市场 | 同一事件如何影响其他具体市场？ |
| MA-10 | 市场活跃度 | 真实成交、流动性或关注变化说明了什么，边界是什么？ |
| MA-11 | 预期与结果复盘 | 结果出现后，事前市场判断与结果如何对应？ |
| MA-12 | 历史基准 | 可比事件或历史市场提供什么基准？ |

MA-02、MA-04、MA-10、MA-11 和 MA-12 只有在存在相应真实数据时可用。

## 3. 产品价值承接面

| ID | 承接面 | 核心问题 |
|---|---|---|
| PA-01 | 结构化事件研究 | 如何组织主体、动作、结果、条件和证据？ |
| PA-02 | 事件时间线 | 哪些前置、变化、后续或反转影响理解？ |
| PA-03 | 已知与未知 | 当前确认了什么，仍有哪些关键未知？ |
| PA-04 | 条件路径研究 | 后续发展依赖哪些条件与节点？ |
| PA-05 | 下一观察点 | 下一条足以改变判断的信息是什么？ |
| PA-06 | 结果或决策研究 | 如何定义、验证最终结果或正式决定？ |
| PA-07 | 概率思维解释 | 为什么判断应以范围和条件表达，而非确定结论？ |
| PA-08 | 信息更新 | 新证据如何改变已有判断？ |
| PA-09 | 可验证问题 | 如何把事件转化为可观察、可验证的问题？ |
| PA-10 | 用户研究路径 | 用户如何使用 PredX 已上线能力继续理解或跟进事件？ |

每个 PA Angle 必须引用已批准的产品事实（可包括产品定位、价值主张、用户场景或已上线能力）。计划能力只可作为缺口，不可作为当前承接对象。

## 4. 只有公共关注度成立时

公共关注度成立但没有市场或产品价值匹配时，不生成伪产品角度。输出：

```yaml
bridge_type: attention_only
angle_status: pending_human_exploration
known_reasons: []
missing_bridge: live_market | product_value | both
```

Agent可提出“需要验证的承接假设”，但必须标记为假设，不进入成熟 Angle 集合。

## 5. 探索规则

1. 先覆盖不同承接面，再在同一承接面内变化表达。
2. 数量由自然成立方向决定：允许 0、1 或多个，不设最低凑数要求。
3. 默认展示质量排序前 5 个，保留其余通过质量门的候选供展开。
4. 每个候选只表达一个核心主张；需要多个主张时拆分。
5. 候选至少覆盖不同承接对象、机制、用户价值或事件阶段之一。
6. 内容标题、Hook、形式和渠道由内容生产阶段决定；本层只提供可供其使用的切入主张。
