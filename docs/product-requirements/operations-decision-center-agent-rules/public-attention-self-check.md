# 公共关注度 Agent 可执行性自查

## 结论

第一期的公共关注度不让 Agent 自行猜测“这件事到底火不火”。系统读取 X 短时增速排行榜的排名：前 3 名即为 `met`。Agent 只负责把该证据归属到当前事件并解释结果。

## 判定演练

| 输入 | 唯一预期结果 | Agent 理由 |
|---|---|---|
| 当前事件的代表帖子位于 X 短时增速榜第 2 名 | `met` | 排名满足公共关注度规则。 |
| 排名第 4 名 | `not_met` | 未进入前 3。 |
| 排名第 1 名；证据取得于 45 分钟前 | `met` | 证据时间保留用于追溯，但不改变排名准入结论。 |
| 人工或外部来源只提供事件描述，没有排名 | `uncertain` | 公共关注度证据缺失；仍可继续检查市场承接和产品价值承接。 |
| 排名第 3 名；没有市场或产品连接 | `met + attention_only` | 可进入选题推荐，但只标记为待人工探索，不生成伪造的产品承接角度。 |
| 没有热度排名；官方决定在 1 小时前发布，且直接影响 PredX 产品 | 公共关注度 `uncertain`；按 `URG-03` 可为 `immediate` | 公共关注度与响应节奏是独立判断；立即响应必须引用关键事实证据。 |

## 边界检查

- 公共关注度回答“可否仅凭公共热度进入推荐”，不回答事实是否真实、是否有产品角度或是否立即响应。
- Agent 不得以“全网都在讨论”“感觉很火”等描述替代排行榜排名。
- `attention_only` 表示公共热度已满足、承接尚未成熟；它不是产品或市场匹配。
- 本子系统没有“持续观察”状态；新信息作为更新上下文再次提交即可。

## 上线依赖

程序必须提供：`platform=X`、事件代表帖或事件 ID、短时增速排名。`captured_at` 可用于追溯但不是准入必填项；缺少排名时，公共关注度输出 `uncertain`，而非由 Agent 估算。
