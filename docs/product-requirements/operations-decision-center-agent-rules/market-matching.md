# PredX 实时市场匹配规则

## 1. 目标

判断事件是否与一个真实、当前可用的 PredX 市场存在可解释关系。语义相似只用于召回候选，不能单独形成匹配结论。

## 2. 匹配步骤

### M1：召回候选市场

使用主体、动作、结果、对象、时间、地点、条件和同义实体召回候选。完成条件：保留召回理由，不把候选视为已匹配。

### M2：检查问题对应关系

比较事件事实与市场问题：

- 主体是否一致；
- 结果或决定是否一致；
- 时间窗口是否重叠；
- 地区、对象和条件是否一致；
- 当前事件是否可能改变对市场结果的判断。

### M3：检查结算语义

读取市场结算规则、截止时间和有效来源。事件必须影响规则所定义的结果；标题相似但结算定义不同，降为 `possible` 或 `none`。

### M4：检查市场可用性

记录开放状态、当前概率、快照时间、结算时间和数据新鲜度。关闭、已结算、暂停或过期数据不得作为“实时市场承接”；可作为历史研究背景时另行标记。

新鲜度由程序依据已发布的 `market_freshness_policy_version` 判断。Agent 只消费 `fresh / stale / unknown` 结果，不自行发明分钟数或小时数阈值。

### M5：分级并排序

```yaml
direct: 事件直接影响市场问题定义的结果或关键证据
related: 事件不直接决定结果，但具体影响一项条件、主体或关联结果
possible: 语义上可能相关，但结算、时间、主体或因果关系需要人工确认
none: 没有具体可解释关系
```

## 3. 必备依据

`direct` 或 `related` 至少包含：

- `market_id` 和真实链接；
- 事件证据 ID 或来源；
- 对应的市场问题与结算要素；
- 匹配理由；
- 市场状态和 `snapshot_at`；
- 数据新鲜度判断。

## 4. 多市场处理

- 同一事件可匹配多个市场；
- 按 `direct > related > possible`、市场可用性、时间相关性和角度差异排序；
- 结果语义相同的重复市场只保留主市场，其余作为关联市场；
- 不为了扩大候选数量保留关系微弱的市场；
- 每个 Angle 指定一个主市场，可附最多三个关联市场。

## 5. 市场数据使用边界

- 具体概率、变化、成交量和流动性必须附时间戳；
- 快照只表示当时状态，重新打开时读取实时值并保留历史快照；
- 概率是市场状态，不是事实概率或官方结论；
- 缺少真实数据时，只讨论市场问题和条件，不补造数值；
- 市场匹配不构成投资建议或结果保证；
- 市场规则冲突、来源异常或状态不明时进入人工复核。

实施前需由产品和工程共同发布 `market_freshness_policy_version`，至少定义不同市场状态与数据字段的过期阈值、接口失败降级方式、生效时间和复审周期。

## 6. 拒绝模式

以下情况输出 `none`：

- 只有宽泛主题相似；
- 事件发生时间不在市场规则覆盖范围；
- 主体相同但市场问题讨论不同结果；
- 必须假设未提供的事实才能建立关系；
- 市场已结束且当前选题依赖实时承接；
- 只能用“任何事情都可以预测”解释关联。
