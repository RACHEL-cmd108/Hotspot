# 《热点运营系统业务可扩展性需求》技术完备性审查

> 审查对象：`business-extensibility-requirements.md`（2026-08-17）  
> 审查角色：平台架构与工程负责人  
> 审查范围：扩展契约、数据模型与生命周期、配置治理、权限、安全、失败恢复、容量与 SLA、第三方平台约束、测试与验收  
> 结论日期：2026-08-17

## 1. 结论

**Verdict：方向完整，但尚不足以直接作为平台工程落地与最终验收基线。**

文档已经清楚定义三环节的业务扩展目标、配置与开发边界、核心对象、业务指标及代表性验收场景，适合作为产品需求基线。尤其是“同平台新增对象不开发”“组件组合优先于一次性 Skill”“新渠道只增加边界适配”三个判断明确且正确。

但对工程实现最关键的契约、状态、数据一致性、配置发布控制、权限边界、恢复语义、容量目标和第三方限制仍多停留在原则级陈述。不同团队可以据此做出彼此不兼容的连接器、状态机与数据模型；即使完成 AC-01～AC-14，也不能证明系统在并发、故障、平台限流、权限误用和配置回滚场景下可靠可扩展。

建议将本文件继续保持为产品需求基线，同时在开发启动前补齐本审查中的 Critical 与 High 项；可通过在本文件新增“工程验收契约”章节，或形成受本文件约束的配套技术规格完成。Medium 项可进入首期范围决策，但必须明确接受风险或延期版本。

## 3. Critical findings

### C-01 缺少三个扩展点的机器可验证契约

- **位置**：§3“总体模型与扩展原则”、§7.1、§8、FR-010、FR-017
- **问题**：文档要求“标准对象与能力契约”“新适配器不改写上下游”，但没有定义 Monitor Connector、Skill、Distribution Adapter 的必需操作、输入输出 schema、错误分类、能力声明、版本兼容规则和弃用流程。“公共字段”也未列出最低字段集。
- **后果**：各接入方会形成不同接口和错误语义；每增加平台仍可能修改核心流程，却形式上通过 FR-017。
- **具体修复**：新增“扩展契约”附录，为三类插件分别定义：`manifest/capabilities`、配置 schema、输入/输出 envelope、稳定 ID、时间与时区、分页/游标、幂等键、错误码（可重试/不可重试/鉴权/限流）、健康检查、超时/取消、指标接口；规定语义版本、兼容矩阵、契约测试、弃用期和未知字段的 forward-compatible 处理。AC 新增“只使用契约测试包接入模拟适配器，核心服务零修改”。

### C-02 统一生命周期没有形成状态机与一致性语义

- **位置**：§3“统一生命周期”、§7.3、§8“任务编排与状态管理”、NFR-003、AC-12
- **问题**：只罗列创建、启停、审核、失败、重试等状态，没有规定监测任务、信号、事件、内容资产、审核、分发任务和发布结果各自的合法状态、转移条件、终态、超时、取消、人工恢复及跨对象一致性。`幂等`未说明幂等作用域和保存期限。
- **后果**：重试、超时回调、人工回填和平台异步回执并发时，可能重复发帖、丢失发布结果、让内容停在不可恢复的中间态。
- **具体修复**：为每个一等对象定义状态图和转移表；明确状态转移的原子边界、乐观并发控制、outbox/inbox 或等价交付保证、去重键生成方式、幂等窗口、迟到/乱序回执处理、补偿动作、人工强制终结权限。将 AC-12 扩为“发送超时但平台实际成功、重复回调、乱序回调、重启后重放”四个场景，并验收零重复发布。

### C-03 核心数据模型、身份与版本快照不足以保证全链路追溯

- **位置**：§3 数据链路、§4、§5.4、§6.2、FR-018、FR-021、NFR-001、AC-13
- **问题**：只给出对象名称和关系链，没有定义对象主键、租户/工作区边界、关系基数、不可变快照、逻辑删除、来源内容版本、配置引用方式及 lineage 的最低保留信息。尤其“历史按原版本解释”与第三方指标持续变化、原帖删除、Insight 重新拆解之间如何协调不明确。
- **后果**：系统可能只能保存当前引用，无法重现当时输入与决策；归因口径或 Insight 更新后历史实验被悄然改写，AC-13 表面可查询但不可复现。
- **具体修复**：补充规范化概念模型及数据字典，至少明确 Source、Run、RawSignal、Event、EvidenceSnapshot、InsightVersion、ContentJob、ContentAssetVersion、ReviewDecision、DistributionJob、ExternalPublication、MetricObservation、ExperimentAssignment、ConfigRelease 的稳定 ID、外键、基数和不可变性。定义 event-time/ingest-time、原始证据 hash、快照策略、删除墓碑、血缘最小字段和重放边界；AC-13 改为从任一发布重建“当时”的输入、版本、审核和判定结果。

## 4. High findings

### H-01 配置治理缺少发布事务、依赖校验和环境晋级

- **位置**：§4 末段、§5.3、§8“配置与版本管理”、NFR-007、AC-04
- **问题**：有草稿、预览、生效、回滚，但没有定义多个关联配置如何作为一个 release 原子发布，何时生效，正在运行的任务使用旧版还是新版，以及回滚配置是否会撤销已排期内容。
- **具体修复**：引入 `Config Release`：包含依赖图、schema/语义校验、审批、预览样本、计划生效时间、环境晋级、版本钉住和回滚语义；规定任务创建时冻结依赖版本，已开始任务不隐式换版。新增多对象部分失败和定时生效时区验收。

### H-02 RBAC 只有原则，没有可验收的权限模型和职责分离

- **位置**：§4“敏感配置按权限控制”、§8“权限与安全”、NFR-005、§13
- **问题**：未定义角色、资源范围、动作粒度、账号/渠道级隔离、发布审批人与作者是否可同一人、紧急发布、服务身份和权限撤销传播时间。
- **具体修复**：定义 RBAC/ABAC 矩阵，至少覆盖查看证据、编辑配置、发布配置、管理凭证、审核内容、自动发布、手工重放、导出数据；高风险渠道强制 maker-checker；所有授权决策带 workspace/account/resource scope。新增越权、跨工作区、被撤权用户现有会话和服务账号轮换的负向验收。

### H-03 凭证与隐私安全要求不完整

- **位置**：§8“平台连接与鉴权”“权限与安全”、NFR-005
- **问题**：没有规定 secret 不进入业务配置和日志、静态/传输加密、密钥轮换、OAuth token 刷新与撤销、最小权限、敏感内容/个人数据处理、日志脱敏和泄露响应。
- **具体修复**：新增安全基线：集中 Secret Manager 引用、禁止明文回显、轮换/撤销、scopes 最小化、加密与密钥管理、PII 分类和保留、审计日志防篡改、敏感生成上下文隔离。验收 token 过期/撤销、轮换不中断、日志无 secret、无权主体无法解密。

### H-04 失败恢复仅写“重试”，缺少退避、熔断、死信和灾难恢复

- **位置**：§7.1、§8、NFR-002/003/006、AC-12
- **问题**：未定义最大重试、指数退避与 jitter、Retry-After、熔断、毒消息隔离、死信处置、批量重放、RPO/RTO、备份恢复和区域/存储故障。
- **具体修复**：按错误分类定义重试策略、预算和降级；提供 DLQ、人工检查与定向重放；定义关键数据 RPO/RTO、备份频率及恢复演练。新增连接器持续 429、内容任务 poison payload、队列积压、数据库恢复后的端到端验收。

### H-05 没有量化容量、性能、成本预算与 SLO

- **位置**：§9.2、§11、§13“待评审项”
- **问题**：任务频率、发布延迟、规模仍列为待评审；NFR 没有数值。无法据此做分区、队列、限流、存储或模型并发设计，也无法验收“可扩展”。
- **具体修复**：为首期和 12 个月目标给出：来源数、任务数、峰值信号/秒、原始内容大小、事件扇出、生成并发、渠道/账号数、排期峰值、指标回流量、保留期、单任务成本上限；定义可用性、成功率、端到端发现延迟、生成 P95/P99、发布准时率、恢复时间和告警 SLO，并明确测量窗口和排除项。

### H-06 第三方平台能力与合规约束未成为接入契约

- **位置**：§5.1、§7.1、§8 末段、§13
- **问题**：只要求接入评审声明能力和降级，未要求覆盖 ToS、抓取合法性、robots/版权、API 配额、审核政策、地域、数据保存限制、应用审核、Webhook 验签、账号封禁和平台删除请求。
- **具体修复**：为每个平台维护版本化 `Capability & Compliance Profile`：读取/发布/指标能力、配额维度、内容限制、授权主体、Webhook 安全、数据使用与保留、地域、删除同步、降级模式、owner 和复审日期。无法自动发布时必须显式声明 manual-only，而不是让通用流程误判可用。

### H-07 限流与配额没有跨任务的公平调度规则

- **位置**：§4 监测频率/优先级、§7.2 剩余额度、§8“平台连接与鉴权”
- **问题**：没有说明平台、应用、用户、账号、端点等多层配额如何建模，也未定义高优先级任务、回补、饥饿防护和时钟边界。
- **具体修复**：定义 quota scope、共享预算、令牌桶/等价策略、优先级队列、公平性、Retry-After 和配额重置时区；匹配结果记录配额快照。验收多个业务线争用同一配额、配额骤降及午夜重置。

### H-08 内容与外部素材的版权、原创性和删除生命周期不可执行

- **位置**：§5.4、§6.4、§9.2 护栏指标
- **问题**：“通过原创性检查降低抄袭风险”没有阈值、阻断规则、授权状态、引用格式和权利人删除后的级联处理；模型训练/生成供应商是否可接收该素材也未约束。
- **具体修复**：为 Evidence/Insight 增加 license、usage_rights、sensitivity、retention、deletion_state；定义相似度/人工审核阈值、禁止复用字段、引用政策、供应商数据处理限制和删除级联。新增原帖删除、授权撤销、相似度超阈值的验收。

### H-09 验收集缺少契约、并发、故障与安全负向测试

- **位置**：§12 AC-01～AC-14
- **问题**：现有 AC 主要是 happy path，且多使用“不改代码”“可追溯”等不可自动判定表述；没有给定数据、前置状态、预期状态、时间/次数阈值和自动化边界。
- **具体修复**：建立四层验收：连接器/Skill 契约测试、状态机与属性测试、平台沙箱集成测试、端到端故障注入；每项包含 Given/When/Then、观测点和数值门槛。增加无效 schema、版本不兼容、重复消息、乱序回调、超时后成功、权限拒绝、secret 泄漏扫描、限流、部分批量失败、重放和回滚竞态。

## 5. Medium findings

### M-01 批量操作和部分成功语义缺失

- **位置**：§4、§5.2、FR-001、AC-01
- **问题**：批量导入未规定逐条校验、重复项、部分成功、原子性、错误报告和重试。
- **具体修复**：定义 dry-run、逐项结果、批次 ID、去重策略、最大批量和可重放失败项；用“9 成功、1 无权访问”和重复导入验收。

### M-02 删除、停用、归档和依赖占用规则不清晰

- **位置**：§3“统一生命周期”、§4、§6.3
- **问题**：Skill/来源/账号停用时，已排期任务和依赖它们的配置如何处理未说明；删除是否为逻辑删除也未定义。
- **具体修复**：定义引用完整性、deprecate→disabled→archived 生命周期、禁止硬删条件、在途任务策略及替代对象迁移工具。

### M-03 Schema 与配置迁移机制缺失

- **位置**：§4、§8“配置与版本管理”、FR-021
- **问题**：连接器或 Skill 新版本改变配置/输出 schema 时，旧对象如何读取、迁移、回滚未说明。
- **具体修复**：定义 schema registry、兼容等级、迁移脚本与 dry-run、双读/双写窗口、失败回滚和迁移审计；验收旧版本对象批量迁移及部分失败。

### M-04 事件合并、拆分、迟到数据和去重冲突未处理

- **位置**：§5.2、§5.3、FR-002/005
- **问题**：跨来源同一事件可能先被拆成多个，后又需要合并；迟到信号可能改变热度判断。当前只说“去重窗口”。
- **具体修复**：定义 signal→event 的聚合键、合并/拆分权限、canonical event、迟到窗口、水位线、重新计算和 lineage 保留；验收跨语言别名、原帖转发、窗口外迟到信号。

### M-05 审核对象、修改后重审和渠道版本冻结规则缺失

- **位置**：§6.4、§7.1/7.3、NFR-005
- **问题**：没有明确审核的是核心资产还是渠道版本，审核后再生成/编辑是否使批准失效，排期到发布之间是否冻结内容。
- **具体修复**：审核决定绑定不可变 `ContentAssetVersion/ChannelVersion`；任何实质修改自动失效并重审；发布任务保存批准版本 hash。新增审核后编辑、排期后规则变化的验收。

### M-06 指标修订、迟到回流和归因重算机制缺失

- **位置**：§7.3、§9、FR-020/021
- **问题**：平台指标会累计并修订，注册归因会迟到；没有区分 observation time 与 metric window，也未定义去重、校正和重算版本。
- **具体修复**：指标记录采用 append-only observation/version，定义自然键、回补窗口、finalized 状态、归因模型版本和重算审计；报告明确“暂定/最终”。

### M-07 多语言、地区、时区和字符规范未进入通用契约

- **位置**：§4 主题/圈层、§5.1、§7、§9
- **问题**：虽然出现语言、地区，但未规定 Unicode、语言检测、翻译来源、当地发布时间、DST、平台字符计数及地区内容限制。
- **具体修复**：公共对象加入 locale、language、timezone、region 和 normalization version；渠道适配器声明字符/媒体计数规则；所有排期保存 UTC 与展示时区。验收 DST、emoji/中日韩字符和跨语言去重。

## 6. Low findings

### L-01 规范性语言与待决项混杂

- **位置**：全篇，尤其 §8、§11、§13
- **问题**：“应、必须、可、不得”虽已使用，但未定义约束强度；一些决定验收能力的项仍在“待评审项”，文档却标为“需求基线”。
- **具体修复**：定义 MUST/SHOULD/MAY 口径；将阻塞开发的待决项标注 owner、截止日期、决策状态和默认假设。未决的容量/SLO/审批策略关闭前状态应为“草案”或“有条件基线”。

### L-02 需求、原则和验收重复，映射关系却不明确

- **位置**：§3～§8、§10～§12
- **问题**：同一要求在叙述、FR、NFR、AC 中重复，但没有 FR/NFR→AC 的追踪矩阵；例如 NFR-003 只被 AC-12 间接覆盖。
- **具体修复**：保留 §3～§9 作为解释与范围，§10～§11 作为唯一规范性需求；增加 Requirement Traceability Matrix，列 owner、测试层、AC、证据和状态。这样可减少约 300～500 字重复，同时提升可执行性。

## 7. 建议新增的工程验收包

为避免把 PRD 写成实现设计，建议由配套技术规格承接以下交付物，并在 PRD 中将其列为开发准入条件：

1. **Extension Contract Pack**：三类扩展 manifest、schema、错误语义、兼容策略和可复用契约测试套件。
2. **Domain & Lifecycle Pack**：概念数据模型、对象状态机、数据血缘、版本快照和保留/删除规则。
3. **Control Plane Pack**：配置 release、依赖校验、审批、环境晋级、RBAC、审计与 secret 管理。
4. **Reliability Pack**：限流、重试、熔断、DLQ、幂等、灾备、SLO、容量和成本预算。
5. **Platform Profile Pack**：每个外部平台的能力、配额、合规、降级与测试沙箱说明。
6. **Verification Pack**：需求追踪矩阵、契约/集成/E2E/故障注入/安全测试及量化通过门槛。

## 8. 文档结构与表达观察

本文面向产品、架构、研发、测试和运营负责人，用于对“什么变化必须配置化、如何证明扩展成功”形成共同基线；最接近**战略/上下文金字塔**结构。整体顺序合理，示例和业务边界应保留。

高影响结构修复只有两项：

| Pass | Original Text | Revised Text | Changes |
