# Event 综合热度与传播覆盖规则 v1

## 1. 文档目的

本规则供热点情报 Agent、后端服务和前端原型共同读取，用于生成 Event Context Pack 中的：

- 监测范围内综合热度；
- 传播覆盖。

本规则只描述系统已接入数据范围内的公开传播表现，不判断事实可信度，也不决定下游是否生产内容。

## 2. 适用数据范围

Event 只读取已经绑定到当前 Event 的数据。

MVP 可读取：

- X 热搜榜快照；
- X 帖子发布时间；
- X 帖子的浏览、点赞、转发和回复数据快照；
- 与 Event 直接相关的独立内容数量；
- X 热搜榜明确标注的榜单地区；
- 内容语言；
- 发布账号类型。

当前不读取：

- 未绑定到 Event 的普通讨论；
- Future Event 排期产生的“热度”；
- 未绑定到 Event 的 YouTube 爆款视频；
- 根据账号所在地、语言或个人简介推测的受众国家。

只有当 YouTube 视频能够可靠绑定到 Event 并具有可用数据快照时，才能将 YouTube 纳入该 Event 的综合热度与传播覆盖。

## 3. 必要时间字段

每次计算必须保留：

- `source_published_at`：原始帖子或视频的发布时间；
- `snapshot_at`：系统读取公开数据的时间；
- `previous_snapshot_at`：上一次有效快照时间，可空；
- `heat_updated_at`：本次综合热度完成计算的时间。

用于比较的快照必须来自不同的实际采集批次，且后一快照时间晚于前一快照。具体抓取频率由任务配置决定，本规则不固定分钟或小时级间隔。

只比较时间顺序正确、字段口径一致的有效快照：

- 两次快照可以判断公开数据相对上升或下降；
- 连续三次快照可以比较前后两个观察区间的增长速度，从而判断增速加快或减慢。

术语统一如下：

- 相邻快照：当前快照与上一张成功快照；
- 一个观察区间：两张相邻成功快照之间的时间；
- 两个连续观察区间：由三张连续成功快照形成的两个相邻时间区间；
- 失败快照：采集失败或关键数据缺失的快照，不参与比较，也不视为离榜或降温。

## 4. 综合热度输出

每个 Event 只输出一个当前主状态：

- `early_burst`：早期爆发；
- `rapid_growth`：快速增长；
- `sustained_hot`：持续热门；
- `cooling`：开始降温；
- `insufficient_data`：数据不足。

同时输出：

- 中文状态名称；
- 一句话热度摘要；
- 主要判断依据；
- 判断依据对应的 Signal、快照或榜单记录 ID；
- 数据覆盖平台；
- 热度更新时间。

状态依据必须来自当前 Event 已绑定的数据。每项依据至少记录来源类型、记录 ID、当前值、比较值和快照时间；无法提供依据时输出数据不足。

## 5. 综合热度判断流程

严格按照以下顺序执行，每次命中后停止：

1. 检查是否数据不足；
2. 检查是否早期爆发；
3. 检查是否快速增长；
4. 检查是否开始降温；
5. 检查是否持续热门；
6. 均未命中时输出数据不足，不强行分类。

## 6. 数据不足

### 定义

当前公开数据不足以判断 Event 所处的传播阶段。

### 命中条件

满足任一条件即输出数据不足：

- 没有有效公开数据快照；
- 只有一条低表现 Signal，且未命中任何早期爆发信号；
- 代表内容缺少公开流量数据，同时没有热搜榜数据；
- 快照无法与当前 Event 可靠绑定；
- 数据字段明显缺失或相互冲突。

如果本轮采集失败，但已经存在上一张成功快照，则保留上一版热度状态，同时标记“等待新快照”，不得将采集失败解释为降温。

### 输出示例

> 当前综合热度：数据不足。现有来源缺少公开流量和榜单数据，暂时无法判断传播阶段。更新于 08/27 14:18。

## 7. 早期爆发

### 定义

代表内容发布不久，就获得明显的公开流量或榜单表现。

### 必要条件

- 当前只有首次有效快照，尚不存在可比较的历史快照；
- 代表内容在首次有效快照中已经命中至少一个爆发信号。

产生第二次有效快照后，不再使用“早期爆发”规则，转入相邻快照比较，判断是否为快速增长、持续热门或开始降温。

### 爆发信号

必要条件成立后，满足以下任一信号即命中：

- X Trend 空降 Worldwide 或美国榜 Top 5；
- X Trend 在首次有效快照中进入至少两个地区榜单；
- Topic Circle 来源命中现有 `Traffic Spike` 规则。

### Traffic Spike 完整口径

`Traffic Spike` 表示：一条 Topic Circle 帖子在发布后的当前阶段，公开表现至少达到该账号日常水平的 3 倍，并且位于该账号近期同帖龄帖子的前 5%。

综合热度 Agent 必须按本节直接判断，不依赖理解其他文档中的术语。

命中条件必须同时成立：

- `Tmax ≥ 3`；
- 该帖子进入账号近期相同帖龄表现前 5%。

### 输入数据

判断一条帖子是否命中 `Traffic Spike`，必须取得：

- 当前帖子 ID 和发布账号 ID；
- 当前帖子发布时间和本次快照时间；
- 当前帖子的浏览量；
- 该账号最近 30 条有效历史帖子；
- 历史帖子在相近帖龄时的浏览量快照。

有效历史帖子是指能够取得发布时间及相近帖龄浏览量快照的帖子。删除、采集失败或缺少可比较浏览量的帖子不进入基线。

### 公开表现指标选择

`Traffic Spike` 只使用浏览量判断。当前帖子没有浏览量，或可比较的有效历史帖子少于 30 条时，输出“数据不足”。点赞、回复、转发和引用不参与本规则计算。

### 计算定义

- 当前帖龄：从帖子实际发布时间到本次快照时间的时长；
- 相近帖龄：对每条历史帖子，选择其发布后时长与当前帖龄最接近的一张成功快照；
- 账号历史基线：最近 30 条有效历史帖子在相近帖龄时浏览量的中位数；
- `Tmax`：当前帖子的浏览量 ÷ 账号历史基线；
- 同帖龄百分位：以这 30 条有效历史帖子的相近帖龄浏览量形成分布；当前浏览量达到或超过该分布的第 95 百分位，即判定为“位于前 5%”。

示例：当前帖子在本次快照时有 30 万浏览；该账号最近 30 条有效帖子在相同帖龄下的浏览量中位数是 8 万，则 `Tmax = 30 ÷ 8 = 3.75`。如果当前帖子同时位于这组历史表现的前 5%，则命中 `Traffic Spike`。

### Agent 执行步骤

1. 计算当前帖龄；
2. 为该账号最近的历史帖子选择相近帖龄的成功快照；
3. 排除无浏览量或采集失败的数据，并取得 30 条有效历史帖子；
4. 计算这 30 条历史帖子的浏览量中位数作为账号历史基线；
5. 计算 `Tmax`；
6. 计算当前浏览量在历史分布中的百分位；
7. 仅当 `Tmax ≥ 3` 且百分位位于前 5% 时，输出“命中”；
8. 任一必要输入不足时输出“数据不足”，不得输出“未命中”。

### 输出字段

每次判断必须保存：

- `traffic_spike_status`：命中、未命中或数据不足；
- `metric_type`：固定为浏览量；
- `current_value`：当前帖子公开表现；
- `baseline_median`：账号历史基线；
- `tmax`：当前值与基线的倍数；
- `percentile`：当前帖子在同帖龄历史表现中的百分位；
- `sample_size`：实际参与比较的有效历史帖子数量；
- `current_post_age`：当前帖子在快照时的帖龄；
- `snapshot_at`：本次判断使用的快照时间。

完成条件：Agent 能够输出命中状态及以上全部依据字段；缺少必要字段时明确输出数据不足。

### 输出示例

> 当前综合热度：早期爆发。代表内容在首次有效快照中命中 Traffic Spike，并空降地区热搜榜前列。更新于最近快照时间。

## 8. 快速增长

### 定义

至少两次有效快照显示，Event 的流量、讨论或榜单表现仍在明显增加。

### 必要条件

- 至少存在两次有效快照；
- 两次快照来自不同的实际采集批次；
- 最近快照晚于首次来源发布时间。

### 增长信号

满足必要条件后，命中以下任一信号即进入快速增长：

- X Trend 相邻两次成功快照排名上升至少 10 位，即命中现有 `Fast Rising` 规则；
- 热搜上榜地区较上一快照增加；
- Topic Circle 的 `Traffic Spike` 从上一快照未命中变为当前快照命中；
- Topic Circle 在当前快照首次命中现有圈内共振或跨圈扩散规则。

圈内共振和跨圈扩散的具体阈值直接读取《热点来源与 Event 触发规则 v2》，本规则不重复维护。

### 输出示例

> 当前综合热度：快速增长。X Trend 较上一张成功快照上升 12 位，并新增 1 个上榜地区。更新于最近快照时间。

## 9. 持续热门

### 定义

Event 已经过早期阶段，没有继续快速增长，但仍连续保持较高公开关注度。

### 必要条件

- 至少存在两张相邻成功快照；
- 未命中快速增长或开始降温。

### 热门信号

满足必要条件后，命中以下任一信号即进入持续热门：

- 当前快照与上一张成功快照均保持 Top 5；
- 当前快照与上一张成功快照均保持至少两个地区上榜；
- 当前快照与上一张成功快照均命中 `Traffic Spike`；
- 当前快照与上一张成功快照均命中圈内共振或跨圈扩散规则。

“热度平稳”属于持续热门，不单独输出状态。

### 输出示例

> 当前综合热度：持续热门。事件在相邻两张成功快照中均保持 Top 5，并持续在至少两个地区上榜。更新于最近快照时间。

## 10. 开始降温

### 定义

最近的公开传播表现相比此前观察周期明显减弱。

### 判断条件

命中以下任一可验证条件即进入开始降温：

- 上一张成功快照处于 Top 5，当前快照已不在 Top 5，且排名没有命中 `Fast Rising`；
- 热搜上榜地区数量较上一张成功快照减少；
- Event 退出上一张成功快照所在的全部热搜榜；
- `Traffic Spike`、圈内共振或跨圈扩散从上一张成功快照命中变为当前快照未命中；
- 至少存在三个连续成功快照，且最近观察区间的单位时间新增流量低于前一观察区间。

仅有两个流量快照时，可以判断累计数据增长，但不能判断增长速度正在减缓。使用“单位时间新增流量下降”判断降温时，必须至少有三个快照。

单一指标回落但其他热度信号仍然成立时，继续输出持续热门，并在判断依据中记录回落指标，不切换为开始降温。

### 输出示例

> 当前综合热度：开始降温。最近观察区间的新增流量明显低于前一观察区间，同时热搜上榜地区减少。更新于最近快照时间。

## 11. Event 级聚合规则

一个 Event 可以绑定多条帖子、多个热搜词和多个来源子包。综合热度必须在 Signal 级判断完成后再聚合到 Event 级。

聚合步骤：

1. 对每条已绑定 Signal 读取当前命中的客观热度标签；
2. 排除失败快照、重复内容和未绑定内容；
3. 按判断顺序计算 Event 当前唯一主状态；
4. 选择最多两项可核验依据生成热度摘要；
5. 保存被选依据的 Signal ID、快照 ID 或榜单记录 ID。

同一 Event 内不同 Signal 状态不一致时，按以下优先级输出：

> 快速增长 → 早期爆发 → 持续热门 → 开始降温 → 数据不足

“开始降温”只有在当前 Event 不再存在快速增长、早期爆发或持续热门依据时才可输出。

## 12. 热度摘要格式

热度摘要只写一句话，格式为：

> 当前阶段 + 最多两项主要依据 + 更新时间。

优先选择最容易核验的依据：

1. 热搜排名变化；
2. 上榜地区变化；
3. 代表内容公开数据变化；
4. 独立相关内容数量变化。

不输出综合分数，不展示内部权重，不使用“全网热度”。

## 13. 传播覆盖输出

传播覆盖只回答：

- 在什么平台传播；
- 由什么类型的账号传播；
- 使用什么语言传播；
- 是否存在来源明确标注的热搜上榜地区。

输出字段：

- `platforms`：实际提供该 Event 数据的平台；
- `primary_language`：主要内容语言；
- `other_languages`：其他已观察语言，可空；
- `account_types`：已观察到的账号类型；
- `trending_regions`：来源明确标注的热搜上榜地区，可空；
- `coverage_updated_at`：传播覆盖更新时间。

## 14. 平台规则

只展示实际提供当前 Event 数据的平台。

- 只有 X 数据时，输出 `X`；
- 只有 YouTube 数据时，输出 `YouTube`；
- 两个平台均存在已绑定数据时，输出 `X、YouTube`。

系统其他模块接入某个平台，不代表当前 Event 已覆盖该平台。

## 15. 账号类型

### 官方账号

公司、产品、政府、机构、组织或赛事的正式账号。

### 核心人物账号

与事件主体直接相关并能够提供一手信息的重要个人，例如创始人、CEO、政治人物、官方发言人或赛事参与者。

### 媒体账号

以新闻采编和事实报道为主要功能的媒体或新闻机构账号。

### 行业或专业账号

长期发布某个行业、研究领域或专业主题内容的研究机构、分析师、专业社区、行业数据账号或垂直领域专家。

### 创作者或意见账号

以个人内容创作、评论和影响力传播为主的创作者、KOL或评论型自媒体账号。

### 普通用户

不属于以上类型的一般个人账号。

### 分类优先级

一个账号同时满足多个类型时，只保留优先级最高的主类型：

> 官方账号 → 核心人物账号 → 媒体账号 → 行业或专业账号 → 创作者或意见账号 → 普通用户

`Topic Circle` 是发现路径，不是账号类型。

### 无法分类时

账号资料不足、身份存在冲突或没有可靠分类依据时，输出“待识别”，不得为了填充字段推断为普通用户或其他类型。

每个账号类型必须保留分类依据，例如认证主体、账号简介、机构官网关联或系统已有账号档案。没有依据时一律使用“待识别”。

## 16. 语言规则

语言字段描述内容使用的语言，不描述受众国家。

- `primary_language`：有效Signal数量最多的内容语言；
- `other_languages`：除主要语言外，在独立有效Signal中重复出现的语言；
- 只有一条内容时，直接使用该内容语言作为主要语言；
- 多种语言的有效 Signal 数量并列最多时，全部保留为主要语言，不强行选择一种；
- 无法可靠识别时输出“暂未识别”。

系统不得将英语表达为“美国英语区”，也不得根据账号所在地推断内容实际触达国家。

## 17. 热搜上榜地区

地区不是传播覆盖的通用推断字段。

只有来源本身明确提供地区榜单时，才写入 `trending_regions`，例如：

- 美国热搜榜第 4；
- 英国热搜榜第 8；
- 日本地区 YouTube 热门榜。

字段名称统一为“热搜上榜地区”。不得改写为传播国家、受众国家、主要市场或用户所在地。

没有明确地区榜单数据时输出：

> 热搜上榜地区：暂无数据

## 18. 传播覆盖展示格式

有地区榜单数据：

> 传播覆盖  
> 平台：X  
> 主要语言：英语  
> 传播账号：媒体账号、行业或专业账号  
> 热搜上榜地区：美国、英国  
> 数据更新：08/27 14:18

没有地区榜单数据：

> 传播覆盖  
> 平台：X  
> 主要语言：英语  
> 传播账号：媒体账号、行业或专业账号  
> 热搜上榜地区：暂无数据  
> 数据更新：08/27 14:18

## 19. Agent 硬性约束

Agent 必须：

- 只读取已经绑定到当前 Event 的数据；
- 为每个判断保留对应快照或榜单依据；
- 每次只输出一个综合热度主状态；
- 数据不足时明确输出“数据不足”；
- 将 Topic Circle 记录为发现路径，而不是账号类型；
- 将来源发布时间、快照时间和热度更新时间分别保存；
- 将地区限定为来源明确提供的“热搜上榜地区”。
- 本轮采集失败时保留上一张成功快照对应的热度状态，并标记“等待新快照”；
- 账号类型缺少可靠依据时输出“待识别”；
- 多种语言并列为主要语言时全部保留。

Agent 不得：

- 使用热度证明事件事实为真；
- 根据语言、账号所在地或账号简介推断受众国家；
- 将未绑定的 YouTube 视频计入 Event；
- 将 Future Event 排期计入当前传播热度；
- 在规则配置缺失时自行发明阈值；
- 为了填充字段强行判断传播阶段。

## 20. 验收标准

以下条件全部满足才算完成：

1. 每个 Event 只出现一个热度主状态；
2. 热度状态具有可追溯的数据依据和更新时间；
3. 两个快照不能用于计算传播加速度或流量减速；
4. 没有足够数据时输出数据不足；
5. 平台只包含实际绑定到 Event 的平台；
6. 账号类型符合六类定义和优先级，无法可靠分类时输出“待识别”；
7. Topic Circle 不出现在账号类型中；
8. 语言不被改写为国家或受众地区；
9. 没有地区榜单数据时不生成传播国家；
10. 热度摘要不超过一个主状态和两项主要依据。
11. 每次热度判断均保存对应的 Signal ID、快照 ID 或榜单记录 ID；
12. 采集失败不会触发降温，也不会用数据不足覆盖上一版有效状态；
13. 同一 Event 内不同 Signal 状态冲突时，严格执行 Event 级聚合优先级；
14. 多种语言的有效 Signal 数量并列最多时，不强行选择单一主要语言。
