# UX/UI 无障碍审查

> 审查日期：2026-08-10  
> 范围：`docs/ux-ui/ux-01`—`ux-07`、现有可点击原型；必要处对照 PRD `NFR-06`。  
> 方法：按 WCAG 2.2 AA 的键盘、焦点、语义、动态状态、非文本内容、可重排和色彩不唯一性要求，审查**设计交接文档是否足以让实现者不猜**。本报告不测试浏览器实现，因而“缺失”表示设计契约缺失，而非断言最终页面已经不合规。

## 总体结论

**结论：需要整改后才能把 UX/UI 当作无障碍实施基线。** 文档已经有正确的基线意识：要求核心操作键盘可达、状态不只依赖颜色、表格与对话框可访问、异常使用 live region，见 [ux-07 §7.1](./ux-07-accessibility-and-validation.md)。但这些要求尚未下沉到组件、页面和流程的交互契约；开发无法据此确定焦点如何移动、图表如何被读屏使用、动态数据何时播报、抽屉如何关闭及恢复焦点。

发现汇总：**0 个严重（Critical）、6 个高（High）、8 个中（Medium）、3 个低（Low）**。优先关闭高优先级问题，尤其是热点雷达、未来事件中心、Event/Fact/Evidence/监测图这三个 M1/M2 工作区。

## 高优先级问题

### A11Y-01 — 交互组件没有键盘操作契约

- **严重级别：高**
- **位置：** [ux-06 §6.3，CP-01—CP-24](./ux-06-visual-design-and-components.md)；[ux-04 §4.4](./ux-04-pages-and-wireframes.md)“列表支持紧凑表格、展开行与右侧预览”；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)只写“核心操作键盘可达率 100%”。
- **问题：** 组件目录只定义业务字段，没有定义 Tab 顺序、Enter/Space、方向键、Esc、选中状态、禁用原因或快捷键。雷达筛选、Top 10 行、Candidate 合并/拆分、Task Plan 卡、批量审核、工作台视图切换、展开行和异常恢复都因此没有统一实现依据。
- **修复：** 在 `ux-06` 为每个可操作 CP 增加“语义元素 / 键盘 / 焦点 / 状态播报”四列。默认使用原生 `button`、`a`、`input`、`select`；只有确需复合控件时才规定 ARIA 模式。例如：筛选为可多选的复选框组或单选组；工作台切换为 `tablist`；排行榜行使用整行链接或“查看 Candidate”按钮，不能使用仅有 click 的卡片；展开行的 `aria-expanded`、`aria-controls` 和展开内容焦点顺序必须明确。将键盘走查扩展为 PG-03、PG-04、PG-16、PG-07 和 PG-13 的逐项验收。

### A11Y-02 — Evidence 来源抽屉/对话框缺少完整焦点生命周期

- **严重级别：高**
- **位置：** [ux-04 §4.4](./ux-04-pages-and-wireframes.md)要求 Evidence 可点击并打开来源信息；[ux-06 §6.3，CP-24](./ux-06-visual-design-and-components.md)定义“Evidence 来源抽屉”；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)仅笼统要求“对话框正确管理焦点”。
- **问题：** 这是核验证据的核心路径，但没有规定打开后焦点放在哪里、焦点是否被限制在 modal 内、Esc/关闭按钮/遮罩如何关闭、关闭后回到原 Evidence 触发器、抽屉标题和内容如何被读屏命名。当前 HTML 原型虽用了 `role="dialog"` 与 `aria-modal`，但其交互代码只处理点击关闭，未实现 Esc、焦点转移、焦点圈定或返回触发点，说明该缺口会直接传递到实现。
- **修复：** 新增“抽屉与对话框”交互原语：打开时将焦点移到标题或首个可操作元素；modal 中 Tab/Shift+Tab 循环；Esc 与关闭按钮均可关闭；关闭后恢复至发起的 Evidence 链接；使用 `aria-labelledby`、可选 `aria-describedby`；加载、来源不可访问、无权限和外链打开分别有可感知状态。若 1280–1679px 的上下文栏也改为抽屉，明确其是非模态可关闭侧栏还是模态对话框，不能混用。

### A11Y-03 — 热点雷达、事件监测图没有非视觉等价物

- **严重级别：高**
- **位置：** [ux-04 §4.4，M1/M2 数据可视化要求](./ux-04-pages-and-wireframes.md)第 60—63 行；[ux-06 §6.3，CP-21/22/23](./ux-06-visual-design-and-components.md)；[ux-06 §6.5](./ux-06-visual-design-and-components.md)。
- **问题：** 文档要求 Top 10、热度变化、跨地区扩散、时间序列/柱状热度图和关键节点，但没有说明标题、摘要、数据表、点位/柱的可访问名称、时间/数值单位、图例、键盘探索或“热度不等于事实”的读屏表达。只说“图表提供数值、时间范围、来源和口径”不足以使读屏用户理解趋势和异常。
- **修复：** 为 CP-21 和 CP-23 写专门的“图表无障碍模式”：
  1. 每张图必须有可见标题、简短趋势摘要（例如“10:00—10:50 热度从 28 升至 96，10:40 出现官方 Evidence”）和数据新鲜度；
  2. 提供“查看数据表”切换，表含时间、热度、地区数、关键节点、来源/口径；
  3. 图形作为补充，SVG/canvas 需有等价文本；若点位可操作，定义方向键移动、当前点位名称与选中提示；若不可操作，图形设为装饰、完整数据由表承载；
  4. 热度、置信度、Fact 状态在结构和文案中分开，不能让颜色或图层承担唯一解释；
  5. 以真实屏幕阅读器任务验证“指出峰值、关键 Evidence、当前事实状态和响应窗口”。

### A11Y-04 — 数据密集表格、排行榜和比较表没有可访问表格规则

- **严重级别：高**
- **位置：** [ux-04 §4.4](./ux-04-pages-and-wireframes.md)“紧凑表格、展开行与右侧预览”；[ux-06 §6.3，CP-13、CP-21](./ux-06-visual-design-and-components.md)；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)只写“表格具有标题、排序状态与行上下文”。
- **问题：** 热点雷达 Top 10、KOL 比较、任务/回执看板是高密度表格，但没有列出表格标题、列标题/行标题、排序按钮的名称和当前方向、筛选结果数、展开行关系、横向滚动提示、列显隐的保存/重置和批量选择的读屏反馈。开发容易把数据表实现成视觉卡片，或让读屏逐单元失去行上下文。
- **修复：** 在 CP-13、CP-21 和页面规格中规定：使用原生 `table` 处理真正的二维数据；`caption` 说明集合和时间范围；`th scope="col"/"row"`；排序列为有状态的按钮并播报“按热度降序”；筛选变更后以 `role=status` 报告“已显示 10/42 条”；展开按钮含对象名称和 `aria-expanded`；批量操作前后播报选中数量、范围和风险拆分。必要的宽表允许局部横向滚动，但要有可见提示、可聚焦滚动容器和列优先级；不能把整页横向滚动当作解决方案。

### A11Y-05 — 动态状态的播报策略缺少事件级定义

- **严重级别：高**
- **位置：** [ux-05 §5.5—5.6](./ux-05-interaction-and-states.md)；[ux-05 §5.9](./ux-05-interaction-and-states.md)；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)第 9 行。
- **问题：** 文档只区分“高风险升级使用 live region、正常时间线不持续打断”，没有定义哪些具体变化是 `status`（礼貌播报）、哪些是 `alert`（立即播报）、哪些应只写入时间线，以及消息是否会重复。热点雷达的刷新、来源延迟、Candidate 合并、Event 置信度/窗口更新、Telegram 回写失败、批量审核结果、回执延迟、自动停发都可能造成遗漏或读屏噪声。
- **修复：** 建立“动态事件播报表”，至少包含：触发事件、可见文案、ARIA 策略、是否移动焦点、去重/节流规则、恢复路径。例如：
  - 雷达普通刷新：不自动播报，提供“数据已更新于 10:50”的可查询状态；
  - 当前筛选来源失效、响应窗口不足、交付物因事实变化过期、Telegram 回写失败、拒绝/退订导致停发：`role=alert`，但每个对象只播报一次并包含对象名和操作；
  - 筛选、排序、批量选择、重试成功：`role=status`，不抢焦点；
  - 自动跳转、刷新、关闭/再激活：不得无提示改变用户正在阅读的内容。

### A11Y-06 — “小于 1280px 不支持”与放大/重排要求冲突

- **严重级别：高**
- **位置：** [ux-01 §1.4](./ux-01-design-goals-and-foundations.md)规定“1280px 最低完整宽度”；[ux-06 §6.4](./ux-06-visual-design-and-components.md)规定 `<1280px 不在正式支持范围`，同时有三栏和侧栏布局。
- **问题：** 桌面优先不等于可以拒绝浏览器放大后的布局。用户在 1280px 宽度以 400% 放大时，可用 CSS 宽度约为 320px；若页面整体不重排，会违反可重排要求，也会让低视力用户失去核心操作。
- **修复：** 将“最低完整宽度”改为“推荐密度”，并新增 200%/400% 浏览器缩放验收：主导航可折叠，右侧上下文栏改为可访问抽屉，非必要列隐藏/可配置，表格与图表允许**局部**双向滚动并提供数据表替代；正文、审核操作、异常接管、Evidence 抽屉和窗口信息在 320 CSS px 下无需整页横滚完成。若确有不能重排的专业分析视图，明确例外理由和替代入口。

## 中优先级问题

### A11Y-07 — 焦点可见性与页面跳转后的焦点落点未定义

- **严重级别：中**
- **位置：** [ux-07 §7.1](./ux-07-accessibility-and-validation.md)第 6 行；[ux-04 §4.5](./ux-04-pages-and-wireframes.md)的深链/返回规则；[ux-06](./ux-06-visual-design-and-components.md)未定义 focus token。
- **问题：** 只要求“焦点顺序与视觉顺序一致”，没有规定可见焦点样式、最低对比、路由切换后落点、返回后恢复列表行/滚动时的焦点、跳过导航链接。
- **修复：** 在视觉变量中加入 `focus-ring` 及其与相邻色的对比要求；全局提供“跳到主内容”；页面内跳转后将焦点置于 `h1` 或对象标题，关闭抽屉/返回列表后恢复触发元素；禁止仅用颜色、阴影或鼠标 hover 表示焦点。以仅键盘完成“雷达→Event→Evidence→返回原排行榜行”验收。

### A11Y-08 — 颜色规则没有落实到可测的组合、非颜色标识和强制颜色模式

- **严重级别：中**
- **位置：** [ux-06 §6.1—6.2](./ux-06-visual-design-and-components.md)；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)第 7、10 行。
- **问题：** 已有色彩 token 和“文字、图标/形状和颜色”原则，但没有指定各 token 与背景/按钮/焦点环的对比组合，也没有定义成功、警告、风险、AI、数据新鲜度和状态图例的文字标签/图标名称。高密度雷达和事件图尤其容易退化为红绿/升降色。
- **修复：** 为每个加载关键组合列出前景/背景、最小对比和允许用途；小字号文字至少 4.5:1，UI 边界、图标和焦点指示至少 3:1；所有涨跌、Fact 状态、数据源健康、置信度和图表系列同时有文字/形状/模式或可见图例；增加 Windows 高对比/forced-colors 及不依赖背景色的验收样本。

### A11Y-09 — 未来事件中心缺少可访问的时间、日历和状态模式

- **严重级别：中**
- **位置：** [ux-04 §4.1，PG-16](./ux-04-pages-and-wireframes.md)；[ux-04 §4.4](./ux-04-pages-and-wireframes.md)第 61 行；[ux-06 §6.3，CP-22](./ux-06-visual-design-and-components.md)；[ux-03 §3.3](./ux-03-user-flows.md)。
- **问题：** 文档规定“日历/列表、预计发生时间、监测窗口、预案、负责人和状态”，但没有规定采用可键盘操作的日历网格还是优先列表、日期/时区的读法、改期/取消后的状态播报、窗口到达时的焦点与通知行为。仅以视觉时间轴呈现会使读屏用户难以比较先后和发现时区。
- **修复：** 默认提供排序列表（发生时间、时区、阶段、窗口、负责人、匹配状态）并把日历作为辅助视图；如果使用日期选择器，采用已验证的 dialog/grid 模式并定义方向键、PageUp/PageDown、月份切换和取消；所有时间使用明确时区与相对/绝对时间并列；改期/取消和窗口到达写入动态事件播报表，历史版本可由键盘进入。

### A11Y-10 — Evidence、Fact 与 Event Card 的语义层级和关系未指定

- **严重级别：中**
- **位置：** [ux-03 §3.4](./ux-03-user-flows.md)；[ux-04 §4.4](./ux-04-pages-and-wireframes.md)第 62 行；[ux-06 §6.3，CP-05、CP-24](./ux-06-visual-design-and-components.md)。
- **问题：** “Fact → 支持/质疑/排除 Evidence”是核心认知结构，但没有定义读屏阅读顺序、Fact 标题层级、Evidence 关系文案、置信度的数字/等级、版本差异或冲突的分组方式。读屏用户可能只听到连续来源标题，听不到来源支撑的是哪一事实、为何不可用于发布。
- **修复：** CP-05 规定每个 Fact 是具名 `section`，标题为可导航 heading；其下 Evidence 列表项必须以“支持/质疑/排除 + Fact 名称 + 来源 + 可信等级 + 采集时间”命名；置信度同时提供百分比、等级、更新时间和依据入口；冲突以可展开分组呈现并在组标题说明“2 个支持、1 个质疑”；Event Card 版本变化提供结构化差异摘要而非仅颜色 diff。

### A11Y-11 — 权限受限和数据不可用的读屏文案不足

- **严重级别：中**
- **位置：** [ux-05 §5.9](./ux-05-interaction-and-states.md)“权限受限”；[ux-04 §4.5](./ux-04-pages-and-wireframes.md)“只显示最少上下文和申请入口”；[ux-07 §7.3](./ux-07-accessibility-and-validation.md)。
- **问题：** 没有规定被隐藏字段、无法访问的 Evidence、来源故障、空结果、筛选无结果如何在结构上区分。若用禁用按钮或空白区域，读屏用户无法理解是“没有数据”、还是“没有权限”、还是“连接器故障”。
- **修复：** 为每类状态写固定标题、原因、影响范围、下一步和不泄露敏感值的文案。不可用操作要么不渲染并说明原因，要么使用原生 disabled 且在相邻说明中提供不可用原因；权限申请入口必须是可聚焦链接/按钮。将“无权查看原始来源但可看到已脱敏摘要”纳入 Evidence 抽屉状态。

### A11Y-12 — 通知、Toast 与错误恢复的视觉/读屏行为没有分工

- **严重级别：中**
- **位置：** [ux-05 §5.9](./ux-05-interaction-and-states.md)要求不用瞬时 toast 承载唯一结果；[ux-06 §6.3，CP-17](./ux-06-visual-design-and-components.md)。
- **问题：** 方向正确，但没有定义 toast 是否存在、自动消失多久、是否可聚焦、错误卡出现位置、重试后状态在哪里被确认。尤其是 Telegram 回写失败、人工发布验证失败和回执延迟，若信息只在时间线更新，焦点不在该区域的用户会错过。
- **修复：** 建立通知等级：确认性通知仅 `role=status`、可消失且不含唯一操作；阻塞异常固定为页面内异常卡/通知中心项，具有标题、对象、影响和主操作；成功/失败后不要自动抢焦点，但提供“查看结果”链接；重试完成使用 status 播报并更新同一异常卡，避免新旧消息并存。

### A11Y-13 — 响应窗口倒计时及自动更新没有减少动态效果和可控性规则

- **严重级别：中**
- **位置：** [ux-05 §5.6](./ux-05-interaction-and-states.md)；[ux-06 §6.3，CP-19](./ux-06-visual-design-and-components.md)；[ux-07 §7.1](./ux-07-accessibility-and-validation.md)只笼统提及减少动画。
- **问题：** 响应窗口是时间敏感信息。若每分钟刷新/动画或越过阈值变色，读屏可能不断播报，认知障碍用户也难以维持当前上下文；文档没有规定阈值、暂停、绝对时间或过期后的稳定状态。
- **修复：** 显示绝对截止时间与相对剩余时间；常规倒计时不自动播报或动画；仅在预设阈值（例如 15/5/0 分钟）以可去重 alert 报告，并提供静音/管理提醒入口；`prefers-reduced-motion` 下取消数字滚动、闪烁和自动滚动，过期后使用稳定文案“已过期，需重新预检”。

### A11Y-14 — 外部连接器跳转缺少可感知的新窗口和返回上下文规则

- **严重级别：中**
- **位置：** [ux-04 §4.5](./ux-04-pages-and-wireframes.md)第 67 行；[ux-05 §5.4—5.5](./ux-05-interaction-and-states.md)。
- **问题：** 规定外部 Telegram、Google Docs、X “在新标签打开”，但没有要求链接文本或辅助说明告知“将在新标签打开”、目标平台、是否会暴露数据，或用户回到系统后如何重新聚焦并读取权威状态。
- **修复：** 外链使用真实链接，名称包含目标和新窗口提示（可见图标并带等价文本）；打开前说明这是协作/发布出口而非系统状态变更；返回系统时保留对象上下文，必要时在状态区域显示“外部操作尚未回写，当前权威状态为……”。

## 低优先级问题

### A11Y-15 — 标题、landmark 和跳过重复内容未纳入共同页面框架

- **严重级别：低**
- **位置：** [ux-04 §4.4](./ux-04-pages-and-wireframes.md)第 56 行；[ux-02 §2.1—2.3](./ux-02-information-architecture.md)。
- **问题：** 已定义全局导航、对象头部、主任务区和上下文栏，但未规定 `header/nav/main/aside` landmark、唯一 `h1`、区块 heading 层级和跳过导航。
- **修复：** 给共同页面框架新增语义骨架：每页一个 `h1`，全局导航为具名 `nav`，主任务区为 `main`，上下文为具名 `aside`，对象链为有 `aria-label` 的 breadcrumb，并提供“跳到主内容”。

### A11Y-16 — 可编辑/AI 改写的输入辅助和错误规则缺失

- **严重级别：低**
- **位置：** [ux-05 §5.3](./ux-05-interaction-and-states.md)“小改直接编辑、结构性修改提交意见”；[ux-06 §6.3，CP-06、CP-08](./ux-06-visual-design-and-components.md)。
- **问题：** 没有输入标签、必填提示、字数/格式/预检错误关联、AI 改写前后差异的读屏摘要和撤销规则。
- **修复：** 每个输入有持久 label、说明和 `aria-describedby`；校验失败将焦点移到错误摘要并连接字段级错误；AI 生成新版本时播报版本号、变更摘要和需要重新审核的原因，差异视图同时提供线性文本模式。

### A11Y-17 — 验收用例覆盖面不足，无法证明 M1/M2 无障碍闭环

- **严重级别：低**
- **位置：** [ux-07 §7.2](./ux-07-accessibility-and-validation.md)VT-01—VT-10；[ux-07 §7.5](./ux-07-accessibility-and-validation.md)。
- **问题：** 现有唯一明确键盘用例是 VT-10（审核和异常接管）。没有验证用户能否键盘/读屏完成雷达筛选、阅读图表、操作未来事件、打开 Evidence、识别来源延迟或在 400% 放大下完成任务。
- **修复：** 增加 VT-11—VT-15：
  - VT-11：仅键盘筛选热点雷达、排序 Top 10、进入 Candidate；
  - VT-12：读屏从 Event 中指出确认/待确认 Fact、支持/质疑 Evidence、置信度与窗口；
  - VT-13：在 Event 监测图的数据表中指出峰值和关键节点；
  - VT-14：键盘创建/改期未来事件并确认时区、窗口和状态；
  - VT-15：在 200%/400% 放大和 Windows 强制颜色模式下完成上述任一主链。
