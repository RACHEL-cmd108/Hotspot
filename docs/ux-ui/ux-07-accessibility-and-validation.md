# 07 无障碍与验收

## 7.1 可访问性基线

- Chrome、Safari、Edge 桌面端完成代表任务无阻塞缺陷。
- 核心操作键盘可达率 100%；焦点顺序与视觉顺序一致。
- 状态、风险、AI、审核和回执不只依赖颜色。
- 表格具有标题、排序状态与行上下文；对话框正确管理焦点。
- 动态高风险升级使用 live region；正常时间线更新不持续打断读屏。
- 文字与背景遵循 WCAG 2.2 AA；减少动态效果偏好下取消非必要动画。
- Opportunity 的四档决定使用语义化单选组或等价按钮组，读屏必须同时读出当前决定、自动/人工来源、理由和下一步；Phase 0 的自动参与不得被读成可日常人工覆盖的选项。
- 四张渠道行动卡可用键盘逐一到达；每张卡读出系统建议、计划选择、依赖影响和交付进展。渠道依赖图必须提供同内容的关系清单和影响摘要，不能只依赖图形位置或线条。
- CP-28 影响分析与 CP-29 计划版本差异以完整对话框/侧栏呈现：打开后焦点进入标题，`Esc` 关闭并归还触发卡焦点；确认、继续重规划、放弃变更均有明确可读结果。
- 热点雷达、Event 监测和 Outcome 图表提供可访问数据表、趋势摘要、时间范围和口径；键盘可按数据点/行查看，不以颜色或悬浮提示作为唯一信息来源。

## 7.2 代表任务

| ID | 任务 | 通过标准 |
|---|---|---|
| VT-01 | 从工作台进入事实冲突 Event | ≤2 次操作，能说明缺口和影响 |
| VT-02 | 区分 Signal、事实、推断和价值 | 正确指出性质和来源入口 |
| VT-03 | 解释 Phase 0 合格触发与自动参与 | 能指出 `T0`、触发规则、内容参与策略版本及高风险为何不走自动路径 |
| VT-04 | 在至少 3 条普通候选中选择一条并完成人工发布/链接回填 | 不把规则预检、Telegram 投递或人工发布误认为自动发布；只要求回填实际发布链接 |
| VT-05 | 处理 Telegram 投递失败 | 能确认内部审核目标、5 分钟投递目标、系统权威状态和恢复入口 |
| VT-06 | 审核 Campaign Proposal | 能发现预算、资源或风险缺口 |
| VT-07 | 比较并批准 KOL 批次 | 能解释性价比构成与触达边界 |
| VT-08 | 处理 KOL 拒绝/退订 | 后续触达停止且记录完整 |
| VT-09 | 处理回执延迟 | 不把延迟判断为完成/失败 |
| VT-10 | 键盘完成审核和异常接管 | 无键盘陷阱，结果可被辅助技术读取 |
| VT-11 | 在 Opportunity 作优先参与、参与、观察或不参与决定 | 能说明这是“是否启动该热点整体响应”；观察要求设置重评时间，不参与要求记录原因，只有参与/优先参与进入 Task Plan。 |
| VT-12 | 在 Task Plan 取消 KOL 合作但保留内容发布 | 系统展示依赖、内容/CTA/窗口/KPI 等影响；无影响时可确认，需重规划时生成新版本，阻塞冲突时不能保留旧计划。 |
| VT-13 | 用键盘和读屏完成渠道组合变更及版本确认 | 能逐卡理解建议、选择与影响；关系清单可替代依赖图；关闭/确认后焦点和结果反馈正确。 |

## 7.3 状态覆盖

所有页面继承 5.10 的加载、空、成功、失败、部分成功、回执缺失和权限受限规则。下表定义每个页面必须进入验收的专属状态；“默认/成功”指业务数据已可用、当前页面任务可继续进行的正常状态。

| 页面 | 默认/成功 | 加载 | 空 | 失败/部分成功 | 权限受限 | 专属异常/边界 |
|---|---|---|---|---|---|---|
| PG-01 | 已登录并选定工作空间 | 会话/权限加载 | 无可用工作空间 | 认证或会话恢复失败 | 显示缺失角色与申请入口 | 受限深链在授权后返回原对象 |
| PG-02A | 显示我的紧急响应与待办 | 保留 `T0` 和倒计时占位 | 无紧急响应/无待办 | 部分候选投递失败仍显示已投递项 | 无内容运营权只显示摘要 | 未投递、未选择、未回填、错过窗口分开显示 |
| PG-02B | M1—M5 与四渠道真实汇总 | 区块分批加载 | 当前筛选无对象 | 单个汇总区失败不遮蔽其余区 | 敏感正文/目标脱敏 | 未启用能力显示阶段标签，不伪造进度 |
| PG-03 | Top 10、趋势、来源状态 | 显示最近成功采集时间 | 无匹配 Signal / 筛选无结果 | 单来源失败仍保留其他来源 | 只显示获授权范围 | 采集失败、过期数据、未达触发条件 |
| PG-04 | 系统标记的候选例外队列 | 保留筛选和关系上下文 | 无待处理例外 | 合并/拆分保存失败不变更对象 | 无修改权仅可比较 | 归并冲突、上下文冲突、下游需复核 |
| PG-05 | Future Event 日历/列表及窗口 | 日历与匹配结果分批加载 | 无 Future Event / 无匹配 | 单个匹配或保存失败有重试 | 无编辑权只读 | 未匹配、窗口已过、改期、取消、提前启动 |
| PG-06 | 当前生效的监测规则 | 规则版本加载 | 无适用规则 | 发布失败保留草稿与回滚入口 | 无配置权只读 | 规则冲突、测试命中异常、紧急变更 |
| PG-07 | Event Card、Fact/Evidence 与监测 | 先显示对象身份 | 无 Evidence / 筛选无事实 | 来源局部失败不隐藏其他证据 | 隐藏未授权证据正文 | Fact 冲突、高风险、窗口过期/调整待依据 |
| PG-08 | Opportunity 决定与依据 | 先显示根 Event/版本 | 无待决策 Opportunity | 建议计算失败仍可查看事实，不可伪造建议 | 无决策权只读/可评论 | 观察待重评、不参与原因缺失、自动参与被事实/风控阻断 |
| PG-09 | 当前 Task Plan 与渠道组合 | 先显示当前版本 | 无 Plan（尚未参与）/无建议渠道 | 重规划失败保留原版本与选择草稿 | 无计划决策权只读/可建议 | 无影响、需重规划、阻塞冲突、计划变更待复核 |
| PG-10 | 行动队列与真实进度 | 列表分批加载 | 无已选入行动 / 筛选无结果 | 部分行动回执缺失或加载失败 | 仅显示授权类型/摘要 | 窗口临期、停用渠道、异常待办 |
| PG-11 | 草稿、预检/审核或选择界面 | 先显示对象链与版本 | 无待处理草稿 | 投递/预检/保存部分失败可重试 | 无审核权只读 | 高风险转审、需修改、驳回、普通内容错过窗口 |
| PG-12 | Action Task 与 Receipt 时间线 | 先显示任务身份/状态 | 无任务/无 Receipt | 外部回执延迟或关联失败 | 无任务权仅看最少上下文 | 待交接、暂停、取消、异常、人工接管 |
| PG-13 | Outcome、口径与策略建议 | 先显示对象链和统计范围 | 尚无结果 / 无可复用建议 | 数据源部分失败或口径未确认 | 隐藏敏感指标或建议细节 | 缺失、冲突、低归因置信度、建议待批准 |
| PG-14 | 当前责任人的异常队列 | 异常分批加载 | 无待处理异常 | 恢复操作失败保留原状态与重试 | 非责任人只读 | 升级、转派、不可重试、错过窗口 |
| PG-15 | 当前字典版本与引用 | 条目/引用分批加载 | 无该类条目 | 发布冲突保留草稿 | 无字典管理权只读 | 被引用条目弃用、替代映射冲突 |
| PG-16 | 连接器与批准目标状态 | 健康/授权分批加载 | 无已批准目标 | 单目标失败不掩盖其他可用目标 | 无管理权仅看目标摘要 | 授权失效、目标撤销、投递失败、内外目标混用阻止 |

## 7.5 验证方法与门禁

1. 至少覆盖热点/研究、内容、社群、增长/活动、KOL/渠道、风控和数据角色。
2. Phase 0 使用真实规模 X 五地区趋势与社媒内容草稿样本；完整产品设计评审另使用四类行动代表样本。
3. Phase 0 演练重点关键词、普通主题排名 1—5、排名上升至少 10 位三类触发；验证每例 `T0 → Telegram 投递` 不超过 5 分钟且至少投递 3 条规则预检通过的候选；再演练高风险人工审核、Telegram 投递失败、投递后 10 分钟提醒、15 分钟未选择/发布/回填的升级和人工发布无链接。完整产品另演练 Opportunity 四档决定、取消 KOL 后内容重规划、活动无人承接、X 私信降级、拒绝/退订和回执延迟。
4. 验证连接器不可用时界面明确降级，不虚构能力或回执。
5. 阻塞问题关闭后才能进入架构和 Story 拆分。

## 7.6 已知缺口与结论

- 社媒账号 API 直发、营销活动自动上线/投放和 KOL 后续全自动对话不在当前边界。
- X 私信、Telegram Bot、Google Docs 的真实能力由架构阶段验证；UX 不假定平台不支持的动作。
- 本设计按“双层首页、Phase 0 内容响应、完整产品四类行动”基线更新；实施前仍需完成代表任务可用性验证。
