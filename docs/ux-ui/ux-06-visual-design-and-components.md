# 06 视觉设计与组件

| Token | 值 | 用途 |
|---|---|---|
| `color-bg` | `#F6F8FB` | 应用背景 |
| `color-surface` | `#FFFFFF` | 工作面 |
| `color-text` | `#18212F` | 主文本 |
| `color-muted` | `#667085` | 次要信息 |
| `color-border` | `#D9E0EA` | 边界 |
| `color-action` | `#2563EB` | 系统动作 |

| `color-warning` | `#B86400` | 待确认/窗口 |

主字号 14px，页面标题 24px，区块标题 16–18px；表格行 44px，可选舒适 52px；所有数值使用等宽数字。

## 6.2 视觉语法

- 已确认事实：普通白色内容面 + 绿色确认图标，不大面积染色。
- 系统自动触发/生成：蓝色系统动作标记，并显示触发规则、输入、策略版本与时间；不得伪装为人工决定。
- Opportunity 决定与渠道行动：Opportunity 的优先参与/参与/观察/不参与，和渠道行动的建议启用/已选入/未选入必须使用不同文字、图标和分组，不得混成同一枚状态标签。
- 渠道依赖：用带文字说明的连线/关系清单表达“支撑、依赖、替代、共享 CTA/受众”；颜色或线型不能成为关系的唯一表达。
- 计划重规划：琥珀提示“需重规划”，红色提示“阻塞冲突”；两者都显示受影响行动、原因、下一步和计划版本，不能只显示警告颜色。
- 规则预检通过：蓝绿组合状态，显示通过的规则和仍由人工承担的下一步；不得伪装为人工审核通过或平台发布成功。
- 待确认/冲突：琥珀边线 + 缺口与下一步。
- AI：紫色小标识、输入版本和依据，可折叠解释。
- 审核：显示审核者、结论、版本和范围；高风险使用红色门禁。
- 执行：蓝色时间线；人工选择/发布链接回填、Bot 回执、平台确认（仅在可获得时）采用不同图标和文案。
- 连接器：显示渠道品牌只为识别，不覆盖系统状态语义。

## 6.3 核心组件

| ID | 组件 | 核心规则 |
|---|---|---|
| CP-01 | 全局导航 | 稳定骨架、异常计数、权限受限 |
| CP-02 | 对象头部 | 状态、风险、窗口、版本、责任人 |
| CP-03 | 对象链 | Event→Event Card→Opportunity→Task Plan→Deliverable Draft→Action Task→Receipt→Outcome |
| CP-04 | 状态组合 | 主状态 + 类型专属状态 + 解释 |
| CP-05 | Fact–Evidence 组 | Fact 状态；支持/质疑/排除 Evidence；来源、可信度、新鲜度 |
| CP-06 | AI 建议卡 | 输入、依据、时间、接受/修改/拒绝、差异 |
| CP-07 | 系统生成 Task Plan 概览 | 根 Opportunity 决定、输入、总目标、成功标准、当前版本、四类渠道行动摘要、资源、风险、窗口与策略版本；不在此卡重复作热点是否参与决定。 |
| CP-08 | 预检与审核卡 | 类型、版本、预检规则/结果、处理者、截止、选择或审核结论 |
| CP-09 | 批量批准摘要 | 数量、目标、差异、高风险拆分 |
| CP-10 | 社媒候选选择与发布交接 | 至少 3 条候选、预检结果、选择、复制、打开平台、仅回填实际发布链接、错过窗口 |
| CP-11 | Telegram 目标选择 | 内部/外部隔离、权限、健康、频率 |
| CP-12 | Campaign Proposal | 目标、创意、预算、资源、指标、清单 |
| CP-13 | KOL 比较表 | 匹配、互动、预估结果、报价、风险、置信度 |
| CP-14 | KOL 批次授权 | 名单/规则、模板、账号、时间、频率、停止 |
| CP-15 | 回复收件箱 | 意向、报价、风险、AI 回复、人工发送 |
| CP-16 | Receipt 时间线 | 来源主体、动作、状态、时间、真实回执 |
| CP-17 | 异常卡 | 影响范围、原因、下一责任人、恢复入口 |
| CP-18 | 工作台视图切换 | 我的响应台/全局运营台、当前角色、上次选择、权限说明 |
| CP-19 | 响应窗口 | 剩余时间、审核截止、调整依据、升级对象、过期影响 |
| CP-20 | 普通内容候选投递 | Telegram 目标、至少 3 条候选、投递回执、系统入口与重试结果 |
| CP-21 | 热点雷达榜单 | 平台、地区、主题、Top 10、热度变化、来源健康度、成功采集时间、触发依据与 Candidate 入口 |
| CP-22 | 未来事件时间轴 | 预计发生时间、前/中/后窗口、预案、负责人、自动/手动启动、匹配状态与阶段 |
| CP-23 | Event 监测图 | 热度时间序列、跨地区扩散、关键 Evidence/窗口节点；事实状态独立显示 |
| CP-24 | Evidence 来源抽屉 | 来源摘要、可信等级、采集时间、原文入口、支持/质疑/排除的 Fact |
| CP-25 | 合格触发与策略依据 | `T0`、触发类型、关键词/排名规则、Monitoring Scope 与内容参与策略版本、自动参与结论 |
| CP-26 | 紧急响应计时器 | `T0 + 5 分钟` 投递进度、投递后 10 分钟提醒、15 分钟截止、错过窗口与升级对象 |
| CP-27 | 渠道行动卡 | 四类渠道共用：系统建议（建议启用/未建议启用）、计划选择（待选择/已选入/未选入/已取消）、依赖、共享信息/受众/CTA、预期贡献、风险、窗口、责任人与交付进展。选择/取消不是独立开关，必须进入 CP-28。 |
| CP-28 | 渠道依赖与影响分析 | 关系图 + 影响清单：显示变更来源、受影响渠道、覆盖缺口、KPI、文案/CTA、资源、窗口和替代承接方式；结果明确为“无影响 / 需重规划 / 存在阻塞冲突”，并给出下一步。 |
| CP-29 | Task Plan 版本差异与确认 | 并排比较当前版本与拟议版本，按渠道展示选入/取消、依赖、交付物及预期结果的变化；只允许确认、继续重规划或放弃变更。已审核、已交接或已发布交付物显示“计划变更待复核”，不得被静默替换。 |

## 6.4 布局与响应

全局导航 240px（紧凑 72px）；上下文栏 320px，可收起。≥1680px 三栏并排；1280–1679px 上下文栏默认抽屉；<1280px 不在正式支持范围。表格密度、列和筛选按用户保存。

Task Plan 工作区的大屏默认采用“计划概览 + 渠道行动区 + 上下文栏”：行动区四张 CP-27 可按渠道平铺或按优先级纵向排列，不能为追求并排而隐藏状态文字。打开 CP-28 或 CP-29 时使用完整工作区/侧栏，不使用瞬时确认弹窗承载依赖图、影响分析或版本差异。

## 6.5 图表与评分

KOL 性价比必须展示构成与数据新鲜度，不能只显示总分。趋势、预算和结果图表提供数值、时间范围、来源和口径；不同业务维度不得无解释合并。
