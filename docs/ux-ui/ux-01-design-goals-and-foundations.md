# 01 设计目标与基础

## 1.1 设计目标

| ID | 目标 | 证据 | 可观察结果 |
|---|---|---|---|
| UX-G01 | 自动响应与人工选择优先 | FR-14—FR-20、NFR-11 | 我的响应台先呈现 `T0`、5 分钟投递目标、内容候选供给、15 分钟选择/发布时限和例外，而非让人从零起草方案 |
| UX-G02 | 事实、热度、价值、AI 不混淆 | FR-01、FR-08、FR-11 | 每项信息显示性质、来源、时间与确认状态 |

| UX-G04 | 自动化深度诚实可见 | FR-14—19 | 用户看得出自动触发、Opportunity 自动参与、系统生成计划、渠道选择、规则预检、人工选择、高风险审核、人工发布、Bot 发送、负责人实施和自动私信的边界 |
| UX-G05 | 系统内部保持权威 | D-11 | Telegram、Google Docs、X 的内容和回执最终回写系统 |
| UX-G06 | 可解释、可停止、可降级 | NFR-03/04 | 无平台能力时显示降级；异常不伪装成功 |

## 1.2 体验原则

1. **统一上下文，不统一自动化深度。** 四类行动共用 Event、目标、受众、风险和 Outcome，但执行方式不同。
2. **人做选择和例外，不从零生产默认方案。** 系统生成 Task Plan 与普通内容候选；普通内容通过规则预检后由内容运营选择，高风险内容及其他行动仍有明确审核门禁。
3. **先决定响应热点，再选择响应渠道。** Opportunity 的四档决定只回答是否启动热点整体响应；Task Plan 才通过四张渠道行动卡决定怎样协同。取消行动必须显示对其他已选行动的影响，并在必要时重规划。
4. **系统内部是唯一权威。** 协作出口可替换，不能产生第二套状态。
5. **先证据，后交付物。** 每份内容、消息、活动方案和触达方案都能追溯事实与 Task Plan。
6. **连接器能力不能被想象。** 不支持直发时显示人工交接；无真实回执时显示等待或延迟。
7. **时间承诺可见且可追溯。** `T0`、5 分钟自动投递目标、投递后 10 分钟提醒与 15 分钟升级必须使用可辨识的时间线、倒计时和异常状态表达。
8. **阶段边界诚实可见。** 完整产品设计展示四类行动运行；Phase 0 页面将未启用行动明确标记，不以模拟数据冒充真实进度。

## 1.3 角色与责任

| 角色 | 默认关注 | 关键动作 |
|---|---|---|
| 小林：热点/研究运营 | 重点领域、关键词、阈值、数据异常、重复候选、Event 变化 | 维护监测范围；校正重复、异常、事实与关系，不手动处理每条正常触发 |
| 小陈：内容运营（Phase 0 默认） | 已投递的普通社媒内容候选、15 分钟窗口 | 在候选中选择一条、人工发布、仅回填实际发布链接；处理升级与例外 |
| 私域/社群运营 | Private Outreach Draft 和目标社群 | 审核后授权 Bot 发送 |
| 小周：增长负责人 | Opportunity 整体响应决定、系统生成的 Task Plan、渠道依赖、资源/风险例外 | 对非自动路径作优先参与/参与/观察/不参与决定；在 Task Plan 内选入、取消或要求重规划渠道行动；不从零起草交付物 |
| KOL/渠道负责人 | KOL 排名、名单、模板、回复 | 批准批次、处理后续回复 |
| 品牌/风控 | 高风险交付物与动作 | 追加审核、限制、驳回 |
| 小王：运营策略/数据负责人 | Receipt、Outcome、口径缺口、策略建议 | 核验结果、复盘并确认可复用策略 |
| 连接器管理员 | Bot/API 权限与目标目录 | 连接、批准目标、设置频率 |

同一用户可兼任多个角色；角色只改变默认视图、敏感字段和操作权，不改变对象结构。

## 1.4 平台与视觉基础

- 桌面 Web；主流 Chrome、Safari、Edge。
- 1440px 主画布，1280px 最低完整宽度，1920px 展开上下文栏。
- 浅色、高密度、冷静可信；蓝色为系统动作，绿色为真实成功，琥珀为待确认/窗口，红色为阻塞/风险，紫色为 AI。
- 状态必须同时使用文字、图标/形状和颜色。
- Hotspot Monitor 是独立品牌；Predx、Telegram、X、Google Docs 作为工作空间或连接器出现。
