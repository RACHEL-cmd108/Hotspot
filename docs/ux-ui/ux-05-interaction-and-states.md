# 05 交互与状态

## 5.1 分层状态模型

关键状态同时使用文字、图标/形状和颜色，并说明“发生了什么、下一责任人、处理时限”。不同核心实体不得合并成一条虚假的统一状态机；尤其不得把 Opportunity 的“是否响应”误作某一渠道行动的状态。

| 层级 | 对象/决定 | 状态或状态序列 | 规则 |
|---|---|---|---|
| 热点响应决定 | Opportunity | 待决策 → 优先参与 / 参与 / 观察 / 不参与 | 四档只回答“是否为这个热点启动整体响应”。观察必须有重评时间；不参与必须有原因。Phase 0 合格普通内容由策略自动写入“参与”，并记录触发规则、策略版本与时间。 |
| 整体响应计划 | Task Plan | 系统生成当前版本 → 渠道组合配置中 → 影响分析/重规划中 → 已确认当前版本 → 已撤销 / 已关闭 | Task Plan 回答“四个渠道如何协同”，不是再次判断是否参与热点。Phase 0 内容路径由策略自动确认“仅内容发布”的初始版本；后续增减渠道形成新的计划版本。 |
| 渠道行动 | 内容发布 / 私域触达 / 营销活动 / KOL 合作 | 见 5.2 的双维状态 | 每个渠道是 Task Plan 内的一张行动卡；四张卡可有依赖，但不共享一个虚假的单一状态。 |
| 交付物 | Execution Deliverable Draft | 系统生成/草拟 → 预检完成 → 已通过 / 待审核 / 需修改 / 已驳回 | “规则预检通过”仅代表可以进入后续选择或审核，不代表已发布或人工批准。 |
| 执行交接 | Action Task | 待交接 → 已接收 → 进行中 → 已完成 / 已暂停 / 异常 / 已取消 | 只有达到可交接条件的草稿才显示“创建行动任务”。 |
| 执行回执 | Task Receipt | 已接收 → 已关联 → 已处理 / 待人工处理 | 回执延迟只表示未知/待处理，不推定已完成、失败或取消。 |

交付物的审核状态不是 Action Task 状态；Task Plan 的版本状态也不是四个渠道行动卡的状态。

## 5.2 Task Plan 与渠道行动状态

渠道行动卡使用四个相互独立的维度展示，避免把“系统建议”“用户选择”“交付进度”混成一个标签。

| 维度 | 可见状态 | 含义 |
|---|---|---|
| 系统建议 | 建议启用 / 未建议启用 | 基于机会、目标、资源、风险和与其他渠道的依赖生成；必须显示理由与预期贡献。 |
| 计划选择 | 待选择 / 已选入 / 未选入 / 已取消 | 小周针对计划内渠道作出的组合选择。Phase 0 合格普通内容直接标记“已选入（策略）”；其他三类行动默认显示“待选择”或“未选入”，不假装已在执行。 |
| 依赖影响 | 无影响 / 需重规划 / 存在阻塞冲突 | 表示本行动的选择或取消对其他已选渠道、共享信息、受众、CTA、窗口、资源或预期指标的影响。 |
| 交付进展 | 未生成交付物 / 草稿处理中 / 已交接 / 有回执 | 只在行动已选入后出现；具体细节由交付物、Action Task 与 Receipt 状态承担。 |

### 渠道组合变更与重新规划

1. 小周选择、取消或修改任一行动卡时，界面先展示关系图和变更预览，不立即静默修改其他行动。
2. 系统生成影响分析：列出受影响的行动卡、覆盖缺口、成功指标、文案/CTA、节奏、窗口、资源与替代承接方式。
3. 若为“无影响”，确认后只更新当前计划版本的该行动选择；若为“需重规划”，系统生成新的 Task Plan 版本和受影响草稿的差异，待小周确认；若为“存在阻塞冲突”，用户必须恢复该行动、选择替代承接方式或关闭受影响行动。
4. 已审核通过、已交接或已发布的交付物不得被计划变更静默改写；它们显示“计划变更待复核”，由对应责任人保留、修订或终止。
5. Phase 0 的内容发布不等待其余三类行动被选择：策略选入内容行动后，直接生成至少 3 条候选、预检并投递。之后若新增或取消其他渠道而影响内容，才依上述规则生成内容的新版本或复核事项。

## 5.3 类型专属状态

| 类型 | 专属状态 |
|---|---|
| 普通社媒内容 | 行动已选入（Phase 0 可为策略自动选入） → 生成至少 3 条候选 → 规则预检通过 → 待投递 → 已投递 / 投递失败 → 待选择 → 已选择/待发布 → 已回填发布链接 / 错过窗口 |
| 高风险社媒内容 | 行动已选入 → 草稿生成 → 待审核 → 已通过 / 需修改 / 已驳回 → 待人工发布 → 已回填发布链接 |
| 私域触达 | 行动已选入 → 草稿生成与适用审核 → 等待 Bot 发送 → 已发送 / 发送失败 → 互动回执 |
| 营销活动 | 行动已选入 → Campaign Proposal 草稿/审核 → 待负责人承接 → 规划中 → 执行中 → 已结束 |
| KOL 合作 | 行动已选入 → 名单/首封草稿审核 → 待名单批准 → 首封排队/已发送 → 已回复 / 拒绝 / 退订 |

Action Task 主状态用于跨类型比较；专属状态回答具体发生了什么。Task Plan、行动卡和交付物草稿状态只能在各自对象范围内比较。

## 5.4 Execution Deliverable Draft 预检、选择与审核

每份交付物显示 Fact/Evidence 引用、Task Plan、响应渠道、版本、预检、差异、处理者和截止。普通社媒内容完成事实/来源/禁用表达/风险规则预检后直接成为候选，必须显示预检规则与结果；小陈选择一条用于人工发布。高风险社媒内容、私域触达、活动方案和 KOL 触达的操作为通过、需修改、驳回；小改直接编辑，结构性修改提交意见让 AI 生成新版本。适用的低风险同类审核项可多选批量通过，确认框显示数量、目标和差异；高风险项自动拆出。

## 5.5 社媒人工发布

普通内容候选投递后提供“选择此候选”“复制内容”“打开平台”和“回填发布链接”。小陈选择一条后人工发布，并仅回填实际发布链接；系统自动关联候选、选择时间和回填时间，不要求再填写渠道、账号或发布时间。系统不得显示为自动发布。修改候选后必须重新预检；高风险内容修改后还必须重新审核。

## 5.6 Telegram 双目标

内部审核目标和外部运营社群使用不同目录、图标和确认文案。内部投递不构成发布；外部 Private Outreach Draft 只有明确批准后才能发送。发送状态包括排队、定时、已发送、失败、回执延迟；失败保留其他成功目标并提供重试、换目标、停发和升级。

Phase 0 只使用内部审核目标。Bot 投递至少 3 条规则预检通过的普通内容候选及其系统入口；它不是“通过、需修改、驳回”的审核卡。选择、发布链接和任何例外处理均须回写系统；投递失败时显示“未投递”，并提供重试、更换批准目标或转入系统处理。

## 5.7 响应窗口与升级

- 工作台、Event、Task Plan 和草稿处理页同时显示事件响应窗口与当前步骤截止；Phase 0 还显示成功采集 `T0`、`T0 + 5 分钟` 投递目标和投递后 15 分钟选择/发布截止。
- 投递后第 10 分钟提醒小陈；第 15 分钟未完成选择、人工发布和链接回填即标记错过窗口，并升级给备援内容运营或内容负责人。
- 当前步骤截止不得晚于响应窗口；不足时显示剩余时间和升级对象。
- 热度变化只产生提示，不自动调整窗口；窗口修改必须显示操作者、依据和影响对象。
- 上游重大变化使草稿过期时，阻止继续交接并要求重新预检/审核。
- 审批超时只能提醒和升级，不得默认通过。

## 5.8 营销活动

整份 Campaign Proposal 审核；通过后生成 Action Task 清单。当前“执行”代表负责人承接和回传，不表示系统自动上线、投放或消耗预算。预算、目标或风险边界变化触发重新确认。

## 5.9 KOL 批次与回复

批准界面必须显示名单数量、选择规则、排除项、模板、变量、发送账号、时间、频率和停止条件。首封可自动批量发送；X 能力不可用时显示降级人工发送。回复进入收件箱，AI 标注意向/报价/问题/风险并给回复建议；后续消息需要人工确认。拒绝、退订、负面反馈或频率异常立即停止。

## 5.10 页面基础状态

| 状态 | 规则 |
|---|---|
| 加载 | 先显示对象身份；>1 秒给语义进度，>3 秒提供刷新/诊断 |
| 空 | 区分无数据、筛选无结果、权限不可见、连接器故障 |
| 成功 | 说明动作、目标与真实回执，不用瞬时 toast 承载唯一结果 |
| 部分成功 | 列出成功、失败和未执行项，不显示整体成功 |
| 失败 | 保留成功数据，显示失败范围、可重试性和接管入口 |
| 回执缺失 | 显示等待/延迟，不推定完成、取消或失败 |
| 权限受限 | 说明所需角色和申请路径，不泄露敏感值 |

## 5.11 页面权限与操作矩阵

角色简称：小林（热点/研究运营）、小陈（内容运营）、社群（私域/社群运营）、小周（增长负责人）、KOL（KOL/渠道负责人）、风控（品牌/风控）、小王（运营策略/数据负责人）、连接器管理员。未列为操作角色的用户，只能在其数据范围内查看；无读取权限时仅显示最少上下文与申请入口。

| 页面 | 主操作角色 | 可执行动作 | 其他角色权限 |
|---|---|---|---|
| PG-01 登录与权限 | 全体 | 登录、选择工作空间、申请权限 | 不适用 |
| PG-02A 我的响应台 | 小陈及被分派的备援内容运营 | 选择普通内容候选、回填发布链接、处理自己的升级事项 | 其他角色仅查看被授权的摘要，不得代填链接 |
| PG-02B 全局运营台 | 小周、小王及获授权管理者 | 筛选、保存个人视图、进入对象工作区 | 其他角色按数据范围只读摘要 |
| PG-03 实时热点雷达 | 小林 | 保存团队监测视图、诊断来源异常 | 授权角色可读；不提供人工确认正常触发 |
| PG-04 候选事件队列 | 小林、获授权研究运营 | 仅处理系统标记的归并/上下文例外 | 其他角色只读；不得删除原始 Signal |
| PG-05 未来事件中心 | 小林、获授权热点运营 | 创建/改期/取消、配置预案、提前启动 | 负责人可查看和接收待办；其余只读 |
| PG-06 监测范围 | 配置管理员、小林 | 编辑、停用、恢复并发布规则版本 | 普通运营只读范围摘要 |
| PG-07 Event 工作区 | 小林 | 校正 Fact/关系、处理冲突、按依据调整窗口 | 相关角色只读或评论；不改变机会/渠道决定 |
| PG-08 Opportunity 工作区 | 小周、授权决策者 | 对非自动路径作四档整体响应决定 | 内容/社群/KOL/风控可提交输入；Phase 0 自动参与仅可查看依据 |
| PG-09 Task Plan 工作区 | 小周、授权计划决策者 | 选入/取消渠道、请求重规划、确认计划版本、撤销/关闭 | 各渠道角色可提交建议；不得从此页编辑草稿正文 |
| PG-10 任务中心 | 各渠道责任人 | 筛选、查看自己渠道的待办并进入详情 | 跨团队仅看授权汇总；不在此页完成复杂审核/交接 |
| PG-11 交付物草稿处理 | 小陈（内容）、社群、KOL、风控及指定审核者 | 按类型选择、审核、修订或回填；高风险由风控结论 | 小周查看计划上下文；无相应审核权不得改变结论 |
| PG-12 行动任务与回执 | 任务责任人、交接人、获授权管理者 | 接收、更新、关联回执、暂停/取消/改派/升级 | 交付物和计划仅可跳转查看，不能改写 |
| PG-13 Outcome 与复盘 | 小王 | 确认口径、复盘、发布策略建议 | 小周及行动责任人提交输入；其他角色按范围查看 |
| PG-14 通知与异常中心 | 当前责任人、获授权升级者 | 重试、换目标、分派、升级、记录恢复 | 关闭通知不等于恢复对象；其他角色只读 |
| PG-15 业务字典 | 字典管理员 | 新增、编辑、弃用、恢复、发布字典版本 | 普通用户仅查看被引用条目 |
| PG-16 连接器与目标目录 | 连接器管理员 | 验证、批准、撤销目标，重新授权 | 其他角色仅在草稿页查看已批准目标摘要 |

对高风险草稿、外部社群发送、KOL 批次、任务暂停/取消等动作，页面操作权还须通过相应风险/审核门禁；本矩阵不以页面访问权替代该门禁。
