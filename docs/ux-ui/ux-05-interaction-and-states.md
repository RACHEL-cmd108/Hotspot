# 05 交互与状态

## 5.1 对象状态

| 对象 | 状态 | 页面规则 |
|---|---|---|
| Candidate Event | 新建 → 待核验 → 已形成 / 已忽略 / 已合并 | 合并、拆分、忽略均保留原始 Signal、理由、操作人和时间。 |
| Event | 待聚合 → 响应中 / 观察中 → 已关闭；可再激活 | 来源冲突可见但不阻断普通候选生成；活动策划不改变内容响应资格。 |
| Account Response Task | 待生成 → 生成中 → 待选择 → 待发布/待回填 → 已完成 / 已暂停 / 异常 / 已取消 | Phase 0 每个合格 Event 对三个预配置 Predx X 账号分别匹配；每个账号至多一个任务。账号/Skill 不可用则仅该账号异常，不生成替代任务，不阻塞其他账号。 |
| Content Candidate | 已生成 → 预检完成 → 已选择 / 需修改 / 已放弃 | 绑定唯一账号任务；候选调整或重新生成产生新版本，不覆盖旧版本。 |
| Publication Record | 待回填 → 已发布 / 发布失败 | 真实 URL 或失败原因是关闭账号任务的必要凭据；发布记录不是表现结果。 |
| Campaign Case | 已形成 → 待运营决定 → 已启动 / 已忽略 / 已过期 | 推荐只是准备建议；不等于热点参与决策或活动立项。 |
| Campaign Proposal | 已生成 → 已调整 / 已导出 / 已归档 | 每次主动启动固定生成三套候选；导出/交接不等于执行完成。 |
| Optimisation Proposal | 草拟 → 待批准 → 已批准 / 已拒绝 / 已归档 | 仅批准后在明确范围发布新规则版本。 |

## 5.2 内容候选门禁

| 条件 | 结果 |
|---|---|
| 账号任务已创建，账号/Skill 可用 | 系统生成至少三条账号专属候选。 |
| 候选通过事实/来源状态、禁用表达、产品资料、平台政策和风险预检 | 普通低风险候选进入待选择。 |
| 来源冲突/未知 | 可生成，但候选必须保留状态、限制表达；不得写成已确认事实。 |
| 高风险命中 | 候选进入人工审核，不能被选为可发布候选或进入 URL 回填。 |
| 生成/预检失败 | 任务异常或候选需修改，显示失败步骤、命中规则、重试和修订入口。 |

## 5.3 内容任务交互

1. 选择候选时，系统显示所选候选、账号、版本和预检结果；取消选择不删除候选。
2. 调整候选必须保留原版本、调整人、调整原因，并重新执行适用预检。
3. 重新生成可接受补充条件，但必须保留旧候选和对应版本。
4. “复制内容”只复制当前已选候选；打开 X 后，系统保持任务上下文。
5. URL 回填需校验格式并绑定所选候选；如果无法发布，必须记录失败原因，不能把任务默认为已完成。

## 5.4 Future Event 与活动交互

- 确认状态决定允许使用的语气：未确认 Future Event 不可用确定时间、确定结果或确定倒计时表述。
- “需要准备”是系统建议；运营可修改，但修改记录原因和规则版本。
- 点击“生成活动方案”才生成三套方案；每套显示 Event 确认度、假设、目标、受众、窗口、机制、资源、风险和外部前提。
- 选择、调整、重新生成和导出均创建版本记录；不创建预算、落地页、投放或外部执行任务。

## 5.5 Event 校正交互

系统自动合并时，Event Card 必须显示“系统已合并”、置信度、依据、前后对象与下游影响；无关键影响的候选继续可用，有关键影响的候选显示“需复核”并暂停发布。自动拆分只显示建议，仍使用人工确认预览。

人工合并、拆分、校正和关系管理都使用确认前预览：

- 当前对象与参与对象；
- 来源、地区和关键上下文差异；
- 操作后 Event/Card 结构；
- 受影响账号任务、候选、发布记录或活动方案；
- 必填理由与操作人；
- 原始 Signal 永不删除。

## 5.6 四类复用状态模板

| 模板 | 覆盖状态 | 行为 |
|---|---|---|
| 等待中 | 采集、聚合、生成、预检、回填等待、追踪延迟 | 显示对象身份、最近更新、当前步骤和刷新/诊断入口；延迟不推定失败。 |
| 无内容 | 无热点、筛选无结果、无 Future Event、未启用能力 | 说明为空原因与下一步；不把权限或故障伪装为空。 |
| 受限 | 权限不足、账号/Skill 不可用、预留能力、外部条件未满足 | 说明限制原因、所需条件和申请/修复路径，不泄露敏感信息。 |
| 异常 | 来源不足、聚合冲突、生成/预检失败、URL 校验失败、追踪失败 | 保留成功数据；显示影响范围、失败原因、责任人、重试或人工接管入口。 |

## 5.7 实际耗时与提醒

Phase 0 记录成功采集、地区来源聚合、任务创建、候选可操作、选择、URL/失败原因回填的时间与状态，用于后续分析实际耗时分布。当前不得将 5 分钟、15 分钟或固定提醒/升级阈值显示为产品承诺或自动关闭条件。

## 5.8 数据新鲜度、来源与口径

所有运营对象采用同一元数据展示规则：在列表中至少展示最近更新时间与状态；进入详情后展示来源、更新时间、口径/计算范围及缺失或延迟状态。不同口径的数据不得在同一指标中静默合并。

| 对象 | 列表最小元数据 | 详情必须补充 |
|---|---|---|
| Signal / 热搜趋势项 | 地区、快照时间、采集状态 | 数据源、排名/热度口径、刷新/失败原因 |
| Future Event | 来源、最近更新时间、确认状态 | 重要性、监测范围、负责人、窗口的预测依据 |
| Event / Event Card | 最近更新、来源一致/冲突/未知 | Fact/Evidence、地区、快照时间、热度口径、风险与窗口依据 |
| Account Response Task | 创建/更新时间、当前状态、规则版本 | Event、账号/Skill、触发来源、阻塞/异常原因 |
| Content Candidate | 生成时间、预检状态、版本 | 事实/来源状态、Skill/规则版本、适用产品资料与洞察引用状态 |
| Publication Record | 回填时间、发布/失败状态 | URL 或失败原因、所选候选版本、人工操作人 |
| Performance Result | 最近更新时间、追踪状态 | 数据源、观察窗口、指标口径、缺失/延迟限制 |

## 5.9 权限差异与受限状态

页面骨架对所有授权用户一致；权限只影响字段、操作和发布动作。无权时保留对象的必要摘要，并把不可用操作替换为说明原因的受限状态，不移除对象或伪装成空状态。

| 操作 | 内容运营 | 热点/研究运营 | 活动运营 | 运营负责人 | 系统维护/字典管理员 |
|---|---|---|---|---|---|
| 查看热搜、Event、来源与账号任务 | 可查看 | 可查看 | 可查看相关 Event | 可查看 | 可查看 |
| 合并、拆分、校正 Event | 仅查看/提交异常 | 可执行并留痕 | 仅查看 | 可执行并留痕 | 仅查看 |
| 选择、调整、复制候选及 URL 回填 | 仅限已分配账号任务 | 仅查看 | 仅查看 | 可查看/协助异常 | 仅查看 |
| 高风险候选审核 | 不可执行 | 不可执行 | 不可执行 | 可审核（品牌/风控授权时） | 不可执行 |
| 启动、调整、导出活动方案 | 仅查看 | 仅查看 | 可执行 | 可执行 | 仅查看 |
| 编辑配置草稿 | 不可执行 | 主题/Future Event 范围内可执行 | 不可执行 | 规则、风险、版本可执行 | 数据源、账号/Skill、追踪可执行 |
| 发布配置版本 / 回滚 | 不可执行 | 不可执行 | 不可执行 | 授权范围内可执行 | 授权范围内可执行 |

受限操作必须给出：缺少的权限或外部条件、可联系的责任角色（不展示个人隐私信息）及保留当前上下文的返回路径。权限变更不改写已经创建的任务、候选或审计记录。
